# V1-Q original external-oracle inputs

All 105 SVG inputs and their geometry/parameter descriptions in `manifest.json` are
original Local Image synthetic fixtures, dedicated under CC0-1.0. No brand assets or
third-party drawings are included. Each SVG carries its licence identifier. The manifest
is the canonical source record: path commands, fill rule, scale, origin, join/cap/miter,
width-relative dash settings, offset distance and simplify tolerance are explicit.
Inputs are smaller than 50 KB each. Existing `quality_corpus.rs`, `quality.rs`, their
source record and `ratchet/geometry.json` are retained unchanged.

Binary corpus: 20 families at normal scale, translated to an origin of 1e6, and at
scale 1e-4 (60 files). Families cover shared/coincident/near-coincident edges, point
and circle tangencies, both figure-eight fill rules, 50 overlapping spikes, nested
holes, a hole touching the outer boundary, zero-area spikes, cubic cusps/loops,
thin slivers, containment and open fills. Page width/height remain 96; viewBox maps
the scaled/translated geometry back to that viewport. Cubic circles use the standard
four-cubic approximation, not exact circular arcs or an implementation-generated oracle.

Unary corpus: 24 signed offsets (square/star, round/miter/bevel, -20/-4/+4/+20),
18 stroke expansions (all three caps and joins, solid/dashed), and 3 simplify tolerances
(0.05/0.25/1 px) on an original 101-node sampled sine. Native dash lengths/offsets are
width-relative; SVG records absolute lengths 16/8 and offset 4 for an 8 px stroke.

## Actual external outputs and provenance

All **345 required references** were generated by `/usr/bin/inkscape`, version
`Inkscape 1.4.4 (dcaf3e7d9e, 2026-05-05)`, with empty DISPLAY and the isolated
`/tmp/vector-inkscape-profile`. SVG numericprecision is 16, minimumexponent -16.
Every output retains a 96×96 viewport and the synthetic CC0-1.0 dedication.
`goldens/generation.json` contains the exact original inputs, complete manifest
parameter objects, executed actions, effective inputs, raw CLI outputs and settings.
No native Local Image kernel or generated native path produced reference geometry.
The external ratchet is empty; all 345 comparisons pass.

The original generators are retained beside the outputs. From the repository root,
run them **serially**, in this order, to reproduce all references:

```sh
python3 crates/pc-pathops/tests/tricky/goldens/generate_binary.py
python3 crates/pc-pathops/tests/tricky/goldens/generate_unary.py
python3 crates/pc-pathops/tests/tricky/goldens/generate_stroke.py
python3 crates/pc-pathops/tests/tricky/goldens/generate_conditioned.py
```

The helper initializes the isolated precision preferences. The unary generator uses
NumPy for its independent simplify certificate. Inkscape batch processes must run
serially on this machine because simultaneous CLI processes share D-Bus state.

### Binary operations: 300 outputs

Actions are `select-by-id:a,b;path-union`, `path-difference`, `path-intersection`,
`path-exclusion` or `path-division`, followed by `export-do`. The effective input uses
the canonical manifest geometry at a common power-of-two similarity: factor 4096,
or 65536 for near-degenerate-sliver and near-coincident-edge families. Scale/origin
are removed analytically from the original recipe before applying this common
similarity. The root viewport is 96×factor. After the CLI, only root width/height
are reset to 96; its viewBox, output paths, styles and fill rules remain unchanged.
This lowers Livarot's fixed intersection quantization below the thinnest regions,
while preserving the original visible geometry and parameters. Exact effective
inputs and raw outputs make this conditioning independently inspectable.

### Unary operations: 45 outputs

The 24 offset cases use the Offset LPE version 1.3, signed distance in px,
manifest round/miter/bevel join, miter limit 4 and `attempt_force_join=false`,
then `select-by-id:a;object-to-path;export-do`. Positive cases use the original
viewport. Negative cases use factor 4096 through a 96-wide viewport and expanded
viewBox: document-to-user scaling preserves the signed document-pixel distance
and makes Inkscape's fixed 0.01 user-unit inset gap negligible in document space.

The 18 stroke cases scale path coordinates, width, absolute dash lengths and dash
offset together by 4096, then execute
`select-by-id:a;object-stroke-to-path;export-do`. Root width/height alone are reset
afterward. SVG absolute dashes correspond exactly to the manifest's width-relative
dashes. Seventeen outputs use this direct recipe.

Two precisely identified cases have equivalent independent SVG constructions,
recorded with `analytical_equivalence=true`, then executed by Inkscape with
`select-all:all;object-to-path;path-union;export-do`:

- `offset-star-round-20`: the exact positive round-offset Minkowski identity,
  original polygon fill union edge rectangles union radius-20 vertex disks.
  Disks consist of 16 exact SVG circular arcs, reducing Inkscape's relative
  curve-flattening error at concave intersections.
- `stroke-butt-miter-dashed`: exact arclength dash intervals, butt segment
  rectangles and outer miter wedges respecting the manifest miter limit.
  This avoids Inkscape's direct converter clipping the inner miter beyond a
  short dash endpoint. The original path and dash/join parameters are retained.

These primitive constructions use only manifest input and elementary mathematics;
Inkscape converts and unions the primitives. The retained recipe, effective input,
raw CLI result and actual action sequence distinguish them from direct conversions.
No acceptance threshold or ratchet was relaxed for these cases.

The three simplify cases use the Simplify LPE version 1.3, one step,
smooth_angles=0, individual_paths/coalesce disabled. The threshold is scaled by
input bounding-box diagonal. Independent adaptive cubic flattening has a 0.00025px
convex-hull bound; bidirectional point-to-segment sampling spacing is ≤0.001px,
with 0.001px added for uncertainty. Recorded upper bounds satisfy the respective
0.05/0.25/1px tolerances. Different valid fitted curves are compared to source
accuracy and reference node budget rather than required to match each other.

### Native normalization and comparison

The test-only normalizer is **usvg 0.45.1 + svgtypes 0.15.3 f64 geometry**. usvg
validates the resolved SVG structure/styles/transforms; svgtypes parses native f64
path coordinates, including circular arcs, so Inkscape's conditioned coordinates
are not quantized to f32. Native sidecars embed actual input/output bytes and the
executed recipe, rejecting stale data. Altered viewports, strokes, text, images,
clips, masks, filters and oversized outputs are rejected. Empty results are valid.

The gate compares relative area, symmetric sampled Hausdorff, continuous coverage
IoU at 8× AA (`sum(min coverage)/sum(max coverage)`), node growth and proper crossings.
Continuous coverage avoids the unstable 0.5 binary threshold for subpixel slivers;
the 0.999 IoU threshold is unchanged and a dedicated jitter regression guards it.
The native rasterizer accumulates scanline coverage in f64 before output conversion.
Division compares the bottom operand's faces, matching Inkscape Division semantics.
All 345 pass with unchanged area/Hausdorff/IoU/node/crossing limits and zero ratchets.
