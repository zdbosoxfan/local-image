## Batch treatment save: exact remaining limitation

The current editor represents modern composition as independent stack nodes. Its top-level `data.cutout` is a compatibility mirror of a chosen/non-discarded cutout's mask, feather, shadow and transform. Separate image layers are not identified as “the background” by that mirror.

`save_treatment` in [batch_tools.py](../backend/batch_tools.py) still saves the **existing mirror contract**. It does not infer which separate image node is a backdrop, whether multiple images should be included, or whether a background-looking image is actually another foreground object. Accordingly, a modern treatment can preserve the mirrored subject settings while omitting a separately stacked backdrop. The React Batch UI discloses that scope before saving. A future change may offer an explicit, narrowly defined background choice in a separately reviewed extension; it must not promise to capture the whole modern composition.

The compatibility fixes already implemented for **applying** a declared treatment do not resolve that **saving** ambiguity:

- Existing treatments apply transform/feather/shadow to the matching mask node, preserving other nodes and their relative order.
- A declared color/image background becomes one ordinary image node immediately below that subject, with existing attribution preserved.
- Detached snapshots copy all stack source/mask assets, including hidden/restorable nodes.
- Optional Qwen preparation of an original/repair stack uses only the returned alpha and snapshots the applied native source pixels into a detached ordinary cutout. It does not commit the editor document. An existing disabled cutout is rejected as ambiguous before requesting a model.

[test_batch_stack.py](../tests/test_batch_stack.py) covers those paths, including pixel arrays, 16-bit samples, alpha, ICC, credits and unchanged source/editor bytes. The Qwen-result cases use controlled fixtures, not real inference. [test_batch_tools.py](../tests/test_batch_tools.py) remains the legacy durable-queue regression suite. See [the regression evidence](../qa-artifacts/migration/batch-stack-regression.txt) for the separately recorded red/green runs.

## Cross-region ownership work

1. **One dispatcher for menus, toolbar and shortcuts.** `editor.js` still routes several shortcuts through old control `.click()` calls, and its `[data-command]` binding forwards clicks to another element. Before deleting menu/control DOM, expose direct domain commands and make both React controls and the existing shortcut owner call those commands. Clicking a directly owned `<input type="file">` to invoke the browser picker is a browser primitive; clicking an invisible legacy button to retain its handler is not an acceptable completed migration.
2. **No second document authority.** Only accepted backend sessions/revisions feed persisted document state. Settings, generation, Assets and Batch need the editor's shared operation/navigation ports; they must not independently overwrite the active session after navigation or bypass serialized document mutations.
3. **The canvas may remain imperative.** Retain its mounted subtree, coordinate conversion, capture, camera and mask buffers. Its future module name is less important than removing dependencies on UI fields that React is replacing. This is not a requirement to convert Canvas 2D or Python compositing to React.
4. **Retire presentation wrappers by region.** `studio-shell`, `stock-studio`, `generation-studio`, `quiet-controls`, `layers-studio`, `generation-composer`, `generation-guidance` and `stock-connections` still contain presentation ownership or function replacement. Retaining needed stack/canvas/domain methods is allowed; retaining the old view writers after their React region mounts is not.
5. **One theme and density scheme.** Existing root tokens and the nonced Fluent provider currently coexist through scoped legacy CSS. Each newly mounted portal must receive the provider theme and `data-react-owned` boundary. Verify Large/200% text for titles, tables, popovers and controls as well as ordinary labels. Remove obsolete React-path CSS once its owner is retired.
6. **Safe delivery is separate from ownership completion.** Preserve `/remove`, request-specific token/nonce, validated manifest-listed hashed assets, CSP-restricted style/module/font loading, package notices and build artifacts. No Vite server or Node backend is required by end users. A secure bundle can still contain an incomplete mixed-owner UI.
