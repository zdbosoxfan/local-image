Completed the model auto-detection task on `wip/codex-model-autodetect`, continuing the existing builder's refine work. Changes are uncommitted. The implementation is Rust, uses existing dependencies, and adds no unsafe code or build dependencies. No model weights were downloaded, no desktop app was opened or stopped, and configuration, caches, verdicts and test artifacts created by this job are isolated in this worktree. The authorized live checks used the existing ComfyUI server's normal upload/output APIs.

1. Template matching and recipe derivation are implemented in `crates/li-ai/src/refine.rs`. Unknown main weights stay in the installed catalog and are offered for refinement without claiming text generation or edit support. Discovery caches the index and template JSON by URL, uses the cache offline, refreshes both index and template bodies after 24 hours (retaining cached copies on network failure), and orders image-edit/img2img templates first. A match requires the exact normalized basename and loader role, and satisfies every declared size and SHA-256 constraint. Malformed constraints and unsupported hash algorithms reject the match. Declarations inside subgraphs are included. Comparison templates are reduced to the output branch using the installed weights; a bypassed matching model branch can be activated without enabling optional adapter branches. Loader choices are bound to actual ComfyUI inventory names, including subfolders. The matched graph retains its encoders, VAE, conditioning, sampler, scheduler and numeric defaults. Source image and denoise controls are marked. Text-only core sampler templates can become img2img using their own decoder VAE; custom sigma samplers use ComfyUI's `SplitSigmasDenoise`. Templates requiring additional images, masks, unavailable components or unsupported controls fail with a reason. This follows the [Comfy-Org workflow templates](https://github.com/Comfy-Org/workflow_templates), including the actual [Klein comparison template](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_flux2_klein_text_to_image.json).

2. The universal checkpoint recipe uses `CheckpointLoaderSimple`, source `LoadImage`, `VAEEncode`, positive/negative `CLIPTextEncode`, `KSampler`, `VAEDecode` and `SaveImage`. ComfyUI detects checkpoint architecture; the application does not invent an unknown split-weight loader. Steps, CFG and sampler/scheduler choices come from live `/object_info`. The text-generation denoise default is reduced to 0.35 for preservation, following the official img2img approach. Documented `modelspec.resolution`/`modelspec.encoder_layer` and `ss_resolution`/`ss_clip_skip` metadata affect resolution and CLIP layer selection. Training step counts are not treated as inference steps. Split weights require a working family or template. Sources: [CheckpointLoaderSimple documentation](https://docs.comfy.org/built-in-nodes/CheckpointLoaderSimple), [ComfyUI img2img tutorial](https://docs.comfy.org/tutorials/basic/image-to-image), [ComfyUI nodes](https://github.com/comfyanonymous/ComfyUI/blob/master/nodes.py), [checkpoint detection/loading](https://github.com/comfyanonymous/ComfyUI/blob/master/comfy/sd.py), [ModelSpec](https://github.com/Stability-AI/ModelSpec), and [sd-scripts ModelSpec metadata](https://github.com/kohya-ss/sd-scripts/blob/main/library/sai_model_spec.py).

3. The checker runs the shared procedural 512×288 image and preservation metric from `refine_check`: mean absolute RGB difference after resizing both images to 64×36, with a strict pass below 35. It tries family → matching templates → universal checkpoint. The complete successful recipe or failure reason is stored atomically in `state/ai-refine.json`, keyed by SHA-256 of the entire main model file. Old `{}` state loads through serde defaults; re-testing preserves other hashes. File hashing, state loading, template discovery and HTTP execution happen on workers. A process-wide gate admits one check at a time, queue running/pending entries defer checks, and admission is checked again immediately before prompt submission. Cancellation, queue contention and connection failures do not become persisted unsupported verdicts. Cancellation uses the existing per-prompt API, never a global interrupt. A background inventory poll invalidates changed files, including verdicts reused after restart. The picker exposes testing, disabled failures with reasons, Re-test, and Cancel test; the selected weight variant has its own status. Verified rows remain ordinary model choices. First-use application refinement also ensures verification on its operation worker.

4. Both standalone refinement and Draft → Refine use the selected refine recipe, its recommendations and its grid. They upload only the source/draft image. The draft sampler and reference images do not enter the refine graph. LoRAs are filtered to the chosen refine family; template and universal recipes conservatively omit user-selected LoRAs whose compatibility cannot be established. Existing known-family prompt conventions and large-image tiled refinement remain in the application path. Newly learned recommendations replace unchanged initial recommendations while retaining values edited away from them.

The added `refine_autodetect` example exercises the same checker and can measure the application's `Ai::generate` path with `--app-refine`. `refine_check` now shares the procedural image, prompt and metric rather than maintaining a second copy.

Practical limits: the default template source is the connected ComfyUI's version-matched official template package; `LOCAL_IMAGE_TEMPLATES_BASE` can select a newer official source or mirror. Unsupported graph controls, missing companion weights or additional required images remain explicit failures. A remote server whose model file is not accessible locally can be checked and reused for that session, but cannot have a trustworthy local file hash; such verdicts are not persisted under a fabricated hash. Main-file hashes do not cover changes to separately installed encoders/VAEs or ComfyUI itself, so Re-test is available after those changes. The single procedural test establishes preservation at the chosen defaults, not image quality for every prompt or user override. No task work is intentionally deferred.
