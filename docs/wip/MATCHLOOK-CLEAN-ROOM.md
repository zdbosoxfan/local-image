# Match Look independent-implementation boundary

Owner requested a clean-room approach on 2026-10-14. This is an engineering process
record, not a legal opinion or a claim of legal clearance.

## Existing work and exposure

The independent Match Look implementation and open-source ports already existed before
the REA investigation. Published checkpoint `3a1bee17` has the same application code as
`0a4f0b25`; the intervening commit adds documentation only. Earlier algorithm work,
including J2, has separate Git and upstream-attribution history.

REA inspection subsequently exposed the coordinating agent and research agent to
proprietary managed/native implementation material. Some derived observations were
also messaged to other existing agents. Those contexts must not be described as
unexposed clean-room implementers. Starting a new context does not erase that history.

Proprietary inspection is stopped. Target-derived evidence and imported analysis
databases are preserved outside this repository for owner/counsel review. No Capture
One binaries, weights, extracted code, reconstructed routines or private evidence
are authorized implementation inputs. No legal conclusion follows from REA's own
open-source license.

Post-checkpoint source-memory and cache work was specified from this application's
existing behavior. Its provenance is recorded separately; it is not automatically
certified clean-room merely because it is unrelated to the proprietary algorithm.

## Allowed implementation specification

Transfer the finished reference's color and tone to each target through this app's
ordinary editable controls. References may be edited RAWs or finished images. Preserve
normalization, selected-tool exclusions, portable saved looks, layer reapplication,
amount/history, batch consistency, cancellation and stale-result protection. Evaluate
different compositions/cameras and local photographic regions; a smaller statistics
error alone does not establish quality. Keep original user photographs read only and
private. Preserve v2 behavior, use pure Rust, and do not edit `crates/lc-raw`.

Sources of this specification are the owner's requests, the existing app, and
[public Match Look documentation](https://support.captureone.com/hc/en-us/articles/22188770298269-Match-Look-Tool).
It contains no recovered internal architecture, model contract, numeric constants,
decompiler output or private native call flow.

## Implementation process

1. Use a fresh implementation context without inherited investigation history. Limit
   its inputs to the functional specification, approved app source, public research and
   appropriately licensed open-source implementations/assets. Shared filesystem access
   is not a technical isolation guarantee; do not describe it as one.
2. Keep investigators and exposed contexts out of new matching-algorithm authorship.
   Any proposed transfer of investigation-derived information requires a separately
   reviewed behavioral specification. Merely paraphrasing disassembly is insufficient.
3. Independently design algorithms and tests. Record source URL/revision, license,
   author, rationale and test evidence for each substantive slice. Preserve existing
   GPL-3.0-or-later notices and compatibility obligations. Check model/checkpoint and
   dataset terms separately from code licenses.
4. Use synthetic/publicly licensed fixtures and the owner's read-only photographs for
   evaluation. Keep target finals out of fitting and threshold selection. Do not copy
   proprietary model weights, tables, resources or reconstructed implementation into
   source, fixtures, generated artifacts or trained-model inputs.
5. Review provenance and the complete diff before publishing. Retain exposure records
   honestly; do not delete evidence or relabel exposed work to simulate independence.

## Legal review boundary

The [US Copyright Office](https://www.copyright.gov/register/tx-programs.html)
distinguishes program expression from algorithms and methods. That distinction does not
resolve every contract, patent, trade-secret or access-control issue. The published
[Capture One agreement, section 4.1](https://mediagen.captureone.com/media/rkzpkalt/capture-one_eula_master-eula-eng.pdf)
restricts reverse engineering subject to mandatory-law exceptions; applicability to
the owner's installation and investigation has not been established here.

Counsel should review the exposure record and applicable terms before relying on any
proprietary investigation or making a clean-room legal claim. Independent development
from public sources can continue without treating that investigation as an input.
