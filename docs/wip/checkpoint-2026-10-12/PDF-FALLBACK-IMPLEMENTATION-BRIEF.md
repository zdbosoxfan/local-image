# Production FS009 PDF image fallback — implementation assignment brief

Prepared read-only 2026-10-12 against candidate HEAD `a8a6ddcfccea8744c4ff76df0503a048f683d23c` and current source. No source/build/test/probe/network changes. Assign only after the shared-shell coder is idle; root keeps the three-source-owner ceiling. This is a cohesive production task, not permission to ship a warning-only placeholder.

## Outcome and scope

An ordinary editable PDF still takes the native path. When editable import encounters a genuinely unsupported feature, the dialog must offer a real **Open as image** / **Place as image** workflow: bounded metadata, chosen page/box/resolution, explicit raster/white-background tradeoff, cancellable contained rendering, detached preview, then one guarded publication. No app mutation or partial output on cancellation/failure/stale context.

Retain the original constraints in `FS009-SCOPE-CHECK.md`: default groups, indirect lengths, named common codecs, inline images, empty-password permission encryption and leading bytes remain required native compatibility work; do not reclassify them all as fallback. K=true refusal is allowed. No universal native group-space/knockout work or nonempty-password entry UI is added. Production renderer correctness and containment are both required; the tiny readiness probe proves neither all unsupported-feature fidelity nor hostile-input robustness.

## Current seams verified

- `pc-ui-egui/src/lib.rs:389` defines `#[derive(Default)] Services`; native host registration is `apps/local-image/src/services.rs::native` (~412). Existing service closures are mostly non-Send UI callbacks, so a decoder worker needs its own **Arc + Send + Sync** service type. Root has reserved the Services region for this task.
- `pc-ui-egui/src/vector_packages/pdf_import.rs::State` owns bytes/name, info worker, decode worker, page/DPI/box/rotation, generation, captured `Place`, preview, errors and cancellation. `controls` polls workers, disables actions when page count is zero, and supports native Open/Preview/Place. `show` is the one host UI entry point.
- Strict `photocraft_pdf::info` → `pages::open` → preflight rejects unsupported content before page count. The async info/decode closures currently erase `ImportError` into `EngineError::Other(String)`. The sync source setter rejects the replacement without retaining a fallback candidate. Both paths need explicit fallback state while preserving the existing invalid-replacement behavior.
- `ImportError` has Invalid/Limit/Cancelled/Unsupported(&'static str)/Encrypted. Unsupported includes feature limitations **and** unsafe/ambiguous cases (external file streams, resource-role conflicts, indirect declarations); it must not mean unconditional fallback permission.
- `offer` requires a byte-zero header; `offer_path` reads only five bytes. Core preflight instead searches the first 1029 bytes for a five-byte header starting at offset ≤1024, then checks the version. Fix the real byte/path entry routes to share that bounded recognition. `file_open.rs::open_file`, `open_path` and `PhotocraftApp::open_bytes` already call the PDF offer hooks; keep their call sites stable where possible.
- Engine `pdf_import::capture/check/preview/publish/document` already supports Raster children, page frame, offset, document/revision/anchor/selection validation and one Undo transaction. Reuse it; no new document schema, canvas transform, renderer shader or compositor work is needed.
- Generic `import_worker::Task` signals cancellation and suppresses cancelled publication but cannot terminate an uncooperative thread. The platform adapter must terminate/reap its **owned process**, then return; do not weaken preflight or treat dropped-thread work as cancelled decoding.

## Proposed service and state contract

Use one optional `Arc<dyn Fn(PdfRasterRequest, &AtomicBool) -> Result<PdfRasterReply, PdfRasterError> + Send + Sync>` (a small trait is equivalent). Requests own `Arc<[u8]>`, immutable limits and source generation; variants are **Metadata** and **Render { page, dpi, page_box, rotation_policy }**. Replies are validated page metadata or bounded RGBA pixels with dimensions/DPI and explicit opaque-white-page semantics. Keep platform executable paths/temp directories out of the UI contract.

Preserve the existing typed importer error inside the generic worker rather than making import_worker generic over a second error type: for example `Task<Result<PdfInfo, ImportError>>` wraps the native result in an outer successful worker value, reserving outer EngineError for worker lifecycle failure. Equivalent typed outcome enum is fine. Define `RasterFallbackReason`/eligibility centrally at the PDF boundary. An internal explicit map from current static Unsupported reasons is a minimal bridge; UI must never parse localized error text. Better typed per-feature reasons can be introduced narrowly at approved refusal sites if needed.

Do not blindly fallback on Limit, Cancelled, malformed/ambiguous structure, external file streams or password-required failures. First eligible categories should be concrete remaining safe-to-contain compatibility cases such as unsupported image codecs/calculator functions, each with real fixtures. Preserve K=true refusal. The current generic “stream codec has no bounded decoder” loses the exact codec identity: classify the actual eligible codec at its refusal site if per-codec provider guarantees are needed. A first Unsupported error does not prove the rest of the document is safe; the independent process containment remains mandatory.

State progression: **native-info pending → native-ready OR unsupported-choice → image-metadata pending → image-ready → image-render pending → image-preview/ready-to-publish**. A source replacement cancels old work and increments generation. Known invalid replacement should retain the prior valid candidate per existing regression. Unsupported new input may become a new fallback candidate only deliberately, with its own bytes/name/reason; never display old metadata for new bytes.

Image metadata is itself untrusted decoding: obtain it inside the same containment, with bounded stdout/page count and selected-page box queries. On first unsupported result, show the choice even when native page count is zero. Require explicit image-mode selection before rendering. No-document context exposes Open as image; active document exposes Preview/Place as image. Preserve DPI semantics: Open uses chosen DPI, placement uses destination DPI for physical size unless the user explicitly selects a distinct supported resolution contract. Respect CropBox/MediaBox/rotation; validate UserUnit/rotated dimensions against limits before allocating. Add tests before promising exact transform equivalence.

Clone the service Arc into the existing worker; the callback receives that worker's cancellation flag. The dialog's source-generation/context/selection checks and engine `check` run again immediately before publication. Reuse `ImportedScene` with one Raster page layer and explicit warning, and existing `preview/publish/document` methods. Native PDF controls remain the default on successful editable import. No fallback re-decode on pointer movement/release; no save path pointing back to the source PDF as if it were a lossless native document.

## Production Linux adapter and dependency decision

The **proved** desktop command is recorded in `pdf-fallback-desktop-probe/{launch.json,receipt.json,REPORT.md}`: clean-env, explicit `/usr/bin` Poppler 26.01.0, prlimit 2.41.5, bubblewrap 0.12.0; exact executable/65-library mounts; private synthetic input/output/fontconfig, system fonts/Poppler data read-only; fresh namespaces incl. network, read-only root, dropped capabilities. Metadata and 72×72 PNG passed; controlled sleep cancellation directly reaped the owned child. Prior tool-sandbox NETLINK denial failed closed; preserve this behavior.

Use a Rust native adapter, **not Python/Codex runtime or our transient validation service**. Explicit system binaries/provider configuration; never use Codex PATH override pdfinfo/pdftoppm. Cache bounded readiness for trusted executable/library locations; if reproducing the probe's `ldd` closure discovery, run only fixed trusted system binaries, cap output, validate every resolved mount remains in allowed system roots, and list `ldd` as a runtime prerequisite. An ad hoc unvalidated library path is not an acceptable mount. Fonts must use a generated private config excluding user/system personal config; retained host mounts stay narrow/read-only.

Preserve at least the proven inner memory/CPU/file/deadline limits initially (512 MiB AS, 3 CPU s, 4 MiB/file, 8 s wall; tune only against explicit image limits/workloads). Also preserve production-equivalent **per-job process count and parent-death cleanup**: the probe's outer TasksMax=16/MemoryMax768M were real protection. Plain per-UID RLIMIT_NPROC is unsuitable alongside user builds. Choose/verify a safe per-job supervisor/cgroup policy or an equally restrictive child policy; do not silently omit this because the first renderer happens not to fork. A user-systemd scope is one deployment option, but if selected it becomes an explicit availability dependency with a clean env and owned-unit teardown—not reliance on an agent runner.

Use fixed argv, no shell; bounded private input and selected-page outputs; bounded/drained diagnostics; checked output dimensions/type before `image` decoding; input/page/pixel/byte budgets and aggregate directory accounting (FSIZE is per file). Check cancellation during both metadata and render, kill only the owned sandbox/process group or service cgroup, wait/reap, verify descendants gone, remove only owned private files. Sandbox/setup failure is unavailable/error, **never an unrestricted retry**. Distinguish missing runtime from feature refusal so the user sees a useful actionable message.

Opaque white-page Splash PNG is the proven minimal contract. Do not label it transparent placement. Known Cairo/Splash/group-colour limitations remain; select eligibility based on demonstrated fidelity for real unsupported cases, not on the tiny PDF success. Do not claim a screenshot rendered by Poppler and compared to itself is independent correctness evidence.

**Release owner follow-up, separate source permit:** declare distro runtime requirements/readiness in README and packaging/installer acceptance. The current tar contains app+CLI+notices only; native installation copies 11 owned files and no runtime helpers. Prefer an explicit distro-runtime dependency for the first Linux route; no automatic package install, no ad hoc copied host tools. A self-contained bundle requires a separately scoped helper/library/font/config closure and notices/source distribution work. Runtime-unavailable UI alone does not complete the user's installed Linux fallback: prove the actual accepted installed build finds the declared provider. No internet/download/install is authorized by this brief.

3. **Adapter lifecycle:** deterministic fake trusted helpers for crash/hang/large diagnostics/output/dimensions/symlinks/missing runtime/namespace denial, with enforced wall/memory/file/aggregate/process bounds and owned descendant kill+reap. Fake helpers are lifecycle proof only. Real contained PDF render fixtures establish actual backend readiness/capability.

Check rendered controls, keyboard/accessibility, focus and no background editor/Library input leakage. Run private profile on the staged release with explicit production tool paths.
