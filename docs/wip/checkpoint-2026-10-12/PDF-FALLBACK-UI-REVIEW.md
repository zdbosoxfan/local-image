## PF-UI2 — P1: cancellation/input ownership must be decided before publication

In frozen `vector_packages/pdf_import.rs`, `poll_worker` at248–269 can immediately `session.add_document` for Open or `pdf_import::publish` for Place. Both `controls` (around332) and `input` (497–512) call it **before** reading Cancel/Escape/focus-loss/enablement. `input` can then return early because the worker has already completed and `pending()` is false. `show` also learns its Window close state only after running controls.

Concrete boundary: the image worker has completed and its result is queued, and the next frame contains Escape or the Cancel-button click that the user issued while it was still pending. `controls`/`input` consumes the result and publishes first. The following cancellation cannot remove the new document or reverse the placed edit; in the button case pending may already become false and disable Cancel. Window-focus loss has the same ordering risk. A successful-ready result is not permission to ignore earlier queued cancellation input.

Required repair: centralize a per-frame cancellation/ownership decision before any accepting poll; honor the focused/topmost owner, queued Cancel/window-close and focus/context cancellation before consuming/publishing ready data. Polling that only collects detached results can remain separate, but publication must wait until the current source generation and input decision are known. Ensure there is one publication owner, not one early poll in controls and another in canvas input with different ordering. For no-document Open, the import window must own cancellation without relying on a canvas response that does not exist. Preserve existing field-owned Escape behavior rather than blanket-consuming all keys.

Required deterministic tests: use a controlled service to make a result ready without polling it; enqueue actual Escape and actual Cancel click in that next UI frame, separately for Open-with-no-document, direct Place and Preview. Assert document count, active DocId, existing document bytes/revision/history/selection, source path and warnings remain unmodified by cancelled work. Repeat ready-result plus window-close/focus loss and target/context change. Add source replacement while the old result is ready: no old-source scene or warning can become the new candidate's result. Keep a positive ready/no-cancel branch proving one normal publication/undo. Do not substitute `state.cancel()` immediately before `poll_worker` as proof of the UI race.

## Paths that are sound within this review

- **Unsupported before native info:** `accept_source` retains eligible typed `ImportError` and source/name even if `PdfInfo` does not exist. The fallback section is shown before page-count controls. The enabled Use image fallback action starts metadata on the injected worker service, enabling image actions only after a valid bounded page count. This is a real workflow, not a warning-only link.
- **Honest tradeoff:** before opting in, the UI says opaque white page and noneditable text/paths and names the source. The detached scene includes the same warning. Native import remains the first path. Absence of a provider and provider failure are displayed; there is no silent renderer retry or fake editable conversion in UI code.
- **Page geometry/options:** selected page is converted to zero-based page index, CropBox/MediaBox and apply/ignore rotation are passed explicitly. Open uses chosen DPI; preview/placement use destination DPI to preserve physical page size. Pixel scene validation enforces positive dimensions/length/budget, valid DPI and alpha255. Detailed provider metadata/rotation/box fidelity belongs to `ai_contracts` and the actual runtime gate; this review does not infer it from the2×1 UI mock.
- **No-document behavior:** Open as image is enabled after image metadata regardless of active document; Preview/Place require an active destination. Source-level no-document Open test produces a raster document, but actual no-document buttons/cancellation still need PF-UI2's frame test.
- **Captured placement:** engine `vector_packages/pdf_import.rs::Place/check` captures DocId/revision/active layer/selection and validates them before preview/publication. Placement inserts one prepared group in one Session edit and supports Undo/Redo. The image worker carries that captured request and cannot legitimately publish into another active document/selection. Stale destination test currently covers a changed revision; add wrong-document/selection controls at repaired adapters.
- **No native overwrite:** the Open worker adds the document with `path=None`; the PDF chooser does not write source bytes. Existing ordinary Open offer returns before `opened_from`, retaining the PDF only as recent/source input. Preserve this on the added Place routes.
- **Source/task lifetime:** source replacement/cancel drops Task receivers, whose Drop signals cooperative cancellation; old receivers cannot later return to the new State. Known invalid replacement retains the old source/info rather than claiming a new candidate. Settings changes cancel render/preview while deliberately retaining an in-flight metadata query. These controls are useful, but they do not solve ready-result input ordering.
- **Header routes:** shared versioned `%PDF-` recognizer checks starting offsets0..1024; native path probe reads1032 bytes and retains full input budgets/path validation. Exact leading-header offer is tested directly. This helps named FS009 leading-byte support; broader malformed/header ambiguity/budget judgments remain in the native-boundary review.
