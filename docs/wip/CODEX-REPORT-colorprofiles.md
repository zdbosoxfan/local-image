# Colour profiles report

2026-10-14. Changes are uncommitted. Continued the branch's existing DCP parser,
55 whole CC0 profiles, user-folder preference and deferred camera-profile render stage.
No Match Look files were touched, no owner photos were used, and nothing under Desktop

## (a) User Adobe/custom camera and lens profiles

Implemented read-only discovery of Adobe Camera Raw/DNG Converter standard shared,
personal and application resource locations on Windows/macOS. Settings → Import's
existing Choose folder now accepts nested DCP/LCP trees; Reload Profiles rescans them.
Original profile bytes remain whole in the user's installation. Nothing from Adobe
is bundled, copied into the catalog, redistributed or uploaded.

The registry preserves alternate profiles for the same camera and assigns content-based
ids, rather than overwriting a model's preceding profile. Develop and the profile browser
show compatible Camera Profile choices (Adobe, Camera Matching, Custom Camera Profiles),
Automatic, Matrix Only and the existing bundled profile. Creative profiles/looks remain
available separately. Selection is serialized, participates in copy/paste/presets and
source cache keys, and survives reopening. Changing the registry invalidates decoded
sources and thumbnail interpretation; the renderer cache version is now 18.

DCP application preserves input AnalogBalance, AsShotNeutral and CameraCalibration.
Calibration matrices are used only when CameraCalibrationSignature matches
ProfileCalibrationSignature, as required by Adobe's reference implementation.
New fields have defaults; old settings/catalogs/smart previews still deserialize.
Custom body profiles are chosen explicitly among profiles for the same camera model.
There is no claim that a generic DCP is automatically more accurate than a matrix.

Develop's Optics section lists compatible imported Lens Profiles. Perspective LCP models
are evaluated in the existing single geometry resample, replacing embedded/lensfun
corrections so they are not doubled. Supported data include radial and tangential
distortion, separate normalized X/Y focal lengths, relative RGB CA, polynomial vignetting,
and focal/focus/APEX aperture interpolation. Remove Chromatic Aberration controls the
calibrated CA and suppresses automatic CA estimation when a calibrated model is active.
Source EXIF orientation is retained, including smart previews; all 64 combinations of
EXIF/user orientation are exercised. Missing focal length disables a correction; missing
aperture disables vignette correction; unavailable focus uses the furthest calibration.
Mismatched camera/lens metadata does not apply a copied profile selection.

Imports are bounded (32 MiB per file, 256 MiB read budget, 4096 candidate files, 65536
traversal entries, depth 12); traversal does not follow descendant symlinks. Malformed or
unsupported profiles are skipped, with counts in Settings. XML does not resolve external
entities or DTDs; predefined/numeric character references remain supported.

UI additions use Tokens and the documented shared `widgets::profile_choice`; the existing
folder action uses the shared text button. Pending strings are in
[i18n-pending-colorprofiles.md](i18n-pending-colorprofiles.md).

## (b) DNG 1.6+ triple illuminants

Implemented ColorMatrix3, ForwardMatrix3, CameraCalibration3, CalibrationIlluminant3,
ProfileHueSatMapData3 and IlluminantData1/2/3, including custom xy and sampled spectra in
both TIFF byte orders. Matrices, camera neutral/white balance and hue/saturation tables
share the same three weights throughout raw decoding, Develop's WB stage and camera-preview
fitting. DNG export preserves third data, custom whites and calibration signatures,
with DNG version/backward-version handling following the SDK.

Weights follow Adobe's temperature/tint-coordinate inverse-distance, smoothing, cutoff
and renormalization algorithm; they are not an invented barycentric-xy approximation.
XYZ-to-camera combines calibrated matrix products without spurious interpolation cross
terms. Existing dual-illuminant behavior remains on its existing path.
Incomplete/invalid triple DCP matrices or tables are rejected rather than silently
interpreted as a different profile.

Five focused tests include six exact SDK weight vectors and an independent nine-value
SDK ForwardMatrix result, both generated by running original SDK routines externally in
`target/refvec/dng-triple/`. Spectral/xy/endian/malformed parsing, DCP/DNG roundtrip,
calibration signature behavior and third-map hash/table evaluation are covered.

The full CIE 1931 2° observer CSV and upstream metadata are retained unchanged under
`crates/lc-raw/data/color/`, pinned to CIE 018:2019/DOI 10.25039/CIE.DS.xvudnb9b and SHA-256
`fa663e3535a7e0763a745993a1f0a192eb0275ac46ad2d1befd7626841e713c1`.
CC BY-SA 4.0 attribution, licence and whole-file update procedure are recorded with the
data, in PORTS.md, notices and app attributions. No SDK source enters the Rust build.

## (c) Body profiling recipe and measured colour quality

[CAMERA-PROFILES.md](../CAMERA-PROFILES.md) provides the external GPL-3 dcamprof/Argyll
workflow: separate measured tungsten/daylight ColorChecker or SG shots, correct chart
reference, linear camera RGB, flat-field/checker sampling, dual-profile construction,
body naming, import/reload, and independent validation captures. It includes actual
commands, small measurement tools and provenance rather than promising accuracy from a
profile name.

One genuine CC0 ColorChecker shot was downloaded under `target/colorprofiles-quality/`:
raw.pixls.us id 3013, Sony DSC-RX100M6, source SHA-256
`3015022b00ce219bf2713d9de21608e631566d111c4468402748b794e312d94c`.
The Rust example exercises the actual raw decoder, RCD and camera colour/profile functions;
creative tone/look tables and exposure rendering are disabled for measurement. External
RawTherapee 5.13 TIFFs use their actual embedded ICC matrix/TRCs, and all renders share
one documented neutral exposure matching rule.

| As-shot white balance, 24 patches | Mean ΔE2000 | Maximum | Mean skin patches |
|---|---:|---:|---:|
| Current matrix | 2.7297 | 7.1146 | 3.5019 |
| Bundled CC0 DCP, Local Image | 3.2265 | 4.8741 | 4.1925 |
| Same DCP, RawTherapee 5.13 | 3.2869 | 4.8935 | 4.2132 |

Local DCP versus the reference: mean ΔE2000 0.07881, maximum 1.17548. The DCP reduces the
largest patch error but worsens mean and skin errors on this specimen. Matrix Only is
therefore available; no camera-wide automatic superiority conclusion is justified.

An actual custom DCP was generated with dcamprof 1.0.6, built externally under
`target/refvec/dcamprof/` with extracted unmodified header packages and existing system
shared libraries, without system writes. Sixteen fitting patches and eight held-out
patches (including both skins) were used. DCP SHA-256:
`80bd925ea2206eaca5d107a10e6e638241902bb1efca4a2d5f7c511e4a6c6050`.
Local Image loads/applies it. Held-out mean: 3.1172; RawTherapee: 3.1214. The same frame's
held-out patches are not an independent validation capture.

A second small check uses identical sensor WB ratios from D05, emulating a neutral
picker. This isolates as-shot WB error without fitting chromatic patch colours:

| Neutral-patch WB | Local mean ΔE2000 | External mean ΔE2000 | Local held-out mean |
|---|---:|---:|---:|
| Matrix | 2.7363 | — | 2.6751 |

Bundled neutral DCP agreement with RawTherapee: mean 0.10360, maximum 0.33972. Details,
ROIs, unmodified chart references, saved PP3s, TIFFs, CSVs, JSON results, source/tool hashes
and failure logs remain under target/. Published Sharma CIEDE2000 edge cases check the
metric. An invalid RawTherapee camera-RGB export was retained and rejected before fitting;
the reported custom profile used the explicit Rust camera-RGB output instead.

**The requested mean ΔE2000 < 2.5 was not achieved**, with either as-shot or chart-neutral
white balance. The sample's illuminant spectrum, target manufacture/date and measured

not be described as meeting a camera-wide/body-specific colour accuracy gate yet.

## Remaining limits and unavoidable outside-area changes

- Imported perspective LCPs use CPU geometry sampling because existing GPU warp parameters
  cannot represent their anisotropic/tangential terms faithfully. Later GPU stages remain
  available. No throughput or real-GPU performance claim is made.
- Fisheye, piecewise-vignette, and nonzero fourth/fifth vignette coefficients are explicitly
  rejected. XMP creative/Adaptive Adobe profiles are outside DCP/LCP scope.
- Standard macOS/Windows location logic is implemented; the owner's Linux host has no native
  Adobe install for an end-to-end Adobe-data test. Whole CC0 DCP and synthetic LCP imports
  exercise the actual folder and picker flow without redistributing Adobe data.
- Profile choice is by model compatibility with explicit selection for a particular body;
  missing/incompatible lens metadata cannot be inferred reliably.
- No full crate/workspace suites, benchmarks, GPU acceptance runs or long quality sweeps
  were run, per the task's ABSOLUTE MINIMUM TESTING override. GPU tests added: **0**.
- `lc-merge/src/output.rs` and the existing `lc-gpu/tests/it/toolset.rs` only gain defaults for
  newly additive colour fields so their existing initializers still compile. Engine
  coverage literals gain RawOptions defaults. These are the unavoidable outside-area
  compatibility edits. Shared theme/widget docs and attribution assets are required by
  the design-system/data licensing rules.
