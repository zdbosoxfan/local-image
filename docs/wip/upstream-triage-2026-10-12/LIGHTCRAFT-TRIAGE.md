Verified so far:
- MUST a443659 DNG bad-pixel opcode cap. Ours `crates/lc-raw/src/opcodes.rs:442-461` still lists every pixel equal to FixBadPixelsConstant's constant with no cap, and the List cap is checked only after a whole rect is pushed. Hostile or merely dark DNG -> multi-GB Vec -> OOM abort (not catchable). Easy (10 lines).
- MUST 87cd873 XMP merge quadratic attribute check. Ours `crates/lc-meta/src/xmp_merge.rs:147` and `:428` still use `e.attributes()` (quick-xml quadratic duplicate check). A crafted sidecar with ~200k attributes hangs a metadata save for 20 s+. Easy.
- MUST 0a474cc permanent delete of several photos built per-photo against the unchanged catalog. Ours `crates/lc-engine/src/cmd/library.rs:587` maps `delete_permanently_ops` per id: two deleted photos in the same album -> second SetAlbumPhotos re-adds the first (dangling album entry to a removed photo); two in one stack -> NoStack failure. Easy (add `delete_photos_permanently_ops` to lc-catalog, call it).
- MUST (part of) 790a341 bounded folder walker. Ours `crates/lc-engine/src/import.rs:310 expand()` recurses with `is_dir()` (follows symlinks), no depth/entry bound, no loop detection: a symlink cycle in an imported Linux folder (two links -> 2^40 paths before ELOOP) hangs the import; one link imports the same files under many paths. Port the `walk::files_in` bounded walker (32 levels, 1M entries, links followed once); the launch-arg/drive-root parts are optional. Moderate.
- Already fixed in ours: 6aa599f PSD RLE bounds (ours psd.rs has 512 MiB cap + truncated-count check); 7173242 JPEG scale overflow (ours jpeg.rs:113 saturating); 8166185 lock unlock-on-drop (ours b3365a2f); 5a537d5 GPU quiesce at quit (ours dc10bae6/609576d1).
