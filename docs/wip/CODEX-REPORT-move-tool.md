# Move tool continuation report — 2026-10-09

Continued the existing Move, modifier, snapping, Free Transform, and GPU canvas implementation in this branch. Changes are uncommitted. No dependencies, unsafe code, C/C++ code, or persisted settings/document fields were added. Existing settings retain their serde defaults; the new capture and render caches are transient.

| Task point | Result |
| --- | --- |
| 1. Live movement and reliable drags | Move owns the primary press through release instead of waiting for egui's drag threshold. Input is processed before painting, including the first pixel and a newer mouse-up position. Capture survives changing widget IDs, relayout, crossing panels, PointerGone/re-entry, and release outside the canvas. Shift and Space changes preserve an active Move gesture. Escape and focus loss cancel cleanly. Ordinary moves, selected-pixel moves, and Alt copies commit one edit on release. Alt copies are transient while held: no document, history, or journal edits mid-drag. Linked copies get separate links so moving them cannot move their originals. |
| 2. Cursor | The current branch already used native Move/Hand icons; no painted hand was found to remove. Fixed Move hover across widget-ID changes, retained native Move during capture across panels, and fixed the active Hand-pan branch to emit Grabbing. Space shows native Grab, then Grabbing while it actually pans. |
| 3. Documented behavior | Layer/Group Auto-Select and Ctrl/Cmd inversion work before snap targets are built. Show Transform Controls frames the shared selection and scales multiple selected/linked layers atomically. Shift constrains horizontal/vertical movement; Alt/Option-drag copies; arrows move 1 px and Shift+arrows 10 px. Canvas edges/center and other layers snap with smart guides; Ctrl/Cmd during motion bypasses snapping. Groups exclude their descendants from self-snapping. Selected pixels move or copy with their selection mask, leaving unselected pixels in place. Disabling Snap and Smart Guides now also suppresses the snap renderer's moving outline. |
| 4. Large-document speed | Added cached GPU planes for independent Normal compositing. Stationary and moving runs keep their original stack order, with moving planes translated at viewport resolution. Display color management, HDR preview, checkerboard, and pixel grid are applied after blending. Idle preparation lets a press reuse the cache even when Auto-Select changes only the session revision. Warm drag frames do no pixel shifts, recomposites, or layer texture uploads. Release commits the real engine move and refreshes the composite. Real RTX 5090 results are below. |
| 5. Real drag tests | Added 13 egui_kittest input tests, four engine tests, three GPU correctness tests, and one explicitly invoked large-document benchmark. Tests use actual primary presses, motions, releases, modifiers and key events. They assert live preview bounds before release, capture/recovery, snapping, multi-layer transforms, selected pixels, cursor output, unchanged history/journal while held, and undo/redo. GPU tests inspect rendered app pixels while the button is held. |

Behavior follows [Adobe's layer selection help](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/transform-manipulate-layers/select-layers.html), [Affinity Photo's Move Tool help](https://affinity.help/photo2/en-US.lproj/pages/Tools/tools_move.html), and the Move/nudge/duplicate conventions in [Adobe's Photoshop reference](https://helpx.adobe.com/pdf/cs6/photoshop_reference.pdf). Transform handles reuse the existing Free Transform system, consistent with [Adobe's Free Transform help](https://helpx.adobe.com/in/photoshop/using/free-transformations-images-shapes-paths.html). Selected-pixel copying follows [Adobe's selection copying help](https://helpx.adobe.com/sg/photoshop/desktop/make-selections/refine-modify-selections/copy-and-paste-selections.html). The current [Adobe snapping help](https://helpx.adobe.com/photoshop/desktop/create-masks/layer-masks/position-elements-with-snapping.html) specifies an approximately eight-pixel tolerance and Ctrl/Command bypass; this also corrects the branch's previous macOS snap-override convention.

Capture uses the press origin, current pointer position, raw button events, and focus events described by [egui 0.36.2 PointerState](https://docs.rs/egui/0.36.2/egui/struct.PointerState.html). The GPU work extends the repository's canvas/transform texture pipelines using [egui-wgpu's prepare/paint callback contract](https://docs.rs/egui-wgpu/0.36.2/egui_wgpu/trait.CallbackTrait.html). The plane partition/cache design is new local code; no external engine port was added. GPU tests use the app's `gpu_canvas::wgpu_setup()` rather than egui_kittest's software-preferring default setup. The harness's synthetic triangle cursor and optional canvas overlays are excluded from pixel comparisons; native cursor behavior is tested separately through platform output.

The measured benchmark used the complete `PhotocraftApp` UI and canvas callbacks offscreen, without opening desktop windows: 8000×6000 RGB, 26 layers including a full-canvas moving raster, 8% zoom, 1200×800 output, 803×677 canvas viewport, one pixel per point, and 120 distinct pointer frames. Adapter: **NVIDIA GeForce RTX 5090**, Vulkan, discrete GPU, **NVIDIA 615.71.09**; no fallback or device loss. The benchmark asserts the 5090/Vulkan adapter and zero per-frame layer uploads. This is the repository's optimized test/dev profile (`opt-level=1` for workspace code), on the shared owner PC.

They fail on a CPU/software adapter; the initial software-adapter run was rejected and is not counted as GPU verification.

No owner app was killed, no GUI window was opened, no ComfyUI job was submitted, and no owner files outside the worktree were edited.

Performance boundaries: cached planes apply to independent Normal RGB stacks, including supported groups and linked masks. Backdrop-dependent blends, adjustments, clipping/effects, moving unlinked masks, nested child targets, linear-encoding/non-RGB documents, selected-pixel moves, unusually large off-canvas content, and more than 16 alternating moving/static runs retain the exact reference preview. These still use the new capture/live input path, but are not covered by the 48 MP offset-only timing claim. A new eligible target/document or an Alt copy can require one cache rebuild; preparation may briefly stall that frame if it was not ready while idle. Extending constant-cost movement to those complex stacks requires compositor support for their backdrop dependencies rather than flattening them incorrectly. Shared scale/rotate handles work; multi-layer folded transforms and Warp remain limited to one layer/group, so grouping is the existing route for those operations.
