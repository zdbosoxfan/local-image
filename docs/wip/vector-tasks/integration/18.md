# Package 18 integration lane

Owned blend evaluator, commands, UI controls and app hooks are implemented. The existing
engine vector_packages registry already calls blend::specs(); do not register it twice.
The new pc-vecfx crate and minimal UI `pub mod blend` registration are included under the
latest REGISTRATION rule. No shared menu, router, UiState, schema or locale catalog edits
are included. Apply the following fragments through 00 before full-app acceptance.

## Commands and provider

`photocraft_engine::vector_packages::blend` exports Capture, Request, Operation, Preview,
preview, commit, spec and spine. Capture::begin(session, ids) records document/revision/
target IDs and validates the full selection. Command parameters:

- vector.blend.create: `{capture:{document,revision,layers},spec:BlendSpec}`
- vector.blend.options: same, exactly one live group
- vector.blend.expand / vector.blend.release / vector.blend.info: `{capture}`

Create orders adjacent sibling keys by paint order. Expand replaces one live group with
its deterministic ordinary projected group. Release removes the live tag and retains
only the editable keys. Options/create/expand/release each journal once and use one
Session::edit. Preview is detached and does not journal. Info is read only. Reject stale,
missing, duplicate, ancestor/descendant and inherited-locked targets atomically.

Persisted BlendSpec remains the shared V9 type: spacing is `SmoothColor`, `Steps(u32)`
or `Distance(f64)`; orientation is `AlignToPage` or `AlignToPath`; spine is Option<Path>.
Use serde serialization of this type, not guessed lower-case strings. Its current enum
encoding and defaults stay compatible with existing documents.

00 can replace the engine's temporary source-path bridge with

The bridge compiles the exact same owned source while avoiding an unauthorized engine

## App registration fragments

Existing root module `crate::blend` is already registered. Add this field to UiState and
its Default implementation (serde defaults preserve old settings):

```rust
#[serde(default)]
pub vector_blend: crate::blend::State,
// In UiState::default():
vector_blend: Default::default(),
```

State serializes only BlendSpec; capture, drag, preview, host tool, errors and projection
cache are transient. Context/menu button opens the same controls; under the Vector
persona add this to context_bar::show's horizontal context controls (and expose the
menu entry for live groups, which the current context resolver otherwise omits):

```rust
crate::blend::app_hooks::context(&mut app.ui.vector_blend, ui);
```

Add the following current-shell menu fragments. The existing TOP_MENUS contains Layer;
00/01 should route its path to Object > Blend in the Vector persona's Object menu when
that persona menu registry lands, retaining Layer > Blend for the current shell:

```rust
// menus.rs UI_COMMANDS entry:
("vector.blend.ui.options", "Blend Options", &["Layer", "Blend"], None),
// menus::invoke match arm:
"vector.blend.ui.options" => {
    app.ui.vector_blend.open = true;
    Ok(serde_json::json!({"open":true}))
},
// At the start of menus::is_enabled:
if id == "vector.blend.ui.options" {
    return app.session.active().is_some()
        && app.session.prefs().toolbar.persona == photocraft_engine::toolsets::Persona::Vector;
}
```

Opening this window is a UI command, not a journaled engine command. Create/Expand/
Release are real engine commands invoked by the panel with freshly captured IDs; do not
call them with only the active layer ID. Add i18n/18.tsv English strings to every
supported catalog.

Immediately after context_bar::show in PhotocraftApp::update, use the ordinary window:

```rust
let mut blend = std::mem::take(&mut self.ui.vector_blend);
if let Err(error) = crate::blend::app_hooks::window(&mut blend, self, &ctx) {
    crate::notices::error(self, error.to_string());
}
self.ui.vector_blend = blend;
```

At the start of primary canvas_view, before selecting the display tree or routing input:

```rust
if primary {
    let mut blend = std::mem::take(&mut app.ui.vector_blend);
    crate::blend::app_hooks::synchronize(&mut blend, app, &ctx);
    app.ui.vector_blend = blend;
}
```

Synchronize cancels on document/revision/selection/tool/persona/dialog/focus changes,
Escape and PointerGone. While editing the spine, the window chooses existing
Tool::PathSelection and the blend hook consumes only the spine gesture. Future dedicated
tool registration may reuse this hook; no parallel selection or Move state is introduced.

At the start of canvas::tool_event, before ordinary path-tool handling:

```rust
if let Some(xf) = ViewXform::active(app) {
    match crate::blend::app_hooks::event(
        &mut app.ui.vector_blend, &mut app.session, ev, mods,
        f64::from(xf.zoom),
    ) {
        Ok(true) => return,
        Ok(false) => {},
        Err(error) => {
            app.ui.vector_blend.cancel();
            crate::notices::error(app, error.to_string());
            return;
        }
    }
}
```

Hit targets use six egui logical points divided by zoom, matching the logical-point
overlay size on HiDPI displays. Gesture coordinates are document pixels. Current modifiers are read
on every move/release; Shift constrains the anchor delta and Alt edits its outgoing
handle. Keep the host's captured outside-canvas Up route. Do not route secondary views.

Rename existing display_doc to base_display_doc and wrap ALL of its return paths:

```rust
fn display_doc(app: &mut PhotocraftApp, idx: usize) -> (std::sync::Arc<Document>, u64) {
    let (source, key) = base_display_doc(app, idx);
    match crate::blend::app_hooks::project_display(
        &mut app.ui.vector_blend, &app.session, idx, source.clone(), key,
    ) {
        Ok(shown) => shown,
        Err(error) => {
            app.ui.vector_blend.cancel();
            crate::notices::error(app, error.to_string());
            (source, key)
        }
    }
}
```

This runs AFTER existing Move/Node/style preview selection. It projects lazy key edits
in those detached trees, including the display selected by Navigator/GpuCanvas. The
same immutable source Arc reuses its cache; a key edit replaces the Arc and reprojects.
The blend option/spine preview is used only while its capture remains current.

Next to the existing path overlays in canvas_view:

```rust
crate::blend::app_hooks::paint(&app.ui.vector_blend, app, &painter, &xf);
```

Finally register full-app acceptance after the state/menu/canvas fragments above:


This source exercises offscreen PhotocraftApp controls, actual canvas pointer events,
GPU canvas, preview/release, clipped/effect layers, expand, Escape and undo. Its adapter
selector requires RTX 5090 + Vulkan + discrete + Rgba32Float. It cannot pass through a
software adapter or skipped hardware. It is intentionally not registered against an
app that lacks the coordinator-owned hooks. The registered engine GPU gate covers the
shared compositor. Both GPU runs are deferred by the latest speed rules.

## Shared schema/color follow-up

The current shared BlendSpec has no `starts` or `key_anchors` fields from upstream.
PathPair::with_starts(a,b,(Option<usize>,Option<usize>)) implements explicit first-contour
starts, while the persisted evaluator automatically matches winding/start/holes. A
clicked-start UI needs an additive defaulted shared field in 00's schema lane before
it can persist; this package does not expand read-only shared types.

pc-color currently has no Oklab helper. The owned paint module adapts the published MIT
2021 matrices and reuses pc-color transfer functions. 00 may promote these functions to
pc-color without introducing a new dependency, then delegate the owned adapter to it.
