## 00: additive data and native mirrors (required, before publishing this feature)

The legacy `Fill::Solid(Color)` and gradient `(position, Color)` literals are widespread.
Package 39 supplies `SwatchBook`, `SwatchRef` and `PaintTarget` in
`photocraft_doc::vector_design::swatches`. `SwatchBook.links` is a portable adapter snapshot
of optional per-use references, not a second application palette. It can initially be stored
as a document-owned side table; the target identifies root/master, layer, paint slot and
optional stop. This preserves old Fill serialization and exhaustive matches. If 00 instead
adds references directly on solid paints/stops, Access below gathers/scatters them and stores
only palette entries/groups in Document.swatches. Both use the same package API.

Minimal concrete side-table activation:

```rust
// pc-doc/src/lib.rs, Document (and Document::new)
pub swatches: vector_design::swatches::SwatchBook,
// constructor:
swatches: Default::default(),

// pc-format/src/manifest.rs, DocM
#[serde(default, skip_serializing_if = "photocraft_doc::vector_design::swatches::SwatchBook::is_empty")]
pub swatches: photocraft_doc::vector_design::swatches::SwatchBook,

// pc-format/src/convert.rs, doc_m
swatches: d.swatches.clone(),
// Loader::document, Document literal
swatches: m.swatches.clone(),
```

After **both** ordinary layers and symbol master layers have been decoded, make `doc` mutable
and apply the Loader's existing `id_map`:

```rust
doc.swatches.validate().map_err(FormatError::corrupt)?;
doc.swatches.remap_layers(&self.id_map).map_err(FormatError::corrupt)?;
```

Validate every paint target after decoding before returning doc (no locks required on load):
`colours::color(&doc, &link.target)` is the engine oracle; copy its small data-only paint-slot
lookup to pc-doc for the format layer or inject a validator. pc-format must not depend on engine.
Old manifests with no field produce an empty book; FORMAT_VERSION remains 2.
Adjust any Document/DocM literals found by all-targets check. Existing serde Fill values do not
change. Add the field to copy/new-document paths only where needed; imported SVG/PSD start empty.
`SwatchId` is document-local. References are IDs, never mutable names.

Reference maintenance is part of activation: delete removes layer links; duplicate/paste
remaps layer IDs and imports/remaps swatch IDs; delete/reorder gradient stops and Appearance
items remaps their indices in the same edit. Do not let an index silently bind to a different
paint. Master expansion is detached and should resolve references before cloning. Palette
entries and their linked gradient stops are included in the book. No XMP storage is used by
production; test XMP providers only simulate the missing shared field inside Session history.

Install Access once, before executing any registered colour commands or constructing colour UI:

```rust
use crate::vector_packages::{colours, recolor};
colours::install_access(colours::Access {
    read: |doc| Ok(doc.swatches.clone()),
    write: |doc, book| { doc.swatches = book; Ok(()) },
})?;
// vector_packages::specs():
out.extend(colours::specs());
out.extend(recolor::specs());
```

Access registration belongs to a once-only engine bootstrap, **not** Session::new on every
session. Commands are `swatch.document.edit` (journal=true), `.list`/`.preview` (false),
`recolor.colors`/`.reduce`/`.preview` (false), `recolor.apply` (true). Edit requests contain a
`Capture { document, revision }` and typed `Action`; recolour requests contain `Plan` with
captured selection and exact extraction. The UI must execute the edit command, not directly
call the lower-level commit helper, so Session owns exactly one journal record.

## 00: tab, dialog and detached canvas routing

UI public modules: `crate::swatches_doc`, `crate::recolor`.
Keep the existing Application Swatches tab. In Vector persona, add a **Document Palette** tab.
Store `swatches_doc::State` and `recolor::State` transiently in the existing UI state; no saved
settings or second workspace. Hooks:

```rust
swatches_doc::panel(ui, &app.session, colours::access()?,
    &current_fill_or_stroke, &captured_paint_targets, &mut state) -> Result<Option<swatches_doc::Event>>
recolor_state.open(&app.session, colours::access()?, &selected_layer_ids)?;
recolor::dialog(ctx, &app.session, colours::access()?, &mut recolor_state) -> Result<Option<Plan>>
```

`Event::Commit(request)` -> `app.run("swatch.document.edit", serde_json::to_value(request)?)`.
Dialog `Some(plan)` -> `app.run("recolor.apply", serde_json::to_value(plan)?)`.
`Event::Recolor` opens the dialog with the current selected layer IDs. Menu:
Edit > Edit Colours > **Recolor Artwork…**, enabled on a supported selection; no assigned
shortcut or new canvas tool. Tool/icon lane 01/46 can use the existing swatch/palette icon.

`state.preview.as_ref().map(|p| &p.document)` supplies the detached document to the existing
CPU/GPU/scaled canvas request. Do not replace `Session.doc` even temporarily, record history,
or reuse the current-revision cache key for changed preview paint. Use a transient preview
request key and clear it on cancel/Escape/staleness/persona or document switch. Render the
complete stack; symbol dependent caches are prepared by the engine. Dispatch success/error
must clear the transient canvas request. Release re-prepares and validates before one edit.

`Event::ImportAse(capture)` opens the existing file picker. Bounded async file read, then
`swatches::import_ase(&bytes, ImportLimits::default())`; display warnings and submit
`Request { capture, action: Action::Import { palette, replace: false } }`. Stale captures fail.
Offer replace through `replace:true`; it converts prior links to their local resolved values.
`Event::ExportAse(book)` -> `swatches::export_ase(&book) -> exchange::ExportedVector` and the
existing save picker, showing its gradient/alpha loss warnings. No engine/UI dependency in
file adapters. Cancelling either picker submits no command.

The document panel supports multi-select, double-click editing, global/spot toggles, tint
percentage, gradient stop colours/positions, group creation/ungroup, merge, add-used colours,
apply/delete and ASE/recolour events. Recolour supports source row drag/drop, typed hex assign,
reduction, three methods, seeded order/HSB randomizers, Preview/Cancel and Save as Swatch Group.

## 08/15/09 rendering dependencies

Colour preparation uses `CompiledAppearance`, existing patterns, legacy mirrors and aggregate
512 MiB bounds-limited cache budgets. Live-corner geometry uses the existing 06 evaluator; shape
clip/live/on-path metadata without an integrated colour projection fails atomically. `prepare_with_projection` APIs accept 08's
`StrokeProjection` provider for brushes/width profiles; command handlers currently use
`NoProjection`, as existing 08 does. Supply the integrated provider before enabling those
advanced combinations. Current 15 `render_instance` rejects advanced master appearance,
corners, on-path text/live/clip metadata; package 39 propagates that error atomically rather
than rendering stale master instances. 15/08 must activate their shared projection before
claiming global edits on advanced master paints. Ordinary master fills/strokes/stops work.

Selected symbol instances address their shared master; recolouring one updates that master
and thus every instance. Ordinary global swatch uses in a selection are detached during
recolour, so unselected art and the original global swatch stay unchanged. Preserve Tints uses
captured global tint percentages and detected local ink ratios. Preserve Lightness retains
CIE L* D50 (0..100), including out-of-gamut target chroma reduction; it returns RGB process
colour and retains source alpha. Exact and Preserve Tints use the assigned colour model.

## 14/21/23 exports

Every command writes resolved plain colours into authoritative fills/strokes/stops and mirrors
before publishing; ordinary SVG/PDF consumers read these. Resolve links on loaded docs via
Access/colours preparation before export if external code altered a palette without a command.
PSD: call `swatches::export_warnings(&book, false)` and merge into 23's warning collector;
links/spot semantics are lost, ordinary resolved colours/pixels remain authoritative.
PDF: only pass `separations:true` when 21 actually emits Separation resources. Otherwise use
false and include its spot warning. No Separation implementation is claimed by package 39.
ASE omits gradients and opacity with explicit exchange warnings.
