## Compiled interfaces

- `photocraft_vecfx::brush::{Brush, Calligraphic, ArtBrush, ArtScale, Direction, Scatter,
  PatternBrush, PatternFit, Resource, presets, project, outline, pressure_profile}`.
- `project(&Path, &StrokeItem) -> Result<Vec<Path>, brush::Error>` is the one brush
  evaluator for display, ordinary expansion, and lower-level SVG/PDF adapters. Paths are
  closed, normalized through actual V1 `finish_compound`, with Join holes. Adapters may
  depend on pc-vecfx and `vector_design::exchange`; they must not depend on engine/UI.
- `Resource { brush, seed }.reference()` returns a versioned self-contained `BrushRef`;
  `Resource::resolve(&BrushRef)` validates and recovers it. Unknown references are errors.
  No fallback silently substitutes a preset. Native `.pcraft` already persists this opaque
  slot and the accompanying WidthProfile, with no format/schema change. This is the local
  resource mechanism while the shared resource table is absent. 00 may intern it later,
  retaining this decoder for saved references; do not replace it with an unversioned name.
- Geometry limits: 8192 input nodes/samples, 256 subpaths, 4096 output pieces, 131072 output
  nodes, bounded coordinates ±1e6, width 0.1..1000, resource IDs at most 4096 bytes. Flattening allocation is preflighted;
  overbudget geometry and zero-length strokes return errors rather than truncated success.
- Pressure profile t uses cumulative stabilized sample length; left/right are absolute
  pixel distances. The same `StrokeItem.profile` is stored for package 11's graph editor.
  Nib sweep inserts pressure breakpoints even if fitting reduces a line to two knots.
- `photocraft_engine::vector_packages::brushes::{Options, Capture, Prepared, TargetCapture}`.
  `Capture::begin(&Session, Options)`, `prepare(&Session, &Capture, &[pencil::fitting::Sample])`,
  `Prepared::commit(&mut Session)`; prepared `document: Arc<Document>` is detached.
- `vector.brush.commit {capture,samples:[{x,y,pressure}]}`: one journal/Session::edit.
- `vector.brush.preview {capture,samples:[{x,y,pressure}]}`: a non-journaled query,
  returning `{detached:true,layer,path,stroke}` without changing the active document.
  `vector.brush.apply {capture:{document,revision,layers},stroke:StrokeItem}`: all targets
  snapshotted/lock-checked, projected and cached before one edit.
  `vector.brush.expand {capture:{document,revision,layers}}`: source layers become groups
  of ordinary filled geometry; layer IDs, masks, opacity/blend and structural position survive.
  Target sets are limited to 64 layers and aggregate prepared caches to 512 MiB.
- `brushes::BrushProjection` implements the actual existing package 08
  `photocraft_vector::appearance::StrokeProjection`. Its `outline` calls the pure brush
  `outline` evaluator, uniting pieces before opacity/blend is applied. `refresh` uses the
  actual `CompiledAppearance::with_projection`, document patterns, bounded tile caches and
  existing `mirror_legacy`; gradient/pattern/along/across paint comes from that renderer.
  Already-integrated `shape_split::split_layer` uses this merged appearance cache.
- `brushes::projection(&Layer)` supplies ordinary layers for expansion, using the same
  merged outline. Solid paint expands exactly, including translucent overlapping scatter.
  Expanding advanced gradient/pattern paints currently fails explicitly because their paint
  frame needs a coordinate bake; display/apply can render them through package 08 already.
  Brushed arrows/dashes, corner/clip projection and unbrushed variable width remain explicit
  unsupported-provider errors, not stale pixels or erased metadata.

## Exact app hooks for 00/01

UI module is already `photocraft_ui_egui::vector_brush` (source `vector_packages/brushes.rs`).
01 adds `Tool::VectorBrush`, ID `vector-brush`, label `Vector Brush`, Vector family and an
existing brush icon alias. Add an app field `pub vector_brush: vector_brush::State`, default
initialized. Use existing tool preferences with serde(default); the State itself defaults
missing fields and serde-skips all gestures/caches. No second toolset store.

Each frame, before canvas input/rendering:

```rust
let selected = app.ui.tool == Tool::VectorBrush; // and Vector persona
app.vector_brush.frame(&app.session, &ctx, selected);
```

Before legacy tool dispatch, in `canvas::tool_event`, including automation:

```rust
if app.ui.tool == Tool::VectorBrush {
    if let Err(e) = app.vector_brush.pointer(&mut app.session, ev) {
        app.ui.status = e.to_string();
        app.ui.status_error = true;
    }
    return;
}
```

Route `tool_move` through this same branch and return before raster/pen hover handling.
In canvas_view's `freehand_tool` and `gesture_active_before`, include this tool and
`app.vector_brush.active()`, respectively. Keep the existing raw stylus sampling and
captured release outside the canvas. Do not dispatch the same event through both pointer
and `canvas_input_with_pressure` (the latter is the standalone kittest adapter).

At the start of `canvas::display_doc`, for the active document:

```rust
if app.ui.tool == Tool::VectorBrush
    && app.session.active_index() == Some(idx)
    && let Some(shown) = app.vector_brush.display_doc(&app.session)
{
    return shown;
}
```

Use this detached document in the normal GPU/CPU canvas and Navigator paths. Generation
keys use bit 61 to distinguish transient brush caches. Route the context bar to
`vector_brush::context_bar(ui, &mut app.vector_brush)`. It offers all four kinds plus Round,
width, pressure, fitting tolerance, rope stabilization, nib angle/roundness and scatter seed.
