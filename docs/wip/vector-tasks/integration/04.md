# Package 04 — Pen integration lane

Base: `2e8c671f`, branch `wip/vec-04-pen`. No shared router, registry, manifest,
catalogue or lockfile is modified. The engine slot already registers `pen::specs()`.
The new UI module is exercised by `tests/pen/main.rs` through a small real-event
egui_kittest host, not yet by the application's legacy Pen router.

## Exact registrations for 00 / 01

Create `pc-ui-egui/src/vector_packages.rs` (or extend the coordinator's aggregate):

```rust
pub mod pen;
```

In `pc-ui-egui/src/lib.rs`: `pub mod vector_packages;`.
In `UiState`: `pub vector_pen: crate::vector_packages::pen::State`, initialized
with `Default::default()`. State is transient. Persist only `vector_pen.options`
through the existing tool-options/preferences owner, using serde defaults; the
provided `Options` round-trip accepts `{}` from old settings. Existing Pen tool ID
is retained. Four context modes share that ID, not four separate tools. Controls:
`crate::vector_packages::pen::context(ui, &mut app.ui.vector_pen)`.

Replace the legacy Pen down/move/up/commit calls in `canvas.rs`, `vector_ui.rs`,
and Enter/Escape shortcut routes; do not keep both event consumers. Preserve the
existing Command/Control Direct Selection delegation. For plain Pen events:

```rust
use photocraft_geom::Point;
// Down, document-space snapped point `at`, current-frame modifiers:
let target = crate::vector_packages::pen::destination(
    &app.session, at, 6.0 / f64::from(app.current_zoom().max(0.01)),
    app.ui.tool_options.vector_mode == "shape", app.ui.vector_mask_target,
    app.ui.vector_pen.options.add_to_selected,
)?;
app.ui.vector_pen.down(&app.session, target, at, tolerance, mods, fill, stroke)?;
// Move (also modifier changes while held):
app.ui.vector_pen.motion(&app.session, at, mods)?;
// Up: sample final position/modifiers, then release (even outside the canvas):
app.ui.vector_pen.motion(&app.session, at, mods)?;
app.ui.vector_pen.up(&mut app.session)?;
// Enter, including the existing Ctrl+Enter path-to-selection route:
app.ui.vector_pen.enter(&mut app.session)?;
// Escape/focus loss/PointerGone/modal/tool/persona change:
app.ui.vector_pen.cancel();
// Per frame before painting/input, detect document/revision changes:
app.ui.vector_pen.synchronize(&app.session, pen_enabled);
```

`fill: Option<photocraft_doc::Fill>` and `stroke: Option<ShapeStroke>` come from the
existing context-bar foreground/background settings. New paths use these captured
values; continued/appended curves retain the existing layer's paint. Engine accepts
open filled curves too, as the current document schema does. Errors go through the
app's normal status/error route. `tolerance` is in document pixels. The optional
isolated-host `pen::input(...)` shows event ordering; the full app should reuse its
existing canvas capture/router rather than consume raw events a second time.

Canvas preview: when `vector_pen.preview` exists, pass that detached Document to
the **normal** CPU/GPU document compositor and use `vector_pen.generation` in the
existing transient preview key; normal caches are bounds-limited pc-vector caches.
Do not publish it to `Session`, render an egui convex fill, or journal any pointer
update. On cancel/release select the ordinary document again and invalidate the
preview key. While `vector_pen.gesture` exists, suppress the legacy PenPath and
original-target Pen overlays so a reshaped first segment has no ghost outline.
Keep the Direct Selection delegation's own overlays. Paint controls after the canvas with:

```rust
crate::vector_packages::pen::paint_overlay(
    &app.ui.vector_pen, painter,
    |p| xf.to_screen(p.x as f32, p.y as f32),
);
```

07 snapping: its implementation lane was read **read-only** in `../vec-07-snapping`.
Once merged, use `photocraft_engine::vector_packages::snapping::query::Cache`;
build once per captured revision with `Cache::build(doc, revision, Exclusions,
Option<Geometry>)`, and call `Cache::point([x,y], &Settings, View, Option<Angle>,
bypass)` each press/motion. Feed `SnapResult.point` to `down/motion` and paint
`SnapResult.guides` via the 07 overlay. `Gesture::constraint_origin()` supplies the
held node or current open endpoint for the 45-degree ray. Exclude the edited layer
or work path using 07's Exclusions; Ctrl/Cmd bypass comes from current modifiers.
Use `Angle { origin: [origin.x, origin.y], step: std::f64::consts::FRAC_PI_4,
offset: 0.0 }` (radians) and `View { zoom, pixels_per_point }`. Its slot is
still empty in this base, so no new dependency, guessed stub or duplicate snap
solver is introduced here. The same origin/angle constraint must apply before
preview and release; do not snap only on commit.

Line mode click-drag creates a straight segment and self-terminates on release;
two clicks are also supported; Line always starts a new two-node subpath. Shape addition
requires exactly one selected curve and rejects a raster selection. Pen/Smart/Polygon
endpoint continuation is chosen before new-layer drawing, supports either end of any open subpath, and preserves
existing knots/handles without reversing the path. A press elsewhere with Add enabled
starts another subpath in the same object. Masks and the work path use the same guarded
command. One finished curve means one `path.penCommit`, one Session edit and one journal
entry. Intermediate node releases remain detached. Escape cancels rather than finishes,
as the task's newer acceptance explicitly requires.

## Full-app acceptance registration — required, still pending wiring

Add to `pc-ui-egui/tests/gpu/main.rs` (00 alone owns this aggregate):

```rust
#[path = "../pen/app_acceptance.rs"]
mod pen_app_acceptance;
```

It uses actual `PhotocraftApp` canvas pointer events, GPU paint callbacks, curved and
closed previews, release, Undo, cancellation and Line mode at 1x/HiDPI. It strictly
selects RTX 5090 / discrete / Vulkan / Rgba32Float. Its actual opaque canvas interior
preview-to-release max difference gate is one byte. Native complete premultiplied
curve-edge/cache parity is covered by the engine's separate strict GPU test.
This source intentionally relies on `UiState::vector_pen`: it must compile and run
after wiring, and cannot count as a passed gate beforehand.

Focused commands after wiring:

```sh
PATH="$HOME/.cargo/bin:$PATH" CARGO_BUILD_JOBS=3 cargo +1.98.1 test --offline -p photocraft-ui-egui --test gpu pen_app_gpu -- --nocapture
```

Performance: no interactive speed claim is made; release real-app measurements await
the same app hooks. Do not substitute isolated-widget or renderer timings.
