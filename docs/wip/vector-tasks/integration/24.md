## Public interfaces

- `photocraft_affinity::import(bytes: &[u8], options: &ImportOptions) -> Result<ImportedScene, Error>`.
- `import_with(bytes, options, Option<&mut photocraft_text::TextEngine>, &AtomicBool)`:
  optional caller-provided fonts; no scan, file/network resolution or linked resources.
- `import_preview(bytes, options, &AtomicBool, reason: &str)`: explicit flattened
  thumbnail at its own dimensions. **Open-only recovery of Unsupported**. Do not
  recover Malformed/CRC, Limit or Cancelled; do not use thumbnail recovery for Place.
- Native container/stream/model APIs remain available for bounded inspection;
  `Archive::open_with` and `model::read_with` accept cancellation. Extended Limits
  bound objects, decoded values, nesting, graph geometry and pixels.

Native geometry is stored at the source DPI and converted to `options.dpi` once,
including text transforms, stroke widths, images and page origins. Default adapter
DPI is 72. Page indices select **spreads**, zero-based; default is the first spread,
explicit selections are arranged side-by-side and retain separate page clipping.
Duplicate/out-of-range selections fail. Returned units are Pixels. No unit is guessed
from proprietary metadata. Profiles, arbitrary gradient affine geometry, unavailable
fonts, unknown effects/records and unsupported pixel representations warn explicitly.
The existing package 08 appearance renderer prepares caches and retains stroke order.
Ordinary fill/foreground-stroke shapes omit redundant appearance metadata, preserving
the established `shape.applyPaths` edit route. Explicit nonlegacy paint order retains
appearance metadata and requires package 08's enhanced path-edit integration.

Engine specs already register through the compiled affinity slot:

- `file.affinity.import {bytes:[u8], dpi?:72, name?:"Affinity"}` — new native document,
  explicit unsupported-layout preview recovery, no source save path.
- `file.affinity.place {document:u64, revision:u64, above:id|null, bytes:[u8],
  name?:"Affinity", offset?:[i32,i32]}` — one engine command/edit/journal publication.
- `capture(&Session, Vec<u8>) -> Result<Place>`, `check`, `decode`, `preview` mirror
  established SVG captured placement. ID/revision/anchor and inherited all/pixel locks
  are revalidated. All prepared layers, IDs, paths, appearance numbers, caches and depth
  are validated before any publication.
- `decode_with(&Session, &Place, &AtomicBool)` supplies cancellation during detached
  preparation. A worker can instead call the reader with the captured destination
  DPI and return a scene; preview/commit checks remain required.
- `read_open(&[u8], dpi, &AtomicBool)` decodes a detached scene on a file worker,
  following Unsupported-only recovery. `open_bytes(&mut Session, &[u8], dpi, name)`
  is the normal UI byte boundary, avoiding expansion of binary input into JSON arrays.
- `commit(&mut Session, &Place, &ImportedScene) -> Result<LayerId>` publishes a decoded
  scene through **one Session::edit**. This is the UI release path, avoiding a second
  parse/render. It produces one undo/revision entry. `Session::execute` wraps the same
  operation for automation and supplies the journal entry there.

### Ordinary file call sites

The concrete shared call sites at this base are `pc-engine/src/file_cmds.rs`
(`open_bytes_as`, `place_bytes`), `pc-engine/src/jobs.rs` (`Session::start_open`),
`pc-ui-egui/src/lib.rs` (`PhotocraftApp::open_bytes`), `file_open.rs` (`open_file`,
`place_bytes`, `place_next_dropped`) and `jobs_ui.rs` (`finish_open`). Supply the
same magic-first reader path through 00's common routing.

At the engine file/job decode boundary, an Affinity branch produces the existing
`photocraft_io::ImportResult`:

```rust
let scene = crate::vector_packages::affinity::read_open(bytes, 72., cancel)?;
let (document, vector_warnings) = crate::vector_packages::affinity::document(scene, name);
let warnings = vector_warnings.iter().map(|w| w.message.clone()).collect();
let result = photocraft_io::ImportResult { document, warnings };
// Keep structured vector_warnings for warning_controls.
// Apply with open_document(result.document, None), returning nativeImport=true.
```

`JobCtx` currently exposes `cancelled()` but not its atomic. Its owner can add this
accessor to the existing impl, sharing the existing flag:

```rust
pub fn cancellation_flag(&self) -> &std::sync::atomic::AtomicBool {
    &self.shared.cancel
}
```

Use `ctx.cancellation_flag()` in that branch; `read_open` preserves
`EngineError::Cancelled`. Carry `nativeImport=true` through `jobs_ui::finish_open`
and the synchronous `file_open::open_file` route. For native imports, replace
`opened_from(path)` with only `push_recent(path)` and
`filmstrip_ui::follow_file(app, path)`. An empty engine save path is insufficient
if these completion hooks subsequently restore the proprietary source path.

For engine Place/drop/linked routes, before smart-object/raster decoding:

```rust
if photocraft_affinity::is_affinity(&bytes) {
    let mut request = crate::vector_packages::affinity::capture(session, bytes)?;
    request.name = name.into();
    let scene = crate::vector_packages::affinity::decode(session, &request)?;
    let id = crate::vector_packages::affinity::commit(session, &request, &scene)?;
    return Ok(serde_json::json!({"layer": id.0, "warnings": scene.warnings,
        "nativeImport": true}));
}
```

Interactive staging uses `State::set_source` then `stage` and the canvas hooks above.
For a large-file worker, capture request and DPI on Begin, prepare using
`photocraft_affinity::import_with` on the worker, then call `preview`/`commit` with
the same request after completion. Cancellation must discard the result; never
recapture a newer revision at release. Affinity Place Linked uses the embedded
editable path and reports that no linked proprietary writeback is available.
