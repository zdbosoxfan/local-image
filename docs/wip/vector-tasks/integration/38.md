## Native data and transaction hooks (00)

Add to `pc-doc::Document` and initialize in `Document::new`:

```rust
pub graphic_styles: Vec<photocraft_doc::vector_design::styles::GraphicStyle>, // Vec::new()
```

In pc-doc itself use `vector_design::styles::GraphicStyle` rather than the external crate
prefix. Add to `VectorData`, include it in `VectorData::is_empty`:

```rust
#[serde(default, skip_serializing_if = "Option::is_none")]
pub graphic_style: Option<styles::StyleLink>,
// is_empty: && self.graphic_style.is_none()
```

In `pc-format/src/manifest.rs::DocM`:

```rust
#[serde(default, skip_serializing_if = "Vec::is_empty")]
pub graphic_styles: Vec<photocraft_doc::vector_design::styles::GraphicStyle>,
```

In `convert.rs::doc_m` set `graphic_styles: d.graphic_styles.clone()`. In the reconstructed
`Document` set `graphic_styles: m.graphic_styles.clone()`. The existing VectorData mirror
already serializes the per-layer link, including symbol template layers. Style IDs are a
separate namespace: do not remap them when remapping LayerIds; the link's baseline contains
no layer IDs. Old documents omit the list/link and load with empty/None. Do not claim style
persistence by hiding it in XMP: the XMP provider in our tests is explicitly a test fixture.

Install this provider once alongside the other package hooks (code uses the new fields):

```rust
use photocraft_engine::{Result, vector_packages::styles::{self, Hooks, Store}};
use photocraft_doc::{Document, Layer, LayerContent};
fn read_graphic_styles(doc: &Document) -> Result<Store> {
    let mut store = Store { graphic_styles: doc.graphic_styles.clone(), ..Default::default() };
    fn collect(layers: &[Layer], store: &mut Store) {
        for layer in layers {
            if let Some(link) = &layer.vector.graphic_style {
                store.links.insert(layer.id, link.clone());
            }
            if let LayerContent::Group(g) = &layer.content { collect(&g.children, store); }
        }
    }
    collect(&doc.layers, &mut store);
    Ok(store)
}
fn write_graphic_styles(doc: &mut Document, store: &Store) -> Result<()> {
    doc.graphic_styles = store.graphic_styles.clone();
    fn assign(layers: &mut [Layer], store: &Store) {
        for layer in layers {
            layer.vector.graphic_style = store.links.get(&layer.id).cloned();
            if let LayerContent::Group(g) = &mut layer.content { assign(&mut g.children, store); }
        }
    }
    assign(&mut doc.layers, store);
    Ok(())
}
styles::install_hooks(Hooks { read: read_graphic_styles, write: write_graphic_styles })
    .map_err(|_| "graphic style hooks already installed")?;
```

The provider above targets the editable root tree. Symbol-master layers persist their
VectorData links through the normal native mirror, but editing a master through the symbol
provider must handle its own style link: current Document::layer does not target template
LayerIds. Do not silently include templates as root query/appearance targets.

Inside `Session::edit`, after applying the caller's edit and colour restriction, before
publishing `st.doc`, call `vector_packages::styles::prune_links(&mut doc)?`. It removes stale
links in the same history state, preserves freshly applied/redefined in-sync links, and is
an inexpensive no-op when hooks are absent. The query and redefine also independently
check sync, including every character/paragraph run, so stale links cannot overwrite a
local edit even if an integration edit path forgets this hook.

Native validation: reject >1024 definitions, zero/duplicate IDs, duplicate/empty names,
dangling links and excessive metadata under the existing bounded manifest policy. Use the
same validation during loading and before saving; engine edits validate names, definitions,
inputs and a 64 MiB serialized metadata cap before cloning/preparing. Never render
malformed imported style values before validation. Add a shared provider test that calls:

```rust
vector_packages::styles::native_acceptance::acceptance(Hooks {
    read: read_graphic_styles, write: write_graphic_styles,
});
```

This compiled fixture asserts actual native list/link persistence, old-v1 defaults, undo,
redo and three linked updates with an unchanged local edit. Its isolated ignored wrapper
requires a real installed provider and is **not** counted as a passed gate.

## Engine command registration (00)

Append to `vector_packages::specs()`:

```rust
out.extend(styles::specs());
```

IDs: `vector.styles.edit` (journal=true), `vector.styles.query` and
`vector.styles.preview` (journal=false). `commit` automatically uses Session::execute once
registered; its pre-registration path uses the authorized one-Session::edit boundary.
The command runner calls `commit_with_hooks` directly, avoiding recursion/double journaling.
Queries/previews never call Session::edit. `commit_with_hooks` is the explicit-provider core
used by fixture tests; production UI calls the registered route after integration.

```rust
styles::capture(&Session, Vec<LayerId>, Operation) -> Result<Request>
// Request {document:u64, revision:u64, targets:Vec<LayerId>, operation:Operation}
styles::sample(&Document, LayerId, byte:Option<usize>) -> Result<Sample>
styles::color_at(&Document, LayerId, x:f64, y:f64, stroke:bool) -> Result<Color>
styles::preview(&Session, &Request) -> Result<Preview>
styles::commit(&mut Session, &Request) -> Result<()>
styles::refresh(&Document, &mut Layer) -> Result<()> // owning type/geometry edit or reload
styles::same_style(&Document, &Store, reference:LayerId) -> Result<Vec<LayerId>>
styles::style_key(&Layer, Option<&StyleLink>) -> Result<Option<String>>
```

Operation serde tags: `copy`, `color`, `apply`, `new`, `redefine`, `rename`, `duplicate`,
`delete`, `breakLink`, `installStarters`. Apply/New/Redefine use stable StyleId (serialized
u64). Empty, whitespace/control/duplicate names are rejected. Apply replaces and links;
add appends only fill/stroke/FX and unlinks, retaining the target's transparency/object/text
settings. Delete keeps appearances and removes links. Starter import is explicit/idempotent;
old documents remain empty. No new-art defaults or proprietary library import is claimed.

For 32, install/merge its Readers with:

```rust
graphic_style: Some(|layer| styles::style_key(layer, layer.vector.graphic_style.as_ref())),
```

Absent/local-edit links return None, never all match on absence. Preserve the existing
appearance/rotation/symbol readers when installing this once-only composite provider.

| stylePicker | Style Picker | none | original dropper over style swatch | Eyedropper flyout |

01 may alias the existing Eyedropper enum/toolbar entry in Vector; do not duplicate I in the
Pixel persona. On activation call `vector_eyedropper::activate(app, ctx, Some(Tool::Eyedropper))`
or StylePicker; None deactivates. Before ordinary tool input/drawing:

```rust
vector_eyedropper::frame(app, ctx); // EVERY frame, including modal/module/tool changes
// In the active canvas:
if vector_eyedropper::route(app, ui, idx, &xf, content_rect, scoped_hit, scoped_marquee) {
    // consume ordinary canvas tool input; still draw canvas
}
vector_eyedropper::context_bar(app, ui); // active tool's context bar only
// before ordinary display_doc providers, for active document only:
vector_eyedropper::display_doc(app, idx, ctx); // Option<(Arc<Document>, generation)>
```

`scoped_hit: Fn(&Document, Point) -> Result<Option<Hit>>`, where
`Hit {layer, byte:Option<usize>, stroke:bool}`. Reuse 32/37's authoritative editable isolation,
visibility and hit predicates. Include raster/placed-image hits using rendered document-space
surfaces; for text use pc-text's transformed layout hit test to supply the exact UTF-8 byte.
For shapes use the existing exact path/nearest hit API, distinguishing stroke hits.
`scoped_marquee: Fn(&Document, Point, Point) -> Result<Vec<LayerId>>` uses the same scope,
returns unique editable targets (up to 256); exclude group descendants when targeting their
container, and choose leaf shape/text targets when applying fill/stroke. No caller may publish
partial target sets after a validation error.

Click samples + applies to captured selection; Alt applies the loaded sample to the clicked
object (first selected object if not loaded); Shift changes only the top active fill/stroke
paint from the sampled colour, retaining other items/options; Alt+Shift appends the clicked
appearance onto the selection. Style Picker loads once, applies selected categories by click
or marquee, and Unload discards it. Pick/Apply masks intersect, so unchecked picked attributes
cannot be applied later. No selection loads the appearance without editing the document.

Document/revision/selection/modals/focus/persona/module/tool changes cancel capture and
preview. Release validates again and produces one edit; Escape produces none. Preview is
sent through the SAME GPU canvas `display_doc` route and generation key used by other tools;
do not flatten it into a separate preview widget in the actual app.

Dock/menu entry Window > Graphic Styles calls `graphic_styles::panel(app, ui)`. Every app
frame calls `graphic_styles::frame(app, ctx)`, and display_doc considers
`graphic_styles::display_doc(app, idx, ctx)` for detached Apply previews. Create/apply/redefine,
rename/duplicate/delete, break link and starter library are actual buttons; Apply captures
Alt at press. Errors go to the existing status path. Wire command/panel labels from 38.tsv.

In ordinary type/geometry edit and reload projection, if a layer has explicit appearance,
call `styles::refresh(&snapshot, &mut layer)` after changing its native text/path and before
publishing. This keeps style paint authoritative after a later character edit without a
second history step. Use the shared preparation budget when refreshing a batch.

Rendering uses 08 CompiledAppearance and the installed 11/17 width/brush projections;
shape caches first use 13's `corners::project_shape` without replacing the persisted base
path or corner metadata. When merging the shared display projection, route combined
corners/appearance through this paint preparation rather than 13's legacy rejection of
appearance; avoid replacing a freshly painted cache with its legacy single-fill cache.
12's path-text project/rasterize feeds native text or painted glyph outlines. Ordinary
character/paragraph-only changes retain pc-text's multicolour runs, and a single normal solid
fill uses native text rendering (including faux bold). Decorated glyph stacks use
pc-text's Create Work Path outlines (its documented faux-bold omission/warped-curve
approximation also applies here); glyphs/decorations remain editable text. Groups with their
own fill/stroke require 08's group projection: current shape/text-only paint transfer rejects
them explicitly. Raster/group opacity/FX/object-only transfers remain supported.
