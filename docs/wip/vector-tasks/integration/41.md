# Package 41 — vector liquify and Puppet Warp integration

Continue the existing vector foundation; do not replace the raster Liquify/Puppet Warp routers.
This branch compiles the owned modules with append-only module declarations, as authorized by
CODEX-TASK's REGISTRATION override. Shared command aggregation, tool registry, menus, canvas
routing, catalogs and attribution regeneration remain in 00/01/46's serial integration lane.
The ordinary kittest host dispatches this package's supplied CommandSpecs directly; it proves
owned gestures and engine transactions, not full-app runtime registration or GPU acceptance.

## 00: command slot (required before UI activation)

`pc-engine/src/vector_packages.rs` already contains `pub mod distort_tools;`. Append inside its
`specs()` aggregate:

```rust
out.extend(distort_tools::specs());
```

Commands supplied by the owned `distort_tools.rs`:

| Command | journal | Parameters |
| --- | --- | --- |
| `object.liquify` | true | `LiquifyRequest { capture, options, samples, seed }` |
| `object.liquify.preview` | false | same request; returns detached paths |
| `object.puppetWarp` | true | `PuppetRequest { capture, options, pins }` |
| `object.puppetWarp.preview` | false | same request; returns detached paths |
| `object.puppetWarp.info` | false | `{ capture, options }`; automatic pins and mesh counts |
| `object.distort.convert` | true | `Capture`; one confirmed conversion transaction |

`Capture { document:u64, revision:u64, layers:Vec<LayerId>, automatic:bool=false }` names the entire target set.
Numeric inputs are finite and bounded. `Sample { at:[f64;2], pressure:f64=1 }` uses document
pixels, pressure 0..1. Options use serde defaults; intensity 0..1, width/height 0.5..10000,
angle in degrees, detail 1..10, simplify 0..100, rate -180..180, complexity 0..15, horizontal
and vertical 0..1. `use_pressure` multiplies intensity by pressure. `node_budget` is global
across a path's subpaths (4..20000), not a per-subpath limit. Stroke work is capped at 4096
samples and fewer than 2048 dabs; excessive work returns an error, never a truncated commit.
Puppet pins use `rest`, `at`, and an optional `angle` in radians. Mesh resolution 4..32,
expand 0..1000 document pixels, refit tolerance 0.001..10, at most 64 pins.

No arbitrary prepared path/cache is accepted from automation: commit evaluates captured
current geometry again, preflights every target and the aggregate cache allocation, then
publishes one `Session::edit`. Previews never edit Session. Bounds-limited appearance caches
use the existing 08 renderer and 11/17 projection via 36's `expand::Projection`. Corners are
evaluated before deformation and cleared only on changed paths; paint, clipping and other
layer attributes remain attached. No-op geometry leaves native/PSD metadata untouched.

## 00/01/46: transient UI state, input and preview

The compiled UI module is `photocraft_ui_egui::distort_tools`. Its `AppBridge` is kept in
egui's transient context, so no shared UiState/Document field is required. Activate it with:

```rust
distort_tools::activate(app, ctx, Some(distort_tools::Tool::Warp));
// Other Tool variants below. None disables it and cancels its capture.
```

At every frame before tool dispatch, call `distort_tools::frame(app, ctx)`. Tool, persona,
module, focus, document and revision changes cancel captured input and detached preview.
Call the existing stylus update before the route so `app.stylus.pressure()` includes the
pc-tablet feed and existing preference/pressure curve.

Before ordinary canvas tool input:

```rust
let consumed = distort_tools::route(app, ui, idx, &xf, canvas_rect);
// A true result owns the tool route; do not dispatch the ordinary tool afterwards.
```

Route the context bar through the same transient bridge:

```rust
let mut b = distort_tools::bridge(ctx);
distort_tools::context(ui, &mut b.state);
if let Err(e) = distort_tools::conversion_prompt(ui, &mut b.state, &mut app.session) {
    app.ui.status = e.to_string();
    app.ui.status_error = true;
}
distort_tools::save_bridge(ctx, b);
```

For display use `distort_tools::display_doc(app, idx, ctx) -> Option<(Arc<Document>,u64)>`
in the existing detached-preview document selection path. Its second element is a transient
preview generation, **not** a saved document revision. Feed it into CPU and GPU canvas cache
keys. The display document must reach the same normal compositor and scaled vector view
used on release; an overlay of outline strokes does not constitute live filled preview.
The package's `paint_overlay` paints only brush/pins/mesh feedback. `ui.view.extras=false`
must hide those overlays for release pixel parity.

Lower-level signatures for other hosts:

- `State::down(&Session, [f64;2], Modifiers, pressure:f64, tolerance:f64)`
- `State::motion(&Session, [f64;2], Modifiers, pressure:f64)`
- `input(&mut State, &mut Session, &egui::Context, Rect, to_doc, enabled, pressure, tolerance)`
- `context(&mut egui::Ui, &mut State)` and `conversion_prompt(&mut egui::Ui, &mut State, &mut Session)`
- `State::cancel()` restores an in-flight pin drag; `deactivate()` also drops pins/rig.

With no selected layers the brush captures all visible unlocked ordinary shape paths, then
only changes paths under its dabs, including paths met later in the stroke. Selected ordinary
groups resolve to shape children. Puppet Warp requires a vector selection. Selected raster/live groups require existing expansion.
Live shapes/text produce an explicit conversion prompt (unselected live shapes outside the brush are preserved); confirmation is a separate undoable
conversion, followed by a fresh stroke. Conversion uses the existing shared shape/corner
projection and type-to-shape commands. Existing type converter fidelity remains the type
owner's responsibility. Pins are transient, added/deleted without path edits; each pin drag
or rotation is one destructive path edit on release. On release the committed geometry and
current pins become the next rest pose. Undo/revision changes discard the transient rig.
If persistent pins/rest-pose restoration across save/undo is desired later, 00 must own its
native-model storage; no unowned data fields were invented here.

`LiquifyGesture::conversion_layers` names the exact live shapes changed by its last attempted
dab prefix. Prompts use this list, including shapes crossed between pointer samples when the
ending brush has already left their bounds. Conversion preflights inherited locks on every
group child and rejects repeated leaves before editing.

All belong to the Vector persona, distinct IDs from raster tools:

Liquify command. Supply these tools to All Tools and Illustration; preserve Pixel custom sets.
Persist `distort_tools::Options` through the existing owner-managed prefs field with
`#[serde(default)]`; no preference store was added in this package. Catalog strings are in
`../i18n/41.tsv`.

## Integrated gates and attribution

Two compiled, ignored **full PhotocraftApp** offscreen GPU gates are in
`pc-ui-egui/src/vector_packages/distort_tools/app_gpu.rs`. They require all runtime hooks
above, fail on missing hooks, and require RTX 5090 / Vulkan / DiscreteGpu / Rgba32Float /
float canvas formats. One checks all eight tools' live pixels, preview/release max diff
<=1/255, one Session journal/history edit, undo and Escape; the other measures release
pointer+app+GPU/readback p95 <=16.667 ms on 2000 nodes for each tool, reporting first and
release costs and adapter identity. They are intentionally not run under the final speed
rules. Once wired, 00 runs them in release and records actual results; do not infer GPU
acceptance from isolated host tests or call this package integrated-complete before that.

Append the exact rows from `41-PORTS.tsv` to docs/PORTS.md and regenerate attribution through
the existing xtask lane. Existing VectorCraft MIT/Apache/NOTICE files and curated attribution
already exist. Source hashes, references and fixture parameters are in `41-SOURCES.md`.
