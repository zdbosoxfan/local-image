## Engine commands and gestures

Edit specs (journal=true): `livePaint.make`, `.paint`, `.options`, `.merge`, `.expand`,
`.release`, `vector.floodFill`. Queries (journal=false): `livePaint.preview`, `.info`,
`.sample`, `.select`. Capture is `{document:u64,revision:u64,layers:[LayerId]}`; edit/preview
request is `{capture,action}`. `Action` is internally tagged with snake_case `kind`:

```rust
Make { gap: Gap } // none/small/medium/large, document pixels 0/4/8/16
Paint { points: Vec<[f64;2]>, paint: Option<Fill>, edges: bool,
        width: f32, tolerance: f64 }
Flood { points: Vec<[f64;2]>, paint: Fill,
        options: FloodOptions { insertion: Inside|InBetween,
            mode: AddOnTop|SmartRefill|Knockout, visible_boundaries: bool } }
Options { gap: Gap }
Merge
Expand
Release
```

`Gesture::begin(&Session,&[LayerId]) -> Result<Gesture>` captures and validates targets;
an empty list resolves selection or all eligible shapes. `Gesture::preview` reuses its
captured Arc graph and returns detached `Preview {model,display,layers,changed}`.
`Gesture::commit` executes the action's engine command once. Commit rechecks staleness,
all locks/targets and cache budget before one Session::edit. Failed/unchanged preparation
does not create history. `Session::execute` owns the command journal, including a no-op
edit command record. Face drags use curve/line intersections; edge drags use bounded
tolerance-aware samples. Queries validate the capture and never journal or edit.

Flood Fill inserts painted regions inside ordinary source wrappers or immediately above
the source and below its next sibling. It separates the remainder fill from the original
stroke, keeps the source's group opacity/effects once, and carries existing fill stacks
for transparent Add/Smart fills. Knockout/opaque fills replace that face's fill stack.
Smart skips duplicate fills. Sources' outside fills and strokes remain visible. Visible
Boundaries extends across geometrically adjacent regions with matching visible fills,
then merges faces per insertion target. Different source wrappers retain their individual
layer semantics; a whole same-colour area can therefore be multiple plain output shapes.
