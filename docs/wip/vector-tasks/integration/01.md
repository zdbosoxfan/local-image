# Package 01 integration lane — persona

Owned implementation is `toolsets_ui::persona` (registered through the owned toolsets UI module).
Do not create a second persona/toolset store. `session.prefs().toolbar.persona` is authoritative;
`active_set` remains Pixel's original id and `vector_set` is Vector's independent id.
Existing tools are usable in Vector now; feature ids below are reserved and await their providers.
V1 is absent at branch HEAD `2e8c671f`; Geometry controls use its real commands and remain disabled.
No standalone boolean implementation is supplied.

## Shared frame/router fragments (00-owned files)

In `PhotocraftApp::ui`, **after `shortcuts::handle` and before canvas input**, always call:

```rust
crate::toolsets_ui::persona::frame(self, ctx);
```

This also handles hidden chrome, hidden toolbar, and commands received through automation.
The owned options bar and toolbar call it already; repeated calls are idempotent.
For immediate tool changes, replace direct tool assignments in shortcut/control/canvas menus with:

```rust
crate::toolsets_ui::persona::select_tool(app, ctx, tool);
```

Persona menu handlers currently enter via the existing `toolsets_ui::run` dispatcher and update
engine prefs. They synchronize before the next canvas frame. The global frame call above makes
cancellation occur before any input can commit a gesture.
Register the following menu-catalog defaults for shortcut discovery/customization (then remove
matching dynamic persona menu rows in `toolsets_ui::menu_items` to avoid duplicate entries):

```rust
(&["View", "Persona"], "Pixel persona", Some("Cmd+Shift+1"), "view.persona.pixel"),
(&["View", "Persona"], "Vector persona", Some("Cmd+Shift+2"), "view.persona.vector"),
```

No existing `Cmd+Shift+1/2` binding was found in the baseline menu catalog. The owned engine
toolset specs register `view.persona.pixel/vector` with those defaults, so the existing common
shortcut dispatcher and user overrides work now (including hidden chrome). There is no second
manual key consumer. The frame helper synchronizes/cancels after command dispatch.

## Feature hook contract

`persona::FeatureHooks` supplies these function pointers:

```rust
pointer: fn(&mut PhotocraftApp, canvas::ToolEvent, egui::Modifiers) -> bool,
context: fn(&mut PhotocraftApp, &mut egui::Ui) -> bool,
overlay: fn(&PhotocraftApp, &egui::Painter, &canvas::ViewXform),
cancel: fn(&mut PhotocraftApp),
```

00 resolves the hook for `VECTOR_TOOLS[i].package` through its serial feature router. Invoke
cancel for the previous feature on tool/persona switch, Escape, focus loss and stale target.
Package-specific runtime/prefs fields remain owned by their providers. A missing hook consumes
input for its tool without a document edit and disables that toolbar entry with the reason above.
Photographer context actions are Geometry and `file.svg.place` (13's provider), not pseudo-tools.

## Capture/preflight fragments

`persona::GestureTarget::capture(app)` captures document id/revision and all selected layer ids;
`is_current(app)` checks all of them. Store it on pointer-down **before** preview in the shared
canvas/pen router; reject release if it no longer matches. `persona::cancel` drops Pen, direct
selection drag, live raster stroke, Move preview/capture, lasso, crop drag, gradient preview,
brush resize and flyouts. Each later feature must drop its own preview through the hook.
The owned frame observer guards cross-frame legacy gestures, but same-frame automation releases
require that router capture check. Do not claim this unregistered fragment has passed acceptance.

Add this field to `UiState` and initialize with `Default::default()`:

```rust
#[serde(skip)]
pub persona_pointer: crate::toolsets_ui::persona::PointerGuard,
```

At the start of `canvas::tool_event` (before dispatching any preview/edit), use:

```rust
let mut guard = std::mem::take(&mut app.ui.persona_pointer);
let intercepted = guard.intercept(app, ev);
app.ui.persona_pointer = guard;
if intercepted { return; }
```

At persona/tool cancellation, Escape, focus loss and gesture abandonment, call
`app.ui.persona_pointer.clear()`. Also clear before dispatching a completed Pen keyboard commit;
the shared event guard recognizes a fresh Pen on the next Down after commit. The owned standalone
`PointerGuard` test covers a same-frame document swap/release and nonfinite/bounded pointer input.
This tested API is still awaiting the shared router registration above.

For control inspection expose `"persona": app.session.prefs().toolbar.persona`; for `ui.set`
with a `persona` value, call `app.run("persona.select", json!({"persona": value}))` and the
frame helper before the next canvas input. Do not add a second persisted UiState persona field.


The existing rasterize prompt already performs the correct type/shape rasterization and asks
before canvas input. Add document/revision capture to its open/confirm to cover delayed answers:
At open, before pushing the dialog, call:

```rust
if let Err(error) = crate::toolsets_ui::persona::capture_rasterize_prompt(app, &mut f) {
    app.ui.status = error;
    app.ui.status_error = true;
    return 0;
}
```

The existing `open` returns `u64`; zero is unallocated (`UiState::next_id` starts at one) and
indicates no dialog was opened. Its actual canvas caller already has a document and ignores
the returned id. At the very start of `confirm`, before `app.run`, call:

```rust
crate::toolsets_ui::persona::validate_rasterize_prompt(app, f)?;
```

This captures doc/revision/active and every selected target id; confirmation rejects any mismatch.
The new persona module does not edit that separately owned prompt file. Keep shape.create's
existing new-layer placement above the active pixel layer; Vector enters Shape mode and Pixel's
prior Pen mode is restored.

In the 00-owned `edit.toolbar` reset handler, reset the active family's set through
`toolbar.select_set(&builtins_for(toolbar.persona)[0])`; do not overwrite Pixel's `active_set`
while Vector is selected.

## Required acceptance after V1 merges

Tests are registered under the owned persona module, avoiding edits to aggregate test files:

```
CARGO_BUILD_JOBS=3 cargo +1.98.1 test --offline -p photocraft-ui-egui persona_
CARGO_BUILD_JOBS=3 cargo +1.98.1 test --offline -p photocraft-ui-egui persona_geometry_actual_add -- --ignored --nocapture
CARGO_BUILD_JOBS=3 cargo +1.98.1 test --offline -p photocraft-ui-egui persona_gpu_ -- --ignored --nocapture --test-threads=1
```

The GPU tests create only offscreen surfaces and require RTX 5090/Vulkan/discrete, Rgba32Float
composition and Rgba16Float canvas. Software/no adapter is a failure. Geometry and GPU union
gates intentionally fail when V1 is absent; ignored/missing dependencies do not count as passes.
Full app capture uses actual UI clicks/held pointer/preview/release, and premultiplied max diff
<=1/255. Synthetic rectangle union area is independently 7200 px; Undo restores both source
layers and their selection.
