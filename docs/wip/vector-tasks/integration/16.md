# Package 16 integration lane

Owned engine slots are already compiled by vector_packages; do not register duplicate
commands. The branch has no UI vector_packages aggregate yet. Package 00 merges the
following exact fragments into its current aggregate/router/catalog. Shared files,
Tool registry, manifests/lock and language catalogs remain untouched in the worktree.

The production owned UI hooks are layout/app_hooks.rs. layout16.rs is an automatically
discovered standalone egui interaction binary. Register layout/app_acceptance.rs only
with the production app hooks. It uses the full PhotocraftApp, actual pointer input,
GPU canvas and an offscreen RTX adapter. The disposable tree under
`target/layout16-registration/worktree` exercises these exact hooks without editing
shared source files. Test commands/results are recorded in the package report.

Until 01 allocates dedicated Tool variants, the panel selects existing PathSelection
only while a package-owned layout mode is active. The event hook then consumes those
events; with layout mode None it leaves PathSelection unchanged. Move and pixel Crop
are never intercepted. 01 should alias dedicated VectorArtboard/PointTransform/
VectorCrop registry entries to the corresponding owned Tool modes, call switch(),
and update the hook enablement check to those variants. No second Move state exists.

The display wrapper must run AFTER the existing display-doc preview selection. This
preserves Move/gradient/effect precedence and projects clips in their detached trees.
The crop wrapper adds a separate vector mask outside the original content/masks,
which package 09 already scales and the CPU/GPU compositors already evaluate. No
renderer core patch is required; vector.clip is cleared only in this transient
projection. File/export consumers need the same projection through their existing
vector_design::exchange boundary; lower-level adapters must not depend on the engine.
00 can promote project_clips to the shared projection boundary when integrating those
adapters. Do not persist projection wrappers or synthetic child IDs.

The vector_cmds translation fragment moves clip geometry with ordinary Move previews
and release. The generic transform-layer fragment transforms Layer.vector.clip
alongside its existing linked vector-mask path transform. Owned layout transforms
derive clips from captured source geometry, so both paths apply the matrix exactly once.
Non-affine/projective crop adaptation remains with its geometry provider.

New Document preset fields remain geometry in pixels. The additive designUnits key
records document design units consumed by the owned Transform panel. Photo/old params retain px. No native migration or new
shared fields are needed. The ruler_units hook below takes document defaults when the legacy
pixel preference is selected and preserves configured physical ruler preferences.
01 can add an explicit per-view pixel override through its preferences lane. Merge i18n/16.tsv using English source lookup and supply
all supported locale entries in 00's catalog lane; the widgets accept t(source).

Public command signatures:

- vector.layout.apply {capture:{document,revision,layers},operation:{kind,...}}
  kind transform/contentMove: matrix:{m:[a,b,c,d,e,f]}; crop:rect:[x,y,w,h]|null;
  resize:rect:[x,y,w,h],basis:{m:[...]}=identity; artboard:rect and layers:[];
  all values are document pixels. ContentMove retains the target's crop.
- vector.layout.align {capture,edge:left|centerX|right|top|centerY|bottom,key?:id}.
- vector.layout.spacing {capture,axis:x|y,spacing?:pixels,key?:id}. Omitting spacing
  keeps the original outer span; an interior key remains stationary.
- vector.constraints.set {capture,constraints:{left,right,top,bottom,fixed_width,
  fixed_height}|null}; omitted booleans default false. Arrays, unknown keys and
  non-boolean values are errors and do not publish an edit.
- vector.layout.newDocument {category,width,height,dpi?,units?,name?}; dimensions
  are in DesignUnits enum units (Pixels/Points/Millimeters/Inches), default category.
- Existing layer.artboard.set adds constraints?:bool (default true when any child
  has constraints), scaleChildren?:bool=false; unconstrained legacy artboards keep
  their original size/moveContents behavior. Its existing command ID is retained.

Artboards retain bounded negative pasteboard coordinates; canvas growth clamps to its
existing positive 300000 pixel dimension limit. Constraints use document axes. A rotated child can undergo ordinary affine resizing;
anisotropic resizing can change its angle. A rotated/sheared parent basis is refused.
Numeric X/Y/W/H changes on a single artboard use the same constraint resize operation
as its handles. The requested rectangle is rounded to the native integer frame before
child pin arithmetic, so repeated fractional requests do not accumulate margin drift.
Ordinary groups have content bounds but no stored container frame. A constrained group
resize is accepted only when the resulting content bounds represent the requested
rectangle; retaining empty padding requires an artboard. Otherwise the operation is
rejected atomically rather than reporting an unrepresentable resize as successful.
Live corners need uniform scale or prior conversion; missing live-group/advanced
stroke geometry providers are explicit errors. R/S panel values are rotation/shear
changes about the selected anchor/custom origin, since baked paths have no persisted
object transform decomposition. Crop corner/edge handles support Shift ratio and
Alt center; dragging inside an existing crop moves its content with a fixed crop.
