# 06 — corner integration contract

Owned sources are ready for package 00's serial registration lane. No shared registry,
manifest, lock, tool enum or catalog has been edited in the branch. See
the registration patch below for the exact executable registration and
canvas fragments used in the offscreen integration copy (`target/corners-integration`).
That patch is **not** the persona/toolbar registration: 01 must supply its final tool ID.

## Registration and app routing (00 / 01)

- `pc-vector/src/lib.rs`: `pub mod live_corners;`. This pure module depends only on pc-doc
  and pc-geom. No pathops -> vector -> pathops cycle. Before that registration, the already
  compiled engine corner slot includes that same source by path, so the engine commands
  work in this branch. Once registered, replace the engine's `#[path = ...] pub mod geometry;`
  with `pub use photocraft_vector::live_corners as geometry;` to use one public module.
- `pc-ui-egui/src/lib.rs`: register `pub mod vector_packages { pub mod corners; }`, merging
  with other package registrations. Add transient `pub corner_state: corners::State` to
  PhotocraftApp and initialize `Default::default()`. No settings schema changes are needed.
- 01: tool ID `corner`, label `Corner Tool`, icon alias `directSelection` until a dedicated
  icon is supplied through the existing icon system. Add to Vector tools/Photographer as
  required by the persona package. Set `app.corner_state.active = app.ui.tool == Tool::Corner`
  **before lifecycle/input every frame**. Do not persist an active gesture or a preview.
- On layer/node selection change: `state.set_target(Option<LayerId>, Vec<CornerKey>)`.
  These are BASE subpath/knot indices, never projected indices. Empty selection + `all=true`
  targets all eligible nodes. With `all=false`, dragging a widget targets that node or the
  selected node subset. The context bar requires a selected subset for per-node typed edits.
- In app `logic`: `state.lifecycle(&session, active, ctx.input(|i|i.focused),
  ctx.input(|i|i.key_pressed(Key::Escape)))`. Tool/persona switch, focus loss, document switch
  and revision changes drop detached state. Selection changes call `set_target` and cancel.
- In the context/options bar: `state.context_bar(ui, &mut session)`.
- In `canvas_view`, immediately after allocating the response and before painting:
  `if primary { state.canvas_input(&mut session, &response, &xf); }`. This captures the
  original view transform, reads press/move/release before pixels are painted, and tracks
  release outside the viewport. It also reads modifier-only frames. While corners are active,
  suppress `move_input::canvas_input` and the later generic `paint_mouse::Buttons` path so
  the gesture is delivered only once. The executable diff below supplies both guards.
- In `canvas::tool_event`, **before legacy snapping/Move/Direct Selection**: when active,
  call `state.pointer(&mut session, ev, mods, zoom)` and return. The owned canvas capture
  continues Move/Up outside the viewport. Modifiers are sampled on each move/release.
- In canvas overlay painting, when active and `ui.view.extras` is enabled:
  `state.draw_overlay(&session, painter,
  &|p| xf.to_screen(p.x as f32,p.y as f32), xf.zoom as f64)`.
- First in `canvas::display_doc`, for the active document: `state.display_document(&session)`
  gives the held corner preview. Before the ordinary committed fallback, use
  `state.display_for_document(&session, idx)` for the committed projection. Other tools retain
  their existing preview priority between those two hooks. These supply ordinary paths to
  the ordinary GPU/CPU shape-split plan. It also supplies Navigator/extra views; it never
  mutates the Session document. Preview keys are tagged with bit 57. Provider errors must
  be surfaced as warnings/errors, never an empty-path success.
- The patch enables the context controls with the transient `State.active` flag only so
  their real app path can be tested before Tool::Corner lands. It defaults false. 01 maps
  the actual tool registry to that flag; no developer-facing flag belongs in the product UI.

## Engine / render / export contracts

`path.corner.set {document:u64, revision:u64, edits:[{layer:u64, corners:[KnotCorner]}]}` is
journaled. `path.corner.preview` accepts the same captured envelope, returns ordinary paths
and clamped metadata, and is never journaled. Both validate duplicates, missing/locked/nonshape
layers, all indices/numbers, and the complete target set before publishing. One commit calls
`vector_api::apply_shape_edits` once. Base Path, metadata and bounds-limited cache share undo.
Cache allocation is clipped to the document and limited to 64 Mi pixels per target.

`CornerGesture::begin(&Session, &[LayerId]) -> Result<CornerGesture>` captures document ID,
revision and detached shape snapshots; `set`, `preview_document`, `commit` expose the tool
lifecycle. Preview pointer frames replace/render captured targets only. `project_shape` and
`project_document` supply ordinary display paths. The pure lower-level
`pc-vector::live_corners::evaluate(&Path, &[KnotCorner]) -> Result<Projection, CornerError>`
is the geometry source that lower-level exchange adapters should call after registration:
**file adapters must not depend on these engine/UI wrappers**. Keep serialized base paths
and metadata; export the projected path. 08/09 merge this provider into their broader
appearance/scaled projection; appearance-bearing corner edits explicitly fail until their
provider can render them (no false legacy-paint success). The display snapshot's paths are
already projected while layer corner indices still address the Session base path. Never feed
that snapshot back into the evaluator. 08's combined provider evaluates corners once from the
base Session document, then appearance; it replaces this committed-display fallback rather
than evaluating the expanded paths again.

V1 is absent in this branch. No duplicate pc-pathops, kurbo adapter, nearest query, boolean
or analytic-bounds API was introduced. Widget hits use exact widget centres, not curve nearest.
After V1 registers, 03 maps `nearest(projected_path, point)`'s subpath/segment endpoints through
`Projection.sources` to base knots where needed. The local curve-offset/root solver is feature
geometry, not a substitute for V1's topology operations. Bounds-clipped caches use the existing
CompiledShape renderer's conservative bounds until the integrated V1 bounds provider lands.

## Node remapping (03)

`geometry::remap_metadata(&[KnotCorner], &[Vec<Option<CornerKey>>]) -> Result<Vec<KnotCorner>,
CornerError>` takes a complete old-base -> new-base map, removes deleted knots, retains kind
and radius, and rejects duplicate source/destination indices. Newly inserted knots receive
no corner automatically. 03 must remap in its same atomic node edit, then evaluate against
the new base Path; a smooth/straight endpoint conversion clears its now-ineligible metadata.
`Projection.sources[subpath][projected_knot]` is an inverse provenance map for hit testing,
not a persistence remap or a new authoritative path.

## Test registration (00)

The engine slot already registers its unit/GPU tests. UI tests are attached to the owned
module through `#[cfg(test)] mod tests`. In the existing serialized `tests/gpu/main.rs` add:

```rust
#[path = "../../src/vector_packages/corners/app_gpu_tests.rs"]
mod corners_app_gpu;
```

The full-app tests use the existing `gpu_lock`, real egui press/move/release, actual app
canvas callbacks, and the same public State API as the product. They assert RTX 5090 /
Vulkan / DiscreteGpu / Rgba32Float compositor capability and float canvas support, with no
skip path. The release pointer-frame test is explicitly ignored in ordinary suites and must
be run with `--release --ignored` before citing performance. No desktop window is created.
