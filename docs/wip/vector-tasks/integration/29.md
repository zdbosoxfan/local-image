## Public interfaces

`lightcraft_ui_egui::vectorize_handoff`:

- `context_action(&LightcraftApp, &mut egui::Ui, PhotoId) -> bool` draws the real
  context button, registers `photo:vectorizeInCompositing`, queues one request and
  closes the menu. It reads the **context photo**, independent of active/selection.
- `take_request(&egui::Context) -> Option<Request>` consumes it once on the shared
  root context. `pending(ctx)` disables repeat gestures while waiting.
- `Request { photo: PhotoId, catalog_revision: u64, path: String }` captures the
  catalog revision and explicit target. `request.check(&LightcraftApp)` revalidates
  both revision and file identity before dispatch. This is transient context data,
  not a preference, not a sentinel external editor name and not a second window.
- `disabled_reason(app, photo)` rejects demos, unavailable host bridge, Camera Raw
  Filter sessions and empty/oversized/NUL paths. Missing files go through normal
  decoder errors rather than probing disk on the UI thread.

`photocraft_ui_egui::library_vectorize`:

- `State::open_path(&mut self, &mut PhotocraftApp, photo: u64, path: &str)` calls
  the ordinary `PhotocraftApp::open_path`, including background tabs/read/decode.
- `State::open_file(..., path, bytes)` uses the same ordinary already-read route.
- `on_job_event(&mut self, &PhotocraftApp, &JobEvent) -> Result<bool, String>` sees
  only the exact originating `file.open` job. Invoke for the entire event batch
  BEFORE ANY normal jobs_ui handler, after the Session has applied the poll result. Resolve its returned
  document index into a DocId immediately, before tab moves or Open Document scripts.
- `take_launch(&mut self, &Session) -> Result<Option<Launch>, String>` drains once
  AFTER ordinary completion and UI synchronization. `Launch { photo, document,
  revision, layer }` requires the exact new active raster and singleton selection.
  Closed/switched/edited documents and changed layers discard the launch with an
  error. Decoder failures/cancellation produce no launch; ordinary job UI owns
  those notices. No previous document is retargeted or edited.
- `cancel(&mut self, &mut PhotocraftApp)` drops the launch and cancels its normal
  open job. Loaded documents stay open. `opening_job()` supports shell inspection.
- `preserves_library_state(&Session)` identifies documents opened through this
  action even after dialog Cancel, so returning to Library preserves browsing
  state. Closed document markers are pruned on the next open; this is transient.

## 00: Library menu insertion and selection fix

In `crates/lc-ui-egui/src/panels/grid.rs::context_menu`, add:

```rust
if crate::vectorize_handoff::context_action(app, ui, id) {
    return;
}
```

**Do not simply insert this below the existing unconditional `library.select`.**
That code runs when the menu is drawn, so clicking Vectorize on an unselected
photo would already have lost the old selection. Remove that unconditional select
and perform it only when a different context action is actually invoked. The
existing actions keep their existing target semantics with this local helper:

```rust
fn run_context(app: &mut LightcraftApp, id: PhotoId, command: &str,
               params: serde_json::Value) -> Result<serde_json::Value, String> {
    if !app.session.selection.contains(id) {
        app.run("library.select", serde_json::json!({"ids": [id.0]}))?;
    }
    app.run(command, params)
}
```

Replace each `app.run(...)` **inside a clicked non-Vectorize action** in that
function with `run_context(app, id, ...)`, including nested rating/flag/label,
album, stack, merge and export-preset actions. The Set Color Label helper needs
the same target-on-click handling; it must not select while opening its submenu.
For menu enablement compute prospective targets as the current selection if it
contains `id`, otherwise `[id]` (stack count, merge count, delete state and Finder
availability). This retains the pre-menu selection until an action is chosen.
Do not edit People state or filters. Existing Detail/Compare/filmstrip entrypoints
already reuse this context menu; no independent Develop tracing UI is added.

## 00: same-window host/open routing

Add a default transient `library_vectorize::State` field named `library_vectorize`
to `PhotocraftApp`, initialized with `Default::default()` in its constructor.
Do not put it in serialized UI state.

Add a default-false transient `preserve_library_vectorize_return` flag to `Host`.
It covers the first return after an accepted request even when background decode
fails or is cancelled before a document exists. A document-origin marker alone
cannot cover those paths. Keep the flag until returning to Library; it is not a
saved preference.

In `apps/local-image/src/library_host.rs`, adjacent to draining `self.opens`,
drain this new explicit message on the **same shared ctx**:

```rust
if let Some(request) = lightcraft_ui_egui::vectorize_handoff::take_request(ctx) {
    let checked = request.check(self.library());
    let mut handoff = std::mem::take(&mut self.editor.library_vectorize);
    let started = checked.and_then(|()| handoff.open_path(
        &mut self.editor, request.photo.0, &request.path
    ));
    self.editor.library_vectorize = handoff;
    match started {
        Ok(()) => {
            // Same operation used to show a file from `self.opens`, but suppress
            // switch()'s automatic active_photo()/develop_layer::open_photo path.
            // Do not call focus_open_document: this request needs a NEW raster.
            self.mode = Module::Compositing;
            self.preserve_library_vectorize_return = true;
            remember_module(Module::Compositing);
            self.styled = None;
            ctx.request_repaint();
        }
        Err(error) => {
            self.library().toast_error(ctx, error.clone());
            self.editor.open_failed(
                &photocraft_ui_egui::file_open::display_name(&request.path), &error
            );
        },
    }
}
```

Use the existing module transition cleanup/restyling and sync paths, with an
explicit already-dispatched-file flag if needed. Calling `Host::switch` unchanged
would also load the Library's **active** photo as a Develop layer, producing a
second handoff and potentially targeting the wrong image. Do not add requests to
`external_edits`, import edit copies, stack new Library photos, change selection,
or apply/save Develop settings. Opening the original raster uses the existing
file decoder and px units. Background decode error/cancel keeps Library state;
the ordinary progress tab/notice can stay in Compositing.

In `Host::switch`, when returning from Compositing to Library, compute:

```rust
let preserve_library = from == Module::Compositing && to == Module::Library
    && (self.preserve_library_vectorize_return
        || self.editor.library_vectorize.preserves_library_state(&self.editor.session));
```

For this return only, guard the existing `saved.or_else(active_photo)` selection
block with `!preserve_library`, and guard `set_library_view(lib, develop)` with
`!preserve_library`. The hidden Library's selection/source/filter/People controls
and original Detail/People/Grid view remain untouched. Keep normal restyling,
background work and explicit save/return behavior. This marker survives dialog
Cancel and is tied to DocId, so unrelated documents retain their existing return
semantics after the first return. Clear `preserve_library_vectorize_return` only
after the guarded Library transition has completed, including after decode
failure or cancellation. The synchronous unsuitable-document error also records
new-file origin; immediate read/decode errors do not change modules.

In `jobs_ui::tick` and `tick_background`, collect the actual `poll_jobs` batch and
run `state.on_job_event(app, &event)` for **all** events before dispatching **any**
`on_event(app, event)`, then always continue the existing handlers. Otherwise an
unrelated open's tab move can invalidate this open's document index. A rejected
launch must not swallow normal open
completion, warning/color-policy/script hooks, path/recent recording or errors.
Do not drain Session events twice or correlate by filename/current active layer.
Use `std::mem::take` to avoid overlapping mutable borrows:

```rust
let events = app.session.poll_jobs();
let mut handoff = std::mem::take(&mut app.library_vectorize);
let errors: Vec<_> = events.iter().filter_map(|event| {
    handoff.on_job_event(app, event).err()
}).collect();
app.library_vectorize = handoff;
for event in events { on_event(app, event); }
for error in errors { crate::notices::error(app, error); }
```

After normal open completion/sync, and once any color-policy modal is resolved:

```rust
match app.library_vectorize.take_launch(&app.session) {
    Ok(Some(_launch)) => app.trace_dialog.open(&mut app.session, &app.trace_prefs),
    Ok(None) => {},
    Err(error) => crate::notices::error(app, error),
}
```

This uses package 28's actual `State::open(&mut Session, &Preferences)` API,
read from its WIP source. It captures the validated new raster layer; no parallel
dialog or tracer is implemented here. Cancel remains package 28's existing
`State::cancel`, which drops preview/jobs and keeps the loaded document.
On leaving Compositing, quitting or abandoning the opening tab call the handoff
cancel hook through `std::mem::take` and restore the field afterwards. Ordinary
job cancel/failure events also clear it. Retain one pending
request at a time; an attempted second open returns an error without starting a job.
Leaving Compositing also calls 28's existing `trace_dialog.cancel(&mut session)`
to cancel its preview/apply work; handoff cancellation only owns the open job.
