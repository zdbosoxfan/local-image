## Engine commands (already registered)

`path.node.edit` is one journaled transaction:

```json
{"document":123,"revision":42,"targets":[{"name":"layer","layer":456,"anchors":[[0,1],[0,2]]}],"operation":{"type":"delete"},"convertLive":false}
```

Target `name` is `work`, `layer` (explicit ID), or a saved path name. Operations are
`move {delta}`, `handle {knot,handle,to,independent}`, `bend {knot,t,delta}`,
`convert {knot,out}`, `insert {knot,t}`, `delete`, `sharp`, `smooth`, `smart`,
`break`, `join {tolerance}`, `close`, `reverse`, `align {axis,value}`,
`transform {matrix:[a,b,c,d,tx,ty]}`. Result `targets` contains remapped selection.
Old `path.moveAnchors/moveHandle/bendSegment/convertPoint` IDs remain registered once,
and accept `targets`, `document`, `revision`, `convertLive` as additive parameters.
Old single-target automation keeps its explicit path-conversion behavior.

The whole set is preflighted before geometry/caches, including the shared
`vector_api::snapshot_shapes` validation for shape targets. Edited snapshots are validated
and bounds-clipped caches prepared before a single Session::edit. Shape-only edits publish
through `vector_api::apply_shape_edits`; mixed work/saved paths, masks and donor-consuming
joins publish the entire detached document in one Session::edit because the foundation's
shared helper accepts only shape replacements. Corner indices publish in that transaction.
Appearance paths deliberately require the package 08 renderer.

## V1 provider (00, after V1 merge)

Install once during engine registration/startup, before join/break commands execute:

```rust
let _ = crate::vector_packages::node::install_geometry(
    crate::vector_packages::node::Geometry {
        nearest: |p, q| photocraft_pathops::nearest(p, q).map_err(|e| e.to_string()),
        join: |p, t| photocraft_pathops::join(p, t).map_err(|e| e.to_string()),
        split: |p, s, k, t| photocraft_pathops::split_at(p, s, k, t).map_err(|e| e.to_string()),
    },
);
```

Use V1's actual crate alias when registering the existing dependency. No duplicate
geometry implementation is supplied. `break` calls `split_at` at t=0 on the selected
subpath, verifies cut provenance, and preserves the surrounding PSD component order.
`join` calls V1 on all targets, keeps the receiving curve's paint, and removes consumed shape layers in the same
transaction; vector-mask donors keep their pixel layers. Provenance moves their live
corners to the receiver.
A missing provider returns an error without editing or journaling.

## Live UI hooks (00)

These functions are all in the already-registered `crate::direct_select` module:

1. After dialog/text focus exclusions in `shortcuts::handle`, **before command shortcut
   dispatch**, insert `if crate::direct_select::frame(app, ctx) { return; }`.
   Also call `frame` every app frame before canvas rendering so focus loss, document or
   tool switch cancels a captured gesture even with no new pointer event. It consumes
   Escape and Delete/Backspace only when the Node tool owns them; focused text keeps keys.
2. In `canvas::display_doc`, before the existing preview providers:
   ```rust
   if let Some(shown) = crate::direct_select::display_doc(app, idx) { return shown; }
   ```
3. In `canvas::document_view` where `xf`, the document content rect, and current input
   are available, call
   ```rust
   let node_input = crate::direct_select::canvas_input(app, &ctx, idx, &xf, rect);
   ```
   after the existing active-document selection handling, when the canvas is not under a modal dialog.
   Only the active document index handles capture; this prevents split views from dispatching
   a captured motion through two different view transforms. If `node_input` is true, suppress this
   frame's legacy Down/Move/Up tool_event dispatch and ordinary click handling. Continue
   canvas rendering, view navigation and overlays. This replaces egui's threshold-delayed
   legacy dispatch for Node gestures: first-pixel preview, outside-canvas capture/release,
   modifier-only frames, and double-click insertion all use raw pointer events once.
   The Pen's existing command/Alt Direct Selection modes retain legacy pointer dispatch.
4. In the Direct Selection context bar:
   ```rust
   crate::direct_select::context_ui(app, ui);
   ```
   It owns Sharp/Smooth/Smart, Break/Join/Close/Reverse, node alignment, transform mode,
   and the explicit Convert to curves prompt. Show its pending prompt even when another
   context bar would normally hide it. No shared state fields are required.

## Snapping provider (07 via 00)

`direct_select::install_snapping` accepts a read-only function:

```rust
fn(&Document, &[node::Target], Point, f64) -> Result<Point, String>
```

The point and tolerance are document-space; targets identify all selected nodes to
exclude from self-snap. Tolerance is 6/(zoom*pixels_per_point). Adapt 07's query using
its own preferences and deterministic priorities. Both preview and release call the
same query; Shift constrains, Ctrl/Command bypasses. This package does not invent a
second snap manager or mutate Move's target cache.

## Enhanced renderer callback (06/08 via 00)

`node::install_renderer` accepts:

```rust
fn(&Document, &ShapeLayer, &VectorData) -> crate::Result<Surface>
```

Install the shared feature-projection/paint cache adapter here when 06/08 land. It is
called identically for detached previews and commit preparation. It must produce a
bounds-clipped cache, evaluating live corners and the appearance stack against document
context. Without it, legacy shapes retain the existing renderer behavior and appearance
edits are refused explicitly. Corner metadata is remapped and retained in either case;
the foundations' legacy renderer does not yet evaluate that metadata. No new renderer
or separate display geometry is introduced by this package.
