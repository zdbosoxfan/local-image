# 09 scaled canvas integration lane

The app callback is wired inside the owned `gpu_canvas.rs`; shared canvas/lib/plan,
manifest, lock and catalogs are untouched. `gpu_canvas::scaled_view` compiles the same
owned CPU/vector/GPU sources through source-path bridges, so this branch does not
need unregistered external symbols to build. The bridges are temporary until 00 owns
native public module registration. No new dependencies, pathops reverse edge or model
fields are added.

Native registry fragments for 00 (remove the corresponding bridge after these land):

```rust
// pc-compose/src/lib.rs

// pc-vector/src/lib.rs
pub mod view;
// pc-text/src/lib.rs
pub mod view;
// pc-gpu/src/lib.rs

```

After native registrations, replace the bounded legacy text branch of UI `project` with:

```rust
photocraft_text::view::render_text_view(
    &mut engine, t, doc.resolution_dpi, doc.pixel_format(), clip, scale,
).map_err(|e| cpu::ViewError(e.into()))
```

The text module cannot be source-path compiled by UI because its glyph drawer uses
pc-text's existing skrifa dependency. The temporary app provider uses the existing public
text renderer only when its whole ink buffer fits the 16 MP budget, then crops to the
visible apron. The native module already rasterizes visible 256px bands; its standalone
test compiles and exercises that implementation. Large offscreen text explicitly requires
the native registration; there is no manifest change or duplicated font dependency.

The existing callbacks get document snapshots from `GpuCanvas::refresh`, compute physical
scale and the visible rect in `prepare`, run the normal GPU compositor on the detached
scaled tree, and draw those tiles with existing CMS/HDR/checkerboard/grid shaders. Persisted
caches and session state are unchanged. Raster sampling is nearest at magnification, as in
the current canvas. Unsupported GPU plans use the same scaled CPU projection. GPU readback
is only in tests, not the canvas implementation.

Provider signatures:

```rust
// CPU library entry points
flatten_scaled(&Document, visible: Rect, scale: f64) -> Result<ViewTiles, ViewError>
flatten_scaled_with(&Document, Rect, f64, Projector) -> Result<ViewTiles, ViewError>
type Projector = fn(&Document, &Layer, f64, Rect) -> Result<Surface, ViewError>;
ProjectionCache::project(&Document, &ViewRequest, Projector) -> Result<Document, ViewError>
// UI installs 08's renderer once; identical for GPU and CPU fallback
crate::gpu_canvas::scaled_view::install_projector(Projector) -> Result<(), Projector>
// Font/master/pattern/appearance providers fold generations only for dependent layer IDs
GpuCanvas::set_scaled_dependencies(doc_key: u64, HashMap<LayerId, u64>)
```

00 calls `set_scaled_dependencies` after `GpuCanvas::refresh` has captured the projected
display document, before painting its canvas callback. Fold only the generations actually
referenced by each layer. Display-CMS LUT changes use existing `set_display_lut` signatures;
they are applied during sampling and need no geometry rerasterization.

The projector must render transformed geometry in device pixels over the supplied clip,
with the full scaled document canvas for paint layout, and must preserve merged coverage
for appearance clipping. `Layer.vector.clip/live/on_path` currently require the feature
projection stage from 12/15/18–20 before this tree projection runs. Package 08 owns
shape_split/plan routing for appearance. Legacy shape pattern paints explicitly refuse the
missing enhanced provider; normal pattern fill/effect layers use the existing compositor.

08 also needs a bounded-region shape splitter before large stroked clipping bases/effect
shapes can be rendered safely at magnification. The existing `shape_split::split(sh,
canvas, depth)` can render the entire compiled path bounds even for a small visible rect.
09 refuses a stroked bounding area over its view budget. The required shared hook is
`split_view(sh: &ShapeLayer, canvas: Rect, clip: Rect, depth: SampleType)` (same fill/stroke
surface pair), where `canvas` preserves paint layout and `clip` bounds all raster/fitting
allocations. CPU and GPU plan calls must receive the projected visible apron as `clip`.

Package 03's **production** node hooks in `integration/03.md` remain necessary. The new
full-app node GPU gate is dependency-ignored until those exact hooks land. No test-host
injection is presented as full-app acceptance. The release node pointer-frame benchmark
must run after that merge before <16ms is claimed.

When routing detached node frames, also supply `GpuCanvas::refresh` with conservative
damage between the previous displayed preview and the new one:
`scaled_view::damage(&previous_preview, &new_preview) -> Option<Rect>`.
Keep the GPU document key stable across gesture frames; put the preview generation in
the existing canvas refresh key. Without bounded normal-refresh damage, the baseline 1x
compositor can still process the whole 6000x4000 document before scaled `prepare`, which
must be included in the app benchmark. Bounds from only the gesture's initial and current
documents are insufficient when the pointer reverses direction: include the last preview.

Existing Move planes retain the original callback path and warm uniforms; 00 must hand
scaled geometry to those planes through the established feature projection before crisp
vector Move planes are accepted. The package does not replace Move's flattening cache.

Integration tests remain package-owned; 00 may move the standalone GPU test source into
its central GPU binary, then add `mod scaled_view;` and its shared `GPU_LOCK`. No central
binary registration was edited here.
