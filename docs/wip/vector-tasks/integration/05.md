# 05 — Vector Pencil and Sculpt integration lane

Package owns only the three implementation files, their pencil tests, and these records.
No shared registry, manifest, lock, catalog, raster Pencil, or router was edited.
Engine commands are already compiled by the foundation's `pencil::specs()` slot.

## Actual interfaces

`photocraft_engine::vector_packages::pencil` exports:

- `Options` (`#[serde(default)]`), `StabilizerKind::{None,Rope,Window}`.
- `Operation::SculptRange` uses `CurvePosition {segment,t}` for arbitrary cubic intervals.
  Exact de Casteljau splits retain every outside anchor and outside curve geometry, including
  same-cubic intervals and closed wraps; open backwards drags reverse only the samples.
- `Capture::begin(&Session, Operation, Options) -> Result<Capture>`; capture includes
  document/revision, insertion anchor or shape/subpath/interval, reserved layer ID, paint.
- `prepare(&Session, &Capture, &[fitting::Sample], closed: bool) -> Result<Prepared>`.
- `prepare_with(..., impl Fn(&[Sample], FitOptions) -> Result<Path,String>)`.
- `Prepared::{path,layer,params,commit}`; `document: Arc<Document>` is detached and has a
  bounds-limited real `pc-vector` cache. `pressure` retains stabilized samples for 11.
- `path.pencil.preview` is non-journaled; it takes `{capture,samples:[[x,y,pressure],...],closed?}`
  and returns commit parameters. `path.pencil.commit {capture,path:serde Path}` is journaled.
  Both reject stale IDs/revision, invalid targets/options, excessive geometry/cache bounds.
  Commit validates outside geometry for Sculpt/Continue and prepares its cache before edit.

`pc-ui-egui/src/vector_packages/pencil.rs` exports:

- `TOOL_ID = "vector-pencil"` (never reuse raster `pencil`/`Tool::Pencil`).
- `State` with serde(default) `options`; gestures/caches/pressure are serde-skipped.
- `State::pointer(&mut self, &mut Session, canvas::ToolEvent, egui::Modifiers, zoom: f32)`.
- `State::frame(&mut self, &Session, &egui::Context, selected: bool)` for cancellation on
  Escape/focus loss/tool/persona/doc/revision changes.
- `State::display_doc(&self, &Session) -> Option<(Arc<Document>,u64)>` for the actual compositor.
- `context_bar(&mut egui::Ui, &mut State)`; changing options cancels the current gesture.
- `canvas_input` is a real raw-event adapter for the small kittest host, including release
  outside the canvas. `canvas_input_with_pressure` accepts the existing stylus pressure and
  captures press immediately without dropping samples before egui's drag threshold. Use it
  before legacy canvas button handling, then disable those buttons for this tool; keep the
  `ToolEvent` routing above for automation. Do not feed the same events through both adapters.

## Exact 00/01 wiring

1. `pc-vector/src/lib.rs`: `pub mod pencil_fit;`. Replace the temporary source bridge in
   engine pencil.rs (`#[path=...] pub mod fitting;`) with
   `pub use photocraft_vector::pencil_fit as fitting;`. This avoids a pc-vector→pc-pathops cycle.
2. `pc-ui-egui/src/lib.rs`: register `pub mod vector_packages { pub mod pencil; }` (or add to
   the coordinator's existing aggregate), add `pub vector_pencil: vector_packages::pencil::State`
   to `PhotocraftApp`, initialize with Default. 01 registers Tool::VectorPencil with id
   `vector-pencil`, label `Vector Pencil`, Vector family and existing pencil icon alias.
3. Before tool rendering/input each frame:

   ```rust
   let selected = app.ui.tool == Tool::VectorPencil /* and Vector persona */;
   app.vector_pencil.frame(&app.session, &ctx, selected);
   ```

   Route `ToolEvent` before legacy Pen/Alt Convert Point, raster Pencil, snap filtering and
   raster Alt-eyedropper dispatch. Use current modifiers for EVERY event:

   ```rust
   if app.ui.tool == Tool::VectorPencil {
       let zoom = app.current_zoom();
       if let Err(e) = app.vector_pencil.pointer(&mut app.session, ev, mods, zoom) {
           app.ui.status = e.to_string(); app.ui.status_error = true;
       }
       return;
   }
   ```

   At the start of `canvas::tool_move(app,x,y,pressure,mods)` route hover/automation moves
   through the same `tool_event` branch and return before legacy Pen hover or snapping:

   ```rust
   if app.ui.tool == Tool::VectorPencil {
       tool_event(app, ToolEvent::Move {x,y,pressure}, mods);
       return;
   }
   ```

   In canvas_view's `gesture_active_before`, include `app.vector_pencil.active()` when this tool
   is selected; include VectorPencil in `freehand_tool` to recover every raw pointer sample.
   The existing egui response owns press/release capture; do not create app.drag/raster strokes.
4. At the start of `canvas::display_doc`, for the ACTIVE document and selected VectorPencil:

   ```rust
   if app.ui.tool == Tool::VectorPencil
       && app.session.active_index() == Some(idx)
       && let Some(shown) = app.vector_pencil.display_doc(&app.session)
   {
       return shown;
   }
   ```

   This routes to BOTH actual GPU and CPU canvas/Navigator. No egui-painted substitute stroke.
   Context bar routes `pencil::context_bar(ui, &mut app.vector_pencil)` for the distinct tool.
5. Persist Options under the persona's existing tool preference mechanism with serde(default),
   load into State on startup and save when context-bar settings change. No second toolset store.
6. V1 integration: once actual `photocraft_pathops::fit_path` is merged/registered, engine
   `prepare` calls:

   ```rust
   prepare_with(session, capture, samples, closed, |samples, options| {
       fitting::fit_with(samples, options, |points, tolerance| {
           photocraft_pathops::fit_path(points, tolerance).map_err(|e| e.to_string())
       })
   })
   ```

   00 owns that internal dependency. Re-run circle/Hausdorff gates with this backend; passing
   native-helper tests does not establish V1's numerical output. Enhanced appearances require
   08's actual cache renderer; until then editing them is an explicit error, never stale pixels.
7. Merge `i18n/05.tsv` via the catalog lane; append PORTS rows below and regenerate attributions.

## Reproducible offscreen app wiring rehearsal

`python3 docs/wip/vector-tasks/pencil/register_ui.py` copies ONLY pc-ui-egui below
`target/pencil-registration`, links existing assets and sibling lc-ui/plug-in fixtures read-only,
and generates a scratch
workspace that depends on original crates. No registry dependency is added. It applies the
above app-field/input/display hooks, recovers all pointer samples, and suppresses legacy Pen
outlines. Pen + a scratch-only `vector_pencil_enabled` flag act as the activation sentinel
because 01 is not merged. This is actual PhotocraftApp/canvas GPU execution, **not final persona
registration acceptance**. The owned `pencil/gpu_tests.rs` records that limitation explicitly.
After 01 merges, replace its two sentinel activation lines with Tool::VectorPencil and remove
sentinel fields/conditions from the rehearsal script. Run the same GPU test in the integrated app.

```sh
PATH="$HOME/.cargo/bin:$PATH" CARGO_BUILD_JOBS=3 CARGO_TARGET_DIR=target \
  cargo +1.98.1 test --offline --manifest-path target/pencil-registration/Cargo.toml \
  -p photocraft-ui-egui --lib pencil
```

The analogous `register_vector.py` generates `target/pencil-vector-registration` with only
`pub mod pencil_fit;` added to a copy of the vector crate. It compiles the exact owned helper
and its independent tests without editing 00's shared module registry.

The `pencil_full_app_gpu_live_pointer_preview_release_cancel_and_frame_measurements` test
requires RTX 5090/discrete/Vulkan/Rgba32Float. Its release run reports real pointer frame, subsequent presentation frame, GPU readback, and their measured per-move total; no microbenchmark performance claim is substituted.
