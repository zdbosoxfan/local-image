# Package 37 — compiled view/isolation hooks for the 00/09/32/35/46 lane

These package modules are compiled in this branch (minimal append-only registrations in
pc-vector/lib.rs, pc-engine/vector_packages.rs, and pc-ui-egui/lib.rs). No shared canvas,

## 00: authoritative session storage and commands

Add these **runtime** fields to `pc-engine::DocState`, initialized with `Default::default()`;
do not add them to Document, native persistence, history snapshots, or serialized prefs:

```rust
pub vector_isolation: vector_packages::isolation::State,
pub vector_view: vector_packages::isolation::ViewState,
```

Install the providers once while initializing the engine, before any UI/automation command:

```rust
use crate::vector_packages::isolation as iso;
iso::install_hooks(iso::Hooks {
    read: |s| s.active().map(|d| d.vector_isolation.clone()).unwrap_or_default(),
    write: |s, state| { if let Some(d) = s.active_mut() { d.vector_isolation = state; } },
    exit_all: |s| { for d in &mut s.docs { d.vector_isolation.exit(); } },
}).map_err(|_| EngineError::Other("isolation hooks already installed".into()))?;
iso::install_view_hooks(iso::ViewHooks {
    read: |s| s.active().map(|d| d.vector_view.clone()).unwrap_or_default(),
    write: |s, state| { if let Some(d) = s.active_mut() { d.vector_view = state; } },
}).map_err(|_| EngineError::Other("view hooks already installed".into()))?;
```

The installation fragment belongs **inside pc-engine** (its Session.docs is private).
At every document/persona transition call `iso::exit_session_isolation(s)` and cancel
all gesture owners **before** changing dispatch or releasing input. Clearing all document
scopes prevents an isolated old tab from being restored when it becomes active again.
The UI `isolation::frame` also detects these transitions and returns a cancellation flag.
Do not interpret a tool change as an isolation exit: switching to Rectangle must preserve
its insertion target. Tool changes still cancel their previous tool's captured gesture.

Requested new compiled command slot `vector_packages::view_modes` is this exact re-export:

```rust
// pc-engine/src/vector_packages/view_modes.rs (00 owns this aggregate slot)
pub use super::isolation::{view_specs as specs, ViewAction, ViewChange, ViewMode, ViewState};
```

Append `pub mod view_modes;` and extend the aggregate with `isolation::specs()` and
`view_modes::specs()`. Commands supplied: `vector.isolation.enter`, `.exit`, `.scope`,
and `vector.view`. **Every spec has journal=false**. `vector.view` takes
`{document,revision,generation,action:{type:set,mode:vector|outline|xray|pixelPreview}}`,
or `toggleOutline`, `togglePixels`, `layerOutline {layer}`. Isolation enter takes
`{capture:{document,revision,generation},layer}`. Enter/captured changes check freshness
and validate targets before changing any view state. Missing storage hooks are errors.
Existing proof-color commands/shortcuts retain Pixel persona ownership.

## 00/01/46: menus, input, Layers, cancellation

Call `photocraft_ui_egui::isolation::frame(app, ctx)` **before** canvas input and shortcut
dispatch. If it returns true, cancel the established Pen/shape/node/move/selection and
package gesture states, detached previews and pointer capture. The return includes
Escape, mode changes and document/persona transitions. Do not journal this cancellation.
Modal dialogs disable view accelerators; egui text entry owns its keys.
Expose the Vector view menu/eye/thumbnail hooks only in the Vector persona. Pass the same
persona/modal enablement gate to the canvas hook before dispatching isolation input.
The bridge also compares the last dispatched mode/scope generations, catching menu, row
and automation changes on the next frame. For bar/canvas hooks returning a change in the
current frame, cancel remaining gesture owners immediately before further input dispatch.

Mode menu:

```rust
let mut b = isolation::bridge(ui.ctx());
view_modes::menu(ui, &mut b.views, |s| crate::i18n::t(s).to_string());
isolation::store_session(&mut app.session, ui.ctx(), b);
```

Use `isolation::bar(ui, &mut session, &mut b.isolation, translate)` above the canvas.
Dynamic breadcrumb names are source layer names. Fixed labels come from `i18n/37.tsv`.
Ctrl/Cmd+Y and Alt+Ctrl/Cmd+Y are consumed by `view_modes::shortcuts` only when Vector
and the Illustrator keymap are active. The current `frame` enables the default Illustrator
keys; 46 must pass the keymap gate when exposing additional keymaps. Mode setters, eye
clicks and commands share `engine::ViewState`; there is no second persisted view store.

For an eye response, **before** the existing visibility command:

```rust
let mut b = isolation::bridge(ui.ctx());
let consumed = view_modes::layer_eye(ui, &eye_response, &mut b.views, &source_doc, layer_id)?;
isolation::store_session(&mut app.session, ui.ctx(), b);
if consumed { /* do not invoke layer.visible/showOnly */ }
```

For the existing Layers thumbnail response call
`isolation::thumbnail(ui, response, session, &mut b.isolation, id)` before selecting/expanding
the row. It captures on primary press and consumes Alt-click release. For the canvas
click/double-click response call
`isolation::canvas(ui, response, session, &mut b.isolation, hit_id, enabled)`. The hit is the
source ID from 32 (map leaf to its eligible container for entering groups). Outside hits
include unselectable dimmed objects, so double-click outside can exit. In Outline mode,
use `Frame::hit` instead of fill hit-testing. Single clicks must pass the scope gate below.
After any row/canvas/menu change call `store_session`, not only `store`, so automation and
the next frame read the same authoritative session state. Errors go to the existing status
error flow, not to a fake successful selection or root insertion.

## 08/09: paint/overlay fragment, exact device scale and cache keys

`view_modes::Geometry` is the shared **geometry** boundary:

```rust
fn paths(&self, doc: &Document, layer: &Layer) -> engine::Result<Vec<Path>>;
fn xray_layer(&self, doc: &Document, layer: &Layer) -> engine::Result<Layer>;
```

Paths are in document coordinates, projected exactly once. `NativeGeometry` already
uses 06's corner projection, pc-text's glyph/on-path outlines, 15's shared symbol expansion,
and raster/smart cache boxes with a cross. Its X-ray provider uses 08's fill-only appearance
renderer and 15's legacy symbol preparation. Live groups and advanced symbol fills need
the existing shared feature provider: they return errors until supplied, not base-path or
stale-cache fallbacks. `xray_layer` returns an effects-free, fill-only layer with faded leaf
opacity (0.20); do not apply 0.20 to enclosing groups again. Isolation dim alpha is 0.25,
applied only to maximal outside roots to avoid repeated fading in nested groups.

Before 09 prepares the base display, evaluate the view policy using its **original source**
(including detached live previews) and the authoritative isolation scope:

```rust
let mut b = isolation::bridge(ctx);
let scope = b.isolation.scope.scope(&source)?;
let frame = frame_cache.prepare(
    &source, source_revision, shared_projection_generation,
    &b.views, scope, document_to_device, device_clip, &shared_geometry_provider,
)?;
```

`document_to_device` is the exact zoom × pixels-per-point affine (plus the actual canvas
origin/flip), **not** the quarter-octave scale bucket. `device_clip` uses the same coordinates.
The cache includes source Arc identity/revision, mode/layer flags, scope, projection dependency
generation, transform and viewport. Retain this per view; warming 5000 paths must not rebuild
geometry or render masks on each pointer-only frame. Source Arc identity distinguishes live
previews which keep the document revision. Font/master/pattern generations must be supplied.

- Vector: send `frame.base` through the established crisp 09 path.
- Outline: `frame.base == None`; suppress the source artwork/effects entirely and keep
  the page/backdrop. Draw all wireframes above that backdrop.
- X-ray: send the detached fill-only `frame.base` through 09, then draw all outlines above
  the **whole composite**, not inside original clipping/effects groups.
- Pixel Preview: bypass `GpuCanvas::prepare_scaled` for the base; choose its 1x texture with
  nearest document-pixel sampling, including HiDPI. `Frame::pixel_buffer` is the independent
  reference through the existing CPU compositor at 1x. Keep the pixel grid in the native path.
- Per-layer/group outline: original base paint is suppressed only for those source subtrees;
  their wireframes are over the complete composite. Overrides also suppress X-ray fills.

`Frame::overlay_buffer(device_clip)` supplies an exact-area, straight-alpha black outline
buffer; use an egui/GPU overlay texture positioned 1:1 in device pixels and clipped to the
canvas. Cache it by the frame/dependency key. Upload into a separate overlay texture/view key;
never replace persisted ShapeLayer caches, source document pixels or history. Preserve the
normal display CMS/HDR/backdrop and Move planes. If using scaled compositor tiles, place the
exact-device overlay **after** the final bucket-to-screen sampling, or hairlines will scale.
`Frame::paint(painter, ppp, device_to_screen)` supplies an egui geometric overlay fragment for
preview/UI fallback; final parity uses the exact-area overlay buffer. `1 / ppp` logical points
is exactly one physical/device pixel. Do not enlarge it at 800%.

Mode/scope generation must join canvas `view_key`/CPU display keys, texture keys and damage
keys. Switching mode/override/scope is view damage even when doc revision is unchanged.
At present `prepare_scaled` returns early at physical<=1; the outline overlay still applies
there. The original source must remain available so Outline's `base=None` does not discard
hit-test data. CPU fallback and GPU base/overlay must use the same prepared frame.

## 02/04/05/35: insertion

At pointer-down capture `engine::isolation::Capture::new(session, isolation_state)` and
`State::insertion_target(doc)`. Prepare the entire new object/tree in its target coordinates
(`InsertionTarget::from_document` is the inverse instance affine for symbol masters).
Validate staleness and the entire target set **before** bounded cache work, as usual.
At release use:

```rust
engine::isolation::insert_prepared(session, isolation_state, capture, above, layer)?;
```

Root/group insertion commits one Session::edit, verifies direct-child anchors, IDs, locks,
depth and cache readiness. A group target with no anchor appends at the group's top.
Symbol-master insertion delegates to 15's update_master so all dependent caches and undo
are handled in one transaction. The new object's coordinates are **already master-local**.
Symbol master `above` currently requires None (top-level append); nested master insertion
needs 15/35's master namespace adapter rather than doc.layer(master_child_id).
For a compound path, 35 must install
`install_compound_inserter(fn(&mut Session, Capture, LayerId, Layer) -> Result<LayerId>)`;
its provider preserves source objects/appearance. Missing 35 is an error, never a successful
insertion at the root or a destructive merge of new appearance into the old path.

## 32 / Select All / Layers / automation: authoritative scope

`State::scope(&doc) -> Result<Scope>` exposes `contains`, `selectable`, `select_all`, `dimmed`
and `master_layers`. Group isolation excludes its enclosing group; nested containers are
selectable if visible/unlocked. Compound and symbol instances use singleton document-object
scope; anchor/master editing uses their own namespaces. Symbol master IDs must not be
passed to doc.layer or Session::selected_layers (those traverse the document tree only).

32 can use `isolation::group_scope(ctx) -> Result<Option<LayerId>>` for its current
`selection::Scope.isolation` group field. The helper **errors** for compounds/symbols, so
missing 32 extension cannot silently select outside them. Extend 32's index/provider for
singleton and symbol-master namespaces; gate the final entire selection set with this scope
before writing selection fields. Apply the same predicate to Select All, Layers click/range,
legacy canvas selection and automation selection actions. `isolation::select` is the supplied
atomic UI selection helper (no revision/history/journal changes).
