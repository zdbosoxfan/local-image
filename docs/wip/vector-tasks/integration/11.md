The existing document model, V1 kernel, appearance renderer and vector_api were retained.
The engine slot is compiled and registers `shape.width.{info,preview,set}`. Minimal new-crate
registration is applied under CODEX-TASK's REGISTRATION override: `photocraft-vecfx`, its

## Public engine and projection APIs

```rust
photocraft_vecfx::width::Projection // implements pc-vector::appearance::StrokeProjection
photocraft_vecfx::width::outline(&Path, &StrokeItem) -> Result<Path, String>
photocraft_vecfx::width::{validate_profile, at, uniform, preset, set_point, Metric, SavedProfile}
photocraft_engine::vector_packages::width::Gesture::begin(&Session, &[LayerId], Option<usize>)
Gesture::{request, profile, set_profile, set_point, remove, preset, is_fresh, commit}
width::prepare(&Session, &Commit) -> Result<Vec<ShapeEdit>>
width::preview_document(&Session, &Commit) -> Result<Document>
```

`item=None` chooses the topmost stroke of each captured shape, including legacy fill/stroke.
`Some(index)` chooses that absolute appearance-stack index on every target. Profiles are
absolute nonnegative document pixels, up to 5000 per side, with strictly increasing normalized
subpath arc-length t in [0,1]. Empty means legacy width. Each subpath runs the same profile.
Duplicate positions are deliberately rejected by the shared contract; moving onto a point
replaces it, with no index ambiguity. Left is up while travelling +x in y-down document space.
Closed seams keep the t=1 widths on the incoming side and t=0 on the outgoing side, including
taper presets whose endpoint widths differ.

The journaled edit envelope is:

```json
{"document":42,"revision":7,"edits":[{"layer":12,"item":1,
 "profile":{"points":[{"t":0,"left":0,"right":0},
                       {"t":0.5,"left":10,"right":4},
                       {"t":1,"left":0,"right":0}]}}]}
```

`shape.width.set` checks freshness, duplicates, inherited locks, target types, all profile
numbers and all selected stroke indices before rendering. It uses package 08's compiled
appearance cache-byte preflight (512 MiB total padded bounds-clipped tiles), then publishes
one vector_api edit. Original editable Path and appearance metadata share the undo state.
`shape.width.preview` takes the same envelope but never edits/journals. `shape.width.info`
accepts `{layers:[id],item?:index}` and returns the captured envelope. UI previews call
`preview_document` to obtain actual detached pixels, not a fake successful preview command.

## 08 / 09 / file adapters

- Compose the `photocraft_vecfx::width::Projection` provider into package 08's unified stroke
  provider, then replace `NoProjection` in appearance engine prepare/preview/set and all
  scaled render/export entry points. For ordinary profile strokes, call `width::outline`.
  pc-vector consumes this ordinary filled Path; it must not depend back on vecfx/pathops.
- Use the same provider on rebuilds after native document loading and geometry edits;
  persisted shape caches are usable without re-evaluating profile geometry.
- Package 11 preserves the base weight for relative dash lengths/offset, samples the profile
  at each dash's original subpath span, normalizes overlapping corners/tight bends through V1,
  clips closed inside/outside profiles geometrically, and uses native tessellation for a
  symmetric constant profile. Brush/arrow combinations and fitted dash alignment require
  08/17's **combined** provider: the isolated provider explicitly returns an error, never
  drops decorations or returns an empty-path success. Live corner metadata currently returns
  an explicit engine error until 06/08 compose source corner geometry before appearance.
- Format adapters call the pure vecfx evaluator through their exchange projection, never
  engine/UI. They must export filled profile paths, not a constant stroke-weight approximation.
- Combined providers should evaluate live corners first, width next, and decorations once;
  do not feed already-projected paths back through width evaluation.

## 00 / 01 app and preferences routing (exact hooks)

01 owns tool ID `width`, label `Width Tool`, alias `directSelection` in the existing colour
icon registry, available in Vector Illustration / All Tools. Add the `Tool::Width` variant
through 01. No shortcut is reserved here; 01 resolves Shift+W conflicts through the menu catalog.
00 adds `pub width_state: photocraft_ui_egui::width::State` to PhotocraftApp, initialized with
Default. Persist only `width::Options`, e.g. a serde-default `width_profiles` preference field;
copy it to/from `width_state.options` using the existing preference bridge. Never serialize
State/gesture/preview. Saved profiles are named absolute distances, bounded to 64 profiles and
128-byte names, with validation before use. Old `{}` Options load to defaults.

Every frame in `PhotocraftApp::logic` (also on disabled tool/focus/persona switches), get the
active selected shape IDs and call:

```rust
app.width_state.lifecycle(&app.session, &ids,
    app.ui.tool == Tool::Width && app.session.prefs().toolbar.persona == Persona::Vector,
    ctx.input(|i| i.focused), ctx.input(|i| i.key_pressed(Key::Escape)));
```

The persona uses 01's existing session toolbar preferences. IDs come from
`selected_layers()`, not path IDs.
In the Stroke/pressure panel or Width context UI:

```rust
app.width_state.panel(ui, &mut app.session, &ids);
```

Before changing the selected appearance stroke index, cancel, then set
`app.width_state.options.item = Some(index)` (None selects topmost). Call lifecycle with the
actual tool-enabled value **after** any panel hook too; panel display alone is not authorization
for a captured canvas tool to survive a persona/tool switch.

In `canvas::canvas_view`, after response/ViewXform creation and **before display pixels**:

```rust
let width_input = primary && app.ui.tool == Tool::Width
    && app.session.prefs().toolbar.persona == Persona::Vector && app.ui.dialogs.is_empty();
if width_input {
    let ids = app.session.active().map(|s| s.selected_layers()).unwrap_or_default();
    app.width_state.input(&mut app.session, &ctx, rect,
        |p| { let d = xf.to_doc(p); photocraft_geom::Point::new(d[0], d[1]) },
        &ids, true, 5.0 / f64::from(xf.zoom.max(0.01)));
}
let move_input = width_input || symbol_input
    || (primary && crate::move_input::canvas_input(app, &response, &xf));
```

`width_input` must also suppress legacy canvas_tool_event and paint_mouse delivery for that
frame. `input` consumes raw press/move/release and retains capture outside the viewport.
Do not deliver the same event twice. It re-reads Alt/Shift each frame; Escape, PointerGone,
focus loss, selection/document/revision changes cancel. Each new press captures IDs/revision;
release uses its actual coordinates, then one engine command. Space/Hand navigation must first
cancel the width capture. UI input coordinates are document pixels; graph coordinates are egui
points. For views with flips/HiDPI, provide the normal existing ViewXform rather than a new map.

At the beginning of `canvas::display_doc`, only for the active document:

```rust
if app.session.active_index() == Some(idx)
    && let Some(doc) = app.width_state.preview.as_ref() {
    return (std::sync::Arc::new(doc.clone()), app.width_state.generation);
}
```

The caller should cache the Arc by generation so a warm frame does not clone a whole preview.
Width state generation reserves bit 56, unused by the existing preview providers inspected
on this branch (Direct Selection uses 55, corners 57, gradients 58). Retain a unique tag
when combining later projection providers.
Overlay hook, gated by `ui.view.extras`:

```rust
app.width_state.paint_handles(&app.session, &ids, &painter,
    |p| xf.to_screen(p.x as f32, p.y as f32));
```

## Tests / GPU registration

New CPU/unit/kittest tests are compiled from the owned modules and filter `width_package`.
The engine also compiles one strict ignored GPU test (`width_gpu_profile_strokes...`).
00 adds this exact module to the serialized UI GPU binary after the router and field exist:

```rust
#[path = "../../src/vector_packages/width/app_gpu_tests.rs"]
mod width_profile_strokes;
```

The supplied full-app source assumes `Tool::Width` and `app.width_state` as above. It uses
actual app canvas input/display/readback, asserts RTX 5090/Vulkan/discrete/Rgba32Float/f16,
checks live preview changes pixels while Session is untouched, release parity max<=1/255
premultiplied, one undo, and Escape cancellation. It never creates a desktop window or reports
an absent/wrong adapter as a successful skip. **Not compiled or run on this branch:** core router
and test registration are 00-owned. The latest task speed rule prohibits GPU execution,
release builds/benchmarks and whole-crate suites. These gates remain integration work.
