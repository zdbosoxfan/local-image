## App fields and persistent preferences (00)

Add transient `pub trace_dialog: crate::trace_dialog::State` to `PhotocraftApp`,
initialized with `Default::default()`. Add this field to the existing persisted
`UiState` (and its Default implementation), retaining all old fields:

```rust
#[serde(default)]
pub trace_preferences: crate::trace_dialog::Preferences,
```

`Preferences` itself has serde defaults, `last_preset: Preset`, default Logo.
The dialog writes the preference when a user clicks a preset. Old settings `{}`
load; a reserved LineArt/Sketch last preset falls back to Logo until 25 arrives.
Use the shell's ordinary UI-state save flow; do not create another settings file.

Add this after ordinary jobs polling and compositing panel/dialog drawing:

```rust
if app.current_module != crate::Module::Compositing {
    app.trace_dialog.cancel(&mut app.session);
} else {
    crate::trace_dialog::show(
        ctx, &mut app.trace_dialog, &mut app.session,
        &mut app.ui.trace_preferences, &document_swatches,
    );
}
```

`show` observes running job state and recent completion summaries; it does not drain `poll_jobs()` events. Call
`State::cancel(&mut Session)` on persona changes and document close/replacement,
matching the existing tool cancellation flow. Focus loss/Escape/backdrop/Cancel
are handled by the modal. It owns independent zoom, pan and split state and never
changes the canvas view. The modal is resizable, using egui's Resize memory.

library when that owner supplies it. This branch's existing Swatches panel only

## Engine interfaces and exact parameters

Exports in `photocraft_engine::vector_packages::trace_output`:

```rust
pub use pc_trace::{Params, Preset, Trace};
capture(&Session, Option<LayerId>) -> Result<Capture>
check(&Session, &Capture) -> Result<()>
source_bounds(&Document) -> Result<Rect>
trace(&Document, &Capture, &Params, &Output, f64, &JobCtx) -> Result<Preview>
start_preview(&mut Session, &Capture, &Params, &Output, f64)
    -> Result<(Started, std::sync::mpsc::Receiver<Preview>)>
prepare(&Document, &Preview, &Output, &JobCtx) -> Result<Prepared>
publish(&mut Session, &Capture, Prepared) -> Result<Value>
```

Use public commands from UI for journaling, not `publish` directly:

```json
{
  "layer": 42,
  "capture": {"document":1,"revision":3,"layer":42,"active":42,"targets":[42]},
  "params": {"preset":"pixel_art","max_colors":6},
  "output": {"expand":true,"work_path":false,"palette_edits":[
    {"from":[255,0,0],"to":[0,0,255]},
    {"from":[255,255,255],"to":null}
  ]}
}
```

`layer.vectorize` accepts the existing omitted capture/output contract (captures
at dispatch, default output). UI supplies its captured token; stale revision,
active document or targets fail without history/revision/journal changes. Output
cache preparation and connectivity run in the worker before one `Session::edit`.
Result `{group,colors,nodes,shapes}` or `{path,colors,nodes}`. Make Work Path is
BlackWhite only and stores a unique named path plus `doc.work_path`, one undo.
Expand uses fallible `photocraft_pathops::regions`, retaining counters. Ordinary
output is one compound per paint; repeated paints created by palette merging are
normalized with the existing fallible visible-region Pathfinder Merge.

`layer.vectorize.preview` accepts the same capture/output plus `scale:0.01..1`.
Requests with the same document/source key cancel previous previews using
`jobs::run_latest`. No document lock or journal. Return fields:
`{capture,trace,scale,scale_xy,bounds,elapsed_ms}` (pixel buffer fields are empty
for automation). UI calls `start_preview` on the same T1 command/job path, with a
request-owned typed mailbox delivering the full `Preview` on the worker. Pixels
and paths stay out of the job's recent JSON history; completion retains only a
small summary. This avoids serializing millions of pixel numbers or reparsing
path JSON on the UI thread. Cancel/replacement drops the receiver. A canceled
job's queued result is discarded before mailbox consumption.
Paths use preview pixel coordinates; `bounds` is `[x,y,width,height]` in document
pixels and exact `scale_xy` accounts for rounded odd crop dimensions. Source and
result are straight-alpha RGBA8 buffers. The dialog shows the last completed
preview while dragging, starts reduced requests at 0.25 while controls move, then
requests 1.0 on release. Job-ID tracking publishes only the newest result;
revision/target checks discard results when the document was edited meanwhile.
The public preview query retains T1's detached snapshot behavior after an edit.

## Providers 25 / 26 / 27

These providers are **empty engine slots on this baseline**, and Params has no
cleanup/layering/stroke extensions. Centreline/Sketch/LineArt, Cutout, prefilter,
snap-lines/circles/symmetry and auto-upscale controls are visibly disabled with
tooltips. No unavailable algorithm is advertised as successful. When 00 merges
the corresponding provider/Params contracts, extend the owned controls and
trace/output shape construction for their actual stroke/layering types. Do not
invent alternative algorithms inside the dialog/output package. BlackWhite,
Logo, FewColors, Silhouette, Photo and PixelArt are executable T1 modes today.
