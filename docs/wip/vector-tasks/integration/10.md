```rust
// UI lib.rs:
#[path = "vector_packages/constructive.rs"]
pub mod constructive;
// PhotocraftApp field/constructor:
pub constructive_state: constructive::State, // Default::default()
// 01 chooses Some(Tool) only for its active vector tools:
constructive_state.set_tool(tool);
constructive_state.set_targets(session.active().map_or_else(Vec::new, |s| s.selected_layers()));
constructive_state.frame(&session, &ctx, active); // Every app frame, even hidden context bar
// canvas input, before ordinary tool button dispatch:
constructive_state.canvas_input(&mut session, &response, &xf);
// Consume ordinary buttons while this tool is active, preventing dual gestures.
// canvas::display_doc, before the committed-document fallback:
if active && session.active_index() == Some(index) {
    if let Some(doc_and_key) = constructive_state.display_document(&session) { return doc_and_key; }
}
// CPU/GPU canvas and Navigator use that same detached display document.
// ToolEvent automation route (ordinary input uses canvas_input's own pointer capture):
constructive_state.pointer(&mut session, event, modifiers, zoom as f64);
// Context/overlay, with normal Extras visibility and view transform:
constructive_state.context_bar(ui, &mut session);
constructive_state.draw_overlay(&painter, &|p| xf.to_screen(p.x as f32,p.y as f32), zoom as f64);
```

The generated patch gives the actual call-site anchors in this baseline's lib.rs,
canvas.rs and panels.rs. Replace `constructive_enabled`/Pen sentinel there with 01's
actual active-tool match, while retaining the unconditional lifecycle call. Tool IDs:
`ShapeBuilder`, `Knife`, `Scissors`, `LineCut`, `Contour`, `Smooth`, `PathEraser`, `Join`.
Labels are `Tool::label()`; 01 owns icons/shortcuts/Tool::ALL registration. Numeric distances honor document px/pt/mm/in and DPI. No new
persisted settings or enum/document fields are required. Cancel on persona/tool,
selection, document, revision, focus or Escape changes. Do not keep delivering legacy
Pen input when the constructive capture consumes the pointer.

The journaled transaction commands are `path.builder.commit`, `path.cut.commit`,
`path.erase.commit`, `path.constructive.commit`, all sharing `Request`:

```json
{"document":1,"revision":3,"layers":[7,8],
 "action":{"kind":"builder","faces":[0,1],"remove":false,"style":7}}
```

Other action tags: `knife {points}`, `line_cut {from,to}`,
`scissors {layer,subpath,segment,t}`, `contour {delta,join,miter}`,
`smooth {points,radius,amount}`, `erase {points,width}`, `join {points,tolerance}`.
`path.constructive.preview` has the same parameters and `journal=false`.
`join` option strings are `round|miter|bevel`. Numeric budgets are enforced by the
engine, not just the controls. Prepared output paths/caches cannot be supplied by a
caller. UI skips no-op dispatches so missed/partial cuts do not create history/journal.

Keep existing V1 `path.offset`, `path.pathfinder`, `path.smooth`, `path.join`,
`path.splitAt`, `path.boolean` IDs for menus/automation; do not register duplicate
geometry IDs. The new captured transaction shell uses those same V1 geometry APIs,
adds staleness/bounds/appearance-safe preparation, and handles create/delete in one
edit. Non-destructive geometry remains existing `path.boolean {keep_compound:true}`
with ordered components, and `path.finishCompound` for baking. Builder inherits the
first touched face's top source style; untouched faces inherit their top source in
paint order. Knife/scissors/offset/eraser preserve each source style and sibling slot;
Join uses the bottom touched source's style. Combined Builder/Join inputs must share
a parent, avoiding changes to group isolation/masks across unrelated parents.
Coincident Scissors/Contour curve hits resolve to the top selected source in paint order.

Appearance is rendered by the existing 08 `CompiledAppearance` bridge, preserving
metadata and legacy mirrors. `preview_with_projection` accepts 11/17's stroke provider.
The default `NoProjection` rejects unsupported width/brush projections atomically;
00 must route an installed provider for those future combinations instead of dropping
paint. Corner projections are baked on geometry replacement and stale live/corner/PSD
geometry metadata is cleared; clip/constraints/paint/masks/effects stay with the style.
Caches are bounds-clipped and their aggregate tile allocation is checked <=512 MiB
before any output renders. Geometry budgets: 128 targets, 8192 aggregate input knots
and knots per output path, 4096 stroke points/output faces, |coordinate|<=1e6,
offset<=1e5, miter<=1000.

## Test registration and remaining app gates

`pc-ui-egui/tests/gpu/main.rs` (already done by the rehearsal patch):


It takes the existing GPU binary mutex, uses an offscreen PhotocraftApp, asserts RTX
5090/Vulkan/discrete/Rgba32Float/f16 support, drives real pointer frames, compares
live preview/release/undo/cancel to CPU pixels with premultiplied max diff<=1/255,
and checks one journal/undo. GPU gate is supplied and compiled, not run by this job
under the latest speed rule. Native tool/router integration, real-GPU execution,
release pointer-frame performance, V1-Q full EDT/corpus and external/manual QA
remain coordinator acceptance; no successful skip or performance claim is made.

## Baseline build defect (25/27)

The single requested native workspace check fails before the new code:
`crates/pc-trace/src/cutout/compose.rs:48`, E0063, missing `Trace.strokes`.
Package 00/27 must apply this exact compatibility fix to their owned source:

```diff
-    Ok(Trace { width: map.width, height: map.height, layers, nodes })
+    Ok(Trace { width: map.width, height: map.height, layers, nodes, strokes: Vec::new() })
```

Cutout emits filled color paths, so the additive centreline field is empty. Only the
disposable verification copy receives this fix; package 10 does not edit pc-trace.
The report distinguishes native check failure from rehearsal clippy/test results.
