```rust
#[serde(default)]
pub layering: cutout::Layering,
```

Refactor the existing T1 preprocessing/segmentation/palette block into the common internal frontend accessor; route after palette assignment and BEFORE `ir::stack_colors`:

```rust
if params.layering == cutout::Layering::Cutout {
    return cutout::evaluate(&seg, params, BOUNDARY_BUDGET, &cancel);
}
```

`evaluate` is crate-visible and accepts `&ir::Segmentation, &Params, usize, &dyn Fn() -> bool`. The public cutout wrapper currently uses package-owned `cutout/prepare.rs`, which calls the SAME existing T1 frontends and palette implementations. Once factored, replace that wrapper's prepare call with the shared accessor; delete the compatibility orchestration. Do not route the main T1 function to the public wrapper recursively.

Without common frontend factoring, 28 can choose `pc_trace::cutout::trace_with_cancel` at its existing job call site. Stacked continues to call T1. Pixel selection, smart-object rendering, source resampling and coordinate offsets remain the existing command's responsibility.

GPU parity with CPU alone does not prove this requirement. The supplied seam gate is explicitly run and reported separately; do not hide it in an adapter skip or change the tolerance.
