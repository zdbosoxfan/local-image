## Engine registration (00)

`vector_packages::anchor_tools` is compiled. Append this single line to the aggregate
`vector_packages::specs()` in `crates/pc-engine/src/vector_packages.rs`:

```rust
out.extend(anchor_tools::specs());
```

This adds `path.anchor.curvatureCommit`, journal=true. Add/Delete/Convert reuse the existing
`path.node.edit` command and operations `Insert`, `Delete`, `Convert`, `Handle`, `Bend`.
New Curvature paths reuse `path.penCommit`. There are no duplicate registrations for legacy
path command IDs. Pure hover/preview APIs below never call Session::edit or journal.

```rust
use photocraft_engine::vector_packages::{anchor_tools, node};
anchor_tools::Capture::begin(&Session, Vec<node::Target>, convert_live: bool)
anchor_tools::AnchorGesture { capture, target: usize, operation: node::Operation }
AnchorGesture::preview(&Session) -> Result<Document>
AnchorGesture::commit(self, &mut Session) -> Result<Vec<node::Target>> // remapped selection
anchor_tools::node_under(&Document, &[node::Target], Point, tolerance: f64)
    -> Result<Option<NodeHit>> // {target: candidate index, knot:[subpath,knot]}
anchor_tools::segment_under(&Document, &[node::Target], Point, tolerance: f64)
    -> Result<Option<SegmentHit>> // same, plus exact V1 t
anchor_tools::preview_curvature(&Session, &CurvatureCommit) -> Result<Document>
anchor_tools::commit_curvature(&mut Session, CurvatureCommit) -> Result<Vec<node::Target>>
photocraft_vector::curvature_fit::fit(&[(Point, bool /* corner */)], closed: bool)
    -> Result<Path, String>
```

Existing-curve command example (mandatory document/revision; all indices are zero based):

```json
{"document":42,"revision":7,
 "destination":{"kind":"curve","target":{"name":"layer","layer":12,"anchors":[]},"subpath":0},
 "targets":[{"name":"layer","layer":12,"anchors":[]}],
 "points":[{"at":[20,40],"origin":0},{"at":[70,100],"corner":true,"origin":1},
           {"at":[120,40],"origin":2}],"closed":false,"convertLive":false}
```

`origin` identifies a retained knot, including moved knots. Inserted clicks use null/absent
origin; deleted origins disappear. Origins must be unique and in range. Corner indices on
the changed subpath remap through these identities; other subpaths keep their op/order.
Deleting the last point removes that subpath and shifts later corner subpath indices in
the same transaction. Shapes, vector masks, work paths and saved paths use the same evaluator.

The UI supplies `targets` in existing-curve requests: the complete immutable selection from
press. The destination must be present and every captured target is validated before any
cache is prepared. The response retains other targets and remaps only the edited one.
Older single-target command requests may omit `targets`; they validate the destination.
New-shape requests have no captured existing targets or old knot identities.

Inputs/results are finite and bounded to 1,000,000 document pixels and 16,384 points;
anchor captures allow 1..64 curves. Both document ID and revision are mandatory for
Curvature; anchor gestures pass both to the existing node command. All captured targets
are checked before preparing detached caches or publishing one edit. Errors preserve
document/revision/history/journal. Original document and settings schemas are unchanged.

## Rendering (00 / 06 / 08 / 11 / 17)

Install the same combined corner/appearance/stroke projection renderer in both:

```rust
node::install_renderer(render_cache)?;
anchor_tools::install_renderer(render_cache)?;
// render_cache: node::RenderCache =
// fn(&Document, &ShapeLayer, &VectorData) -> Result<Surface>
```

Without it, ordinary Curvature edits project corners through 06 and render through
CompiledAppearance. Unsupported decorated strokes fail explicitly through NoProjection.
Node edits continue using 03's existing provider contract. Prepared Curvature caches are
bounds clipped, with a 512 MiB appearance-cache cap. Ordinary shape edits additionally
preflight a 64 Mi-pixel clipped cache cap. Do not substitute a constant-width approximation
for unsupported appearance combinations. Cache providers retain their own total budgets.

## App hooks (00)

The public UI module is `photocraft_ui_egui::anchor_tools`. State is stored transiently in
egui memory; persistent `Options` has serde defaults. At tool activation, after the existing
Tool/persona routing, call:

```rust
anchor_tools::activate(app, ctx, Some(anchor_tools::Tool::AddAnchor));
// likewise DeleteAnchor / AnchorPoint / Curvature; None deactivates
```

Call `anchor_tools::frame(app, ctx)` on every app frame, including frames when canvas routing
does not run. Tool/module/persona/document/revision/focus changes and modal dialogs cancel.
Inside the active canvas, **before ordinary tool input and before canvas pixels are drawn**:

```rust
if anchor_tools::route(app, ui, idx, &xf, canvas_rect, &shown_handles) {
    // skip normal tool input for this canvas; continue drawing the canvas
}
```

`shown_handles: Vec<anchor_tools::ShownHandle>` refers to the front-first candidate indices
from `selected_targets(&Session, &DirectSelection, vector_mask: bool)`. Pass only the handles
03 actually displays (selected anchors and the two controls of the selected segment,
excluding retracted controls). **03's `shown_handles` is currently private**: 00 should
expose it or adapt the existing display list at the call site; this package does not edit
03's file. The app route accepts this list rather than hitting hidden handles.

For vector-mask routing on non-shape layers use the lower-level `input` entrypoint with
`selected_targets(..., true)`. 03's current `node::Target` chooses the shape path before a
mask when both exist on one layer: an explicit mask-on-shape selector must be added by 00/03
before routing that case here. Saved paths may be supplied as explicit node::Target values.
`route` currently selects ordinary shape layers plus the selected work path.

Add at the start of the shared canvas display-document provider (and scaled geometry path):

```rust
if let Some(shown) = anchor_tools::display_doc(app, idx, ctx) { return shown; }
```

This returns `(Arc<Document>, generation)` with prepared caches. Preview is never put in
Session. Overlay painting honors `app.ui.view.extras`; filled pixels always use the ordinary
CPU/GPU canvas. The app route requests repaint while a gesture is active.

The app route copies returned remapped anchors into 03's existing selection fields. Lower-level
input hosts consume `State.last_targets` after a finished anchor gesture to update their own
selection model. `cancel` clears pending output; successful release stores it after cancellation.

`AppBridge.state.needs_conversion` requests 03's existing Convert to curves modal. Copy
`state.pending_conversion` into the modal's pending record before opening it (modal frames
cancel tool state). On confirmation restore that record and call
`State::confirm_conversion(&Session)`. It checks the captured document/revision and replays
the original press/target IDs, rejecting stale context. Cancellation discards the request.
The pure input API accepts paint arguments; wire the current vector fill/stroke proxies
there when 46 supplies them. The convenience app route defaults to a simple stroked curve.

Curvature drawing is one detached click sequence: Esc/Enter **between presses** finishes an
open path; Esc/Enter during a captured point drag cancels the whole unfinished sequence.
Clicking the first point closes and commits; Alt-click/double-click toggles; dragging an
existing point updates the curve; Delete removes the last touched point. Editing a previously
committed curve finishes its drag/toggle/deletion as one separate gesture. This batching
deliberately differs from the pinned VC tool, which journals each newly placed point.
After an existing-point drag/toggle, the selected point remains available for Delete or
another drag. Its knot origins and freshness guards advance to the committed revision;
the next press captures the current complete selection again. Esc/Enter clears that selection.

## Pen auto add/delete preference (00 / 04)

Candidate lists contain selected editable curves only, front first. On Pen hover, first
call `node_under`, then `segment_under`; a node suppresses segment insertion at endpoints.
Use the same helpers at press, start an AnchorGesture, preview, and commit on release.
For the Illustrator **Disable Auto Add/Delete** preference, skip both helpers/gestures
when true and let 04's normal Pen input continue. Add that bool with a serde default of
false in 01/00's existing Pen preference model, not a second settings store. The dedicated
Add/Delete tools continue working regardless of this preference. Do not query unselected
objects or copy another insertion/deletion implementation into Pen.

## Tests and remaining integrated gates

The CPU tests and two full-app GPU tests are compiled in their owned modules. CPU names
start `anchor33_`; `anchor33_gpu_` are explicitly ignored because the final speed rules
prohibit GPU runs. No desktop windows are opened by the harnesses.

The GPU tests require actual app hooks above and assert RTX 5090 + Vulkan + DiscreteGpu,
Rgba32Float accumulator and float canvas support. They test detached preview/release,
premultiplied byte max-difference <=1, cancellation, undo and one journal entry per gesture.
The Curvature gate covers both a new click sequence and dragging an existing point followed
immediately by Delete, so it also requires the registered existing-curve command.
Running them without the hooks fails the `routed` assertion. They do not claim an isolated
widget is the full app. For serialized GPU milestone execution, register the existing file
in `tests/gpu/main.rs` (remove the local test module if consolidating):

```rust
#[path = "../../src/vector_packages/anchor_tools/app_gpu.rs"]
mod anchor_tools_app;
```
