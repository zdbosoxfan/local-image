## Registration and model

The engine `vector_packages::symbols::specs()` slot is already aggregated by the
foundation. The new commands are `symbol.create`, `.place`, `.update`, `.editMaster`,
`.rename`, `.delete`, `.detach`, `.setInstances`, `.list`. All editing commands require
`document` (DocId) and `revision`; preview helpers are non-journaled. `.list` alone is
read-only. Parameters and results are documented at the owned command definitions.

`LayerContent::Symbol(SymbolInstance)` and `FORMAT_VERSION=2` plus no-op v1→v2
migration must activate together. Native cached surfaces use the existing Sink/Fetch,
content hashes, compression/depth/ID remap and directory garbage collection.
The lower-level native/file adapter provider is `pc-doc::vector_design`:

```rust
symbol_validation::document(&Document) -> Result<(), SymbolError>
symbol_validation::validate(&[SymbolDef], &[Layer]) -> Result<(), SymbolError>
symbol_expansion::expand(&Document, &[Layer]) -> Result<Expansion, SymbolError>
symbol_expansion::expand_scene(&exchange::ImportedScene) -> Result<Expansion, SymbolError>
symbol_expansion::expand_layers(&[SymbolDef], &[Layer]) -> Result<Expansion, SymbolError>
// Expansion { layers: Vec<Layer>, transforms: BTreeMap<u64, Affine> }
```

The path module registration intentionally compiles the **same data-only source**
owned by 15 under pc-doc; there is no pc-doc→pc-engine crate dependency. Package 00 may
relocate these two modules into pc-doc after ownership is reconciled, preserving API
names and engine reexports. No manifest/dependency edits are needed.

Expansion preserves each enclosing instance layer's blend/masks/effects and replaces
its content with an isolated ordinary group. Template objects have fresh LayerIds;
the transform map carries composed geometry transforms to apply exactly once. A file
adapter must consume those transforms in its own geometry/paint projection; it must
not treat the untransformed projected tree as rendered output. Master caches are not
an authoritative source for geometry. Master names and SymbolIds remain separate from
ordinary LayerIds.

## UI and compositor hooks

Register the owned panel as `crate::symbols`; add serde-default `UiState::symbols`.
Add the ordinary movable `dock::Tab::Symbols`, initially hidden, opened by
`window.panel.symbols`. Existing default layouts/tab ordinals stay stable. Invoke
`symbols::frame(app, ctx)` before canvas painting even when the panel is hidden;
`symbols::canvas_input` captures native presses before Move; automation dispatch also
calls `symbols::pointer`. `canvas::display_doc` prioritizes detached symbol previews.

The patch covers every current exhaustive content match found by compiler checks:
doc kind/surface, format, compose/proxy, GPU planner, PSD fallback, engine move,
transform/rasterize, image/depth/color conversion and canvas geometry. Existing GPU
content planning reads `Layer::surface`; symbol cache revisions/transforms now enter
its structure key. Release rebuilds semantic instance caches; previews never publish.
Cross-document copy calls `transfer_definitions` before color/depth conversion and
imports the remapped master closure in the same Session::edit as the copied layers.
After applying the destination offset it validates again before changing the active
document or publishing, so out-of-range placements remain atomic errors.

Register the owned full-app GPU module in the existing single GPU binary so it shares
`gpu_lock()`. The strict engine GPU test is already under the owned module. Do not
replace the RTX/Vulkan/discrete/Rgba32Float assertions with skips.
