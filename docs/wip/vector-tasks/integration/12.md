Package owns pc-text/on_path, engine/path_text, UI/path_text and their fixtures.
Core module declarations, app routing, native reload, ordinary type edit routing,
localisation catalogs and PORTS remain package 00's serial integration work.

`Layer.vector.on_path` already has serde defaults and native serialization.

## Existing type edits and cache refresh

`path_text::refresh(doc: &Document, t: &mut TextLayer, path: &PathText)
-> Result<on_path::PathLayout>` is the shared projection hook. Call it whenever
`layer.vector.on_path` is Some; otherwise use the existing ordinary type refresh.
The patch above covers the ordinary type.edit/style helper. Apply that same branch
in type_extra_cmds::with_text, font replacement loops, transform/canvas cache
rebuilds, edit-menu text moves and commands::refresh_text_caches. Take the metadata
before borrowing TextLayer if needed. Propagate errors from Result call sites;
reload/display callers must surface a structured warning instead of displaying
straight text. Never silently remove on_path to make an edit work.

Path text uses the ordinary CharStyle/paragraph shaping service and sets only a
cloned layout source to Point so frame wrapping cannot discard the path flow.
Source TextLayer remains editable, with byte ranges, styled runs and transform.
The path command's replacement uses type_cmds::replace_text for the changed UTF-8
range; no second run editor. Existing Type/Vertical Type path clicks inherit the
context font, size, foreground and orientation. The UI hook consumes path drafts
before the legacy point/frame editor sees keys/pointers. Ordinary point/frame
editing and existing caches keep their established route.

For existing `type.convertToShape`, route an on_path target to guarded
`type.path.convert` before the ordinary straight-text outline implementation.
`type.createWorkPath` must obtain projected painted outlines from pc-text's
on_path service and preserve nonzero winding. The engine adapter `curves.rs`
shows exact quadratic-to-cubic elevation; no new shaper is involved.

Commands (captured document/revision, all target IDs preflighted, one history edit):

```json
{"command":"type.path.commit","params":{"document":1,"revision":4,"edits":[{"target":{"kind":"text","layer":7},"path":{"path":{},"start":0.25,"end":1.0,"flip":false,"align":"baseline"},"text":"ABC"}]}}
{"command":"type.path.convert","params":{"document":1,"revision":5,"layers":[7]}}
```

The nested path `{}` above is a placeholder for an existing serialized native
Path, not a valid empty geometry request. New target is `{"kind":"new","curve":7}`
with optional `style`, `orientation` and `paragraph`; existing targets reject run-wide style
orientation or paragraph replacement. Bulk targets are unique, locked ancestors are
respected, previews never edit/journal, cache rectangles clip to document bounds.
Equal brackets are an empty span with overflow; closed start>end crosses the seam;
flip reverses traversal in that span without reflecting glyph shapes. Overflow
is explicit in PathLayout and in the canvas/context indicator.

## Shaping membership limitation / shared bridge

The current shared TextLayout exposes glyph positions and logical clusters but
not their membership. Placement preserves glyph IDs/styles/offsets and associates
them in original line space; tested bidi, ligature, combining-mark and Japanese
fixtures pass. Unusual font offsets crossing a logical cluster/line boundary can
be associated with the neighboring cluster. This remains an accuracy limitation.

For exact membership, 00's shared shaping bridge must expose one source-cluster
**index** per PlacedGlyph, from the existing `layout.rs` run/slot cursors, in the
same order as TextLayout.glyphs. Byte ranges alone are insufficient because caps
expansion can create distinct clusters with equal ranges. Preserve the mapping
through vertical placement. Then wire that index map into the owned projection
instead of its position matching. This calls for shared shaping output and
owned projection changes; it is not implemented or claimed as a passing gate
here. No competing layout.rs/model field changes or second shaper were added.

## Exchange / package 13, 14, 22 and 23

Adapters operate on `vector_design::exchange` and doc/text types. They must not
import engine/UI. Add a local V1 ArcPath-backed implementation of pc-text's Curve
trait, then call:

```rust
photocraft_text::on_path::layout(&mut text_engine, text, &curve, path_text, dpi)?;
photocraft_text::on_path::validated_outlines(&layout, &text.transform)?;
```

These APIs share shaped glyphs, orientation and colors with the cache/converter.
SVG import maps textPath startOffset to a fraction of total arc length, SVG
method=align to the default placement; side/flip and alignment retain metadata
where representable. Export must use the preserved styled model or projected
painted outlines and report unsupported combinations through exchange warnings.
PDF uses these outlines; no text shaping in adapters. Warp Text combined with
path text currently returns an explicit error, rather than flattening silently.

PSD 23: no native PSD live textPath writer is implemented by this package. Preserve
the raster cache in PSD, and emit an exchange VectorWarning for every layer with
on_path (`feature: "text-on-path"`, `object: Some(layer.id.0.to_string())`,
`message: "PSD does not preserve editable text-on-path; rendered pixels retained"`).
Do not export ordinary straight TySh as a faithful replacement. refresh clears
stale psd_raw; the commit removes old TySh blocks. Native .pcraft preserves metadata.
