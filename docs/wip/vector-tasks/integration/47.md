# Package 47 — one shared handler across personas

This supersedes the reduced legacy Pen/basic-shape wiring portions of handoffs 02/04.
Read [the audit and validation report](../../CODEX-REPORT-shared-tools.md) for scope,
compatibility, test counts and the deferred GPU/performance gates. Feature code is compiled
on this branch; no dependencies or manifests changed. The final task rule reserves UI
menu/router wiring for this serial handoff.

## Exact registrations for 00 / 01

`pc-ui-egui::shared_tools` and `pc-ui-egui::vector_packages` are registered publicly;
`pc-engine::shared_tools` resolves all baseline IDs. Do not re-register a second copy of
these modules under another path. The UI aggregate registers drawing, pen, pencil, corners,
appearance, path_text, snapping and layout. Existing direct_select remains the sole Node
implementation. Existing root bridges for other feature packages stay intact.

Keep one `crate::shared_tools::State` in the host runtime. It is intentionally not Clone or
Serialize: do not put its document/gesture state in egui temp-data. Persist feature options
through the package-01 tool settings with serde defaults. `ToolOptions::pen_options` is
already defaulted and available to the legacy Pen façade. State.pen.options uses the same
Options type; synchronize persistent options at tool activation/context updates, not by
cloning runtime State. Use State::deactivate(app) on host deactivation; it cancels the existing Node capture
and legacy Pen façade alongside the shared state. Activation/input perform that same
cancellation on persona/tool/modal/focus changes.

Pixel supports the 29 additional IDs in `pc-engine::shared_tools::SHARED_ADDITIONS`;
`toolsets::tools_for` and `supports` include them. Append the IDs to appropriate flyouts
using the package-46 persona layouts. Frozen ALL_TOOLS, the existing five built-in Pixel
layouts and all owner-approved shortcut defaults remain unchanged. Do not replace raster
Pencil or Gradient IDs with VectorPencil/VectorFill: architecture §5 explicitly keeps their
output families distinct. The richer geometric tools must be offered in Pixel too.

Call `State::activate(app, canonical_id, persona)` before context controls and input.
Tool IDs resolve through the common engine registry; `shared_tools::handler(id, persona)`
returns the very same function for both personas. The test guards every shared ID.
Persona chooses creation defaults (Pen work path versus shape) only; users can override
`state.shape_mode`. Masks use the existing vector_mask_target flag. Existing selected
curve continuation keeps its original fill/stroke. Shape fill/stroke uses the normal foreground/background options and the validated
shape.design.create payload. Stroke-only shape families and Pen Line use the common
foreground-stroke defaults; legacy Line weight remains honored.

Inside the existing canvas capture/router, use ONE of these integration paths:

- `State::input(app, ui, id, persona, &xf, canvas_rect)` handles native geometric tools
  with raw press/motion/release events, current modifiers and release outside the canvas.
  Honor its ownership bool to suppress old dispatch exactly once. Node calls the existing
  direct_select frame/input functions; TextOnPath preserves its own keyboard/text routing.
- Feed recovered tablet/automation events into `State::pointer(app, ToolEvent, modifiers)`
  exactly once after activation. Preserve the pressure sample. A pointer-only host must
  call the normal feature keyboard routes for Enter/Escape and text input separately.

The raw adapter returns false for established Move, PathSelection, CustomShape, Type,
VerticalType, Crop, Eyedropper, Hand, Zoom and raster paths, so their existing capture,
IME, pan and scrub logic continues. ArtText/FrameText default through the same Type
creator; the adapter owns those aliases and constrains ArtText creation to a point.
Do not route a true ownership result to the legacy canvas dispatcher as well.
Do not merely change Tool::from_name aliases: new shape/corner/paint/layout IDs must
select the common feature state and controls.

The existing vector_ui::pen_down/move/up/commit entrypoints now delegate to the full
package-04 core and load old serialized knots. Its public `pen_pointer(app, event, mods)`
accepts current modifiers. Replace old canvas calls that lack modifiers with this façade
or the shared State input at the serial boundary. Retain existing Ctrl/Cmd Direct Selection
delegation, Ctrl+Enter path.toSelection behavior and its overlays. When using shared State,
perform the existing Node delegation before ordinary Pen input. Do not pass Ctrl/Cmd
Node gestures twice to the Pen and Node captures. The old tool-switch auto-commit in the
shell must become cancellation for an unfinished gesture, consistent with the task's
persona/tool switch rule; switching tools must not publish a draft.

`State::context` delegates full Pen/shape/Node/Pencil/Corner/Fill/path-text controls.
Package-34 transformations and package-32/33/35/36/41 tools keep their already merged
feature APIs and menu defaults; bind those same providers from either persona when
exposed. Do not add reduced Pixel variants of their algorithms.

## Detached previews / GPU integration for 00 / 09

Use borrowed `State::preview() -> Option<(&Document, u64)>` as a transient compositor
input. `State::shape_preview() -> Option<(&Layer, u64)>` exposes the live-shape detached
layer. Use that layer with the ordinary transient layer plane, or prepare a detached
document only when its generation changes; never call preview_document each idle frame.
Pen reuses its preview document and inserted layer ID across motion and tracks path
changes with a small generation rather than a whole-path equality clone.

Render native shapes/paint/text with the normal document compositor and GPU preview
cache. `State::overlay` draws controls; it is not a substitute for the actual GPU fill,
transparency, corners or text projector. For Node consume the existing borrowed
`direct_selection.preview_doc` with its existing generation. Install the feature 06/08
geometry/projector providers before offering enhanced corner/appearance handles. A
missing exact geometry/projector provider is an error, not an empty success or approximate
acceptance. The shared shape adapter propagates snap query failure and cancels before
committing; the old infallible drawing API wraps that same implementation.

Package-07 snapping cache is built once per captured revision, and Pen/shape release
re-queries raw position using current modifiers. Real on-ray targets now take priority over
an angle-only guide. Manual Shift construction stays active with automatic angle guides off. Integrate the existing manager/settings
and guide painter at the common boundary, setting State.snap_exclusions for edited objects/work paths before capture. Raw input refreshes physical
pixels-per-point scale from egui, and State::overlay paints its retained SnapResult guides.
Pointer-only tablet/automation hosts supply State.pixels_per_point when using another
display scale; None defaults to 1. Legacy snap_ui remains
for raster/layer operations until the serial shell routes those contextual operations
through the same appropriate richer provider. Do not claim complete smart-guide app
acceptance before that routing and the hardware measurements below.

## Required deferred acceptance

Owner SPEED RULES explicitly prohibit this builder from whole-crate suites, GPU acceptance,
release builds and benchmarks. At an approved integration milestone, run the serial
real-app checks from feature handoffs, including package 46 shortcuts and lifecycle
cancellation, then measure before/after Pen/shape/Node drags on a large document using the
real RTX 5090 Vulkan device. Report interactive frame times and allocations/cache behavior;
llvmpipe, skipped adapters or image equivalence alone do not count.

`vector_packages/pencil/gpu_tests.rs` is preserved but is no longer imported by the newly
registered production Pencil module. It was a package-05 target/ registration rehearsal
with temporary app.vector_pencil_enabled and app.vector_pencil fields absent from this
branch. Migrate its app pointer assertions to the shared runtime and the actual activated
VectorPencil ID, remove the rehearsal sentinel, and register the migrated acceptance in
the serial GPU suite with its common GPU lock. Keep the real RTX 5090/Vulkan/float-target
assertions. No package-47 GPU result or new performance timing is claimed.
