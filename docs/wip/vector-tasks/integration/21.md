## Common projection and font dependencies (00 / feature owners)

`export::Projection::layer(&Document, &Layer) -> Result<Option<Layer>>` must
return the same ordinary detached replacement used by display, retaining layer
ID/compositing envelope and clearing evaluated metadata. Corners, path text,
live geometry, symbols, width/brush/arrows and non-object stroke gradients
require that common provider. Missing providers fail explicitly; a stale cache
is never used as proof of supported vector export. Native ordinary paths and
multi-paint stacks are written directly. Unsupported appearance/pattern paint
uses the already public package-08 bounded CompiledAppearance renderer and
normal compositor, with one raster warning. No duplicate evaluator is present.

Install the engine provider once:

```rust
type Provider = fn(
    &Document, &ExportScope, &ExportOptions, &mut ExportContext<'_>
) -> photocraft_pdf::export::Result<ExportedVector>;
photocraft_engine::vector_packages::pdf_export::install_provider(provider)
    -> Result<(), Provider>;
```

The provider supplies `cx.projection` and delegates to `export_with`, preserving
`cx.cancelled` and the process's existing shared pc-text engine. The pure adapter
convenience entry point creates a bundled-font engine; the command uses the
process font database. Package 15's documented shared model activation must
land first: its source is merged here, but the real shared LayerContent still
lacks Symbol. Package 09 also needs its Symbol projection match updated before
that activation compiles in the real app.

Full embedded Unicode needs a **pc-text-owned additive source-mapping API**:
each `PlacedGlyph` must expose the UTF-8 source range captured from Parley's
actual positioned cluster during `layout` generation, plus a documented empty
range for continuation/mark glyphs. Retain visual order, bidi, ligatures and
multiple glyphs per cluster; do not infer source order from glyph IDs or pen
advance. Also expose resolved design-space variable coordinates so krilla's
instance agrees with native outlines. The current adapter embeds only exactly
unique one-glyph/one-cluster layouts with matching public positions and default
normalized coordinates. It uses authoritative pc-text outlines and warns for
ambiguous mappings, variable instances, vertical/warped type or restricted
font embedding. Faux-bold/non-antialiased styling uses the existing raster
renderer with a warning. These fallbacks preserve appearance, but do not meet
the entire positioned/subset text acceptance for arbitrary shaped text.
