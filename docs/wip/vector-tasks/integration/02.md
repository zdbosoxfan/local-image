## 00: geometry registration

In `crates/pc-vector/src/lib.rs`, beside `pub mod shapes;`:

```rust
pub mod design_shapes;
```

Replace the bootstrap path-module declaration at the top of
`crates/pc-engine/src/vector_packages/drawing.rs` with:

```rust
pub use photocraft_vector::design_shapes as geometry;
```

Until that registration, the owned engine slot includes the **same** generator source by `#[path]`.
This allows the engine commands and independent tests to compile without editing 00-owned lib.rs.
It is a temporary module-registration bridge, not a second geometry implementation or document tree.
The existing engine aggregate already calls drawing::specs(); no extra command registration is needed.
All four IDs are installed: `shape.design.create`, `.set`, `.convert` (journal=true), `.preview` (false).
Every call requires `{document:u64,revision:u64}` captured at begin. Create also takes `{design,above?:id}`;
set takes `{edits:[{layer:id,design}]}`; convert takes `{layers:[id]}`; preview takes `{design}`.

## 00: actual canvas pointer/context/preview routing

The package exports the production event entry point:

```rust
pub enum Event { Down(Point), Move(Point), Up(Point), Cancel }
pub fn pointer(
    session: &mut Session, state: &mut State, event: Event, mods: egui::Modifiers,
    selected: Option<LayerId>, enabled: bool, handle_tolerance: f64,
    snap: impl Fn(Point, Point, bool) -> Point,
) -> bool;
```

Map existing captured `canvas::ToolEvent::{Down,Move,Up}` document x/y to these events **before**
legacy `vector_ui::finish_shape` routing. The enabled flag is the active 01-registered design-shape
family (including a selected live shape's handles). Hit tolerance is `7.0 / f64::from(zoom)`.
Return early when consumed; do not execute both new and legacy shape commits. Up uses the release
position/modifiers and commits once. Call `Event::Cancel` on Escape, loss of focus, tool/persona/document
switch. `State::cancel()` also drops numeric previews. Document switches/revision changes are validated
by `Capture::check` and rejected before publication.

The stand-alone `canvas(ui,session,state,rect,View,selected,enabled,snap)` hook is the tested small-host
adapter; it is **not** an assertion that the real app is wired. Its state machine shares the same
begin/update/commit functions as the production pointer entry point.

Context bar:

```rust
drawing::controls(ui, &mut app.session, &mut app.ui.vector_drawing, &selected_layers,
    |label| crate::i18n::t(label).to_owned());
```

This supplies all numeric/boolean/corner-kind parameters and Convert to Curves. Geometry stays in px;
length controls use document design_units/resolution_dpi; rotation/start/end are radians. Dragging/typing
numeric values previews, and drag-release/Enter/focus-loss issues one command. Units: px=pt*dpi/72,
px=mm*dpi/25.4, px=in*dpi. Select tool settings come from `parameters_for`.

Overlay:
`drawing::paint(&painter, &app.ui.vector_drawing, View{origin:xf.to_screen(0.,0.),scale:f64::from(xf.zoom)}, &app.session, selected)`.
The `paint` signature accepts the existing canvas Painter. Do not substitute red path outlines for
the filled app preview acceptance.

Compositor: when `State::preview_layer` is Some, obtain `state.preview_document(&app.session)?` and
feed that detached document into the existing transient GPU/CPU preview plane. It replaces only the
target Layer in the detached clone, or inserts the new preview above its captured target. The layer's
cache is bounds-limited by `render_shape`. No document/revision/history mutation is needed, and every
preview must have its own transient cache key/invalidations. Cancel drops that plane; release renders
the authoritative committed document. Do not upload a second permanent flattened canvas or open windows.
Package 09's scaled preview integration can consume the same detached document.

Existing move/node/path replacement code must clear `layer.vector.live_shape` when it cannot update
parameters alongside the base Path. Without this hook, stale metadata is safely rejected on handle begin,
but handles will be unusable after a legacy Move. Do this in 00's shared engine edit/transform integration;
use the same edit as geometry, not a later cleanup undo step.

## 07: snap callback

Callback inputs are `(candidate, press_anchor, shift_constrained)`. Return a point on the current
Shift constraint; snapping may not break square proportions. Both press and release endpoints are
snapped. The current kittest uses an independent exact guide callback, but it does not establish
acceptance of the unmerged actual 07 provider.

## Tests and gates

Owned engine `drawing.rs` registers its own unit modules, including the strict RTX GPU family test.
The analytic fixture suite lives in `pc-vector/tests/design_shapes/geometry.rs` and is included in the
engine unit suite until/shared after geometry registration, using `super::geometry`.
UI `drawing.rs` registers its owned small-host tests. In `crates/pc-ui-egui/tests/gpu/main.rs` add:

```rust

mod live_shapes_app_gpu;
```

The exact source is `crates/pc-ui-egui/src/vector_packages/drawing/app_gpu.rs`; it intentionally requires
the real `PhotocraftApp.ui.vector_drawing` routing. It selects/asserts discrete RTX 5090 + Vulkan +
Rgba32Float, drives real pointer frames, checks filled mid-drag pixels, release journal/undo, and cancel.
It must not be counted as passed before compilation/registration and execution.

Full tests/clippy are recorded in CODEX-REPORT-vector-02-live-shapes.md. No release app performance claim.
