## Registered implementation

New internal crate `photocraft-vecfx` (`crates/pc-vecfx`) and its workspace dependency,
engine dependency, and UI `pub mod repeat` are minimally registered under the task's
REGISTRATION override. Cargo.lock adds only this local package and its engine edge;
no registry package, feature upgrade or external dependency is added. The existing
engine aggregator already calls `repeat::specs()`, so automation works on this branch.

Journaled commands:

```text
vector.repeat.create {document:u64,revision:u64,layers:[u64],spec:RepeatSpec}
vector.repeat.set    {document:u64,revision:u64,layers:[u64],spec:RepeatSpec}
vector.repeat.expand {document:u64,revision:u64,layers:[u64]}
```

`create` returns `{layer:id}` and groups consecutive sibling sources in paint order.
`set` returns `{instances:n}` and atomically edits every target repeat group.
`expand` returns `{layers:[id]}` and replaces each target's children with prepared,
ordinary editable instances, preserving the enclosing group's ID and appearance.
Every edit requires document/revision and validates the entire disjoint target set,
including inherited/descendant locks, before projection/preparation/publication.
Expand allocates fresh persistent IDs only after successful preparation. Native keeps
ordinary source children and `VectorData::live = LiveGroup::Repeat(spec)`. The native
regression found the shared tag collision described below; its exact field codec
registration is required before native acceptance passes. No new model fields/version
bump is needed. One command/Session::edit per release.

The shared serde spec uses `kind=radial/grid/mirror`. Radial `count,center,angle` means
a complete n-fold turn starting at `angle` radians. Grid `rows,cols,spacing` stores gaps
between the source's geometric bounds (pitch = width/height + gap). Mirror `origin,angle`
uses a radian axis direction. Count `1..=1000`; grid product <=1000; invalid pitch below
0.001 px is refused. Coordinates/angles are finite and bounded to 1e6. Projection is
limited to 100,000 layers, 1,000,000 generated knots and the normal group depth limit;
legacy cache preparation has a 16,000,000 pixel aggregate content/mask budget.

## Data-only renderer / file API

```rust
photocraft_vecfx::repeat::instance_count(&RepeatSpec) -> Result<u32, RepeatError>
photocraft_vecfx::repeat::transforms(&RepeatSpec, Bounds) -> Result<Vec<Affine>, RepeatError>
photocraft_vecfx::repeat::source_bounds(&[Layer]) -> Result<Bounds, RepeatError>
photocraft_vecfx::repeat::expand_layers(&[Layer]) -> Result<Expansion, RepeatError>
photocraft_vecfx::repeat::expand_scene(&vector_design::exchange::ImportedScene)
    -> Result<Expansion, RepeatError>
// Expansion { layers, transforms: BTreeMap<u64, Affine>, sources: BTreeMap<u64, LayerId> }
photocraft_engine::vector_packages::repeat::project_document(&Document)
    -> photocraft_engine::Result<Document>
photocraft_engine::vector_packages::repeat::preview(&Session, &Capture, &RepeatSpec)
    -> photocraft_engine::Result<Document>
```

Projection replaces live repeat groups with ordinary instance groups, retains all
source layer metadata and gives deterministic, unique **transient** IDs. Apply each
map affine exactly once to content, masks, clip, paint and effects; parent affines are
already composed into descendant entries. Instance wrappers are identity/pass-through
groups so source clipping stacks do not cross instance boundaries. The editable/native
source tree is never mutated. `sources` maps generated IDs to editable source IDs.
Adapters 13/14/21 depend on pc-vecfx and call `expand_scene` through the exchange DTO;
they must not depend on UI or engine or export the untransformed source tree as repeat art.
Symbol expansion and other live providers must coordinate the same composed affine
map; missing cache-only content bounds are an explicit provider error.

09 consumes this projection before scaled geometry. Cache keys include source document
Arc/revision, view key and preview generation. Source edits, undo, load and preview
release must invalidate generated instances; never persist generated display caches.
The current engine prepares ordinary shape/raster/text/smart/group content through
15's public bounds-limited renderer, with preflight before compiling/rasterizing.
Transformed non-solid paint and rotated artboard clipping are explicitly refused until
08/09's shared providers are wired. The inherited renderer also refuses corners,
appearance stacks, path text, symbols and other live kinds lacking their final provider.
The pure projection retains their complete metadata/transforms for those providers.

## Exact app hooks for 00 (shared files intentionally untouched)

### Required native compatibility registration (observed regression)

The real native writer/reader test **fails on this baseline**: internally tagged
`LiveGroup` and `RepeatSpec` both use `kind`. Writing a grid serializes the outer tag
as `grid`, and reading expects `blend/repeat/envelope`. Envelope has the same conflict.
The owned, data-only `repeat/native.rs` codec writes adjacent `kind` / `spec` fields
and reads both new records and legacy flat blend/radial/grid/mirror/warp/mesh/top_object
records, preserving their parameters. It requires no new dependency or model field.

Apply this exact shared registration in `crates/pc-doc/src/vector_design.rs`:

```diff
@@
 pub mod live;
+#[path = "../../pc-engine/src/vector_packages/repeat/native.rs"]
+pub mod live_wire;
@@
-    #[serde(default, skip_serializing_if = "Option::is_none")]
-    pub live: Option<LiveGroup>,
+    #[serde(default, skip_serializing_if = "Option::is_none", with = "live_wire")]
+    pub live: Option<LiveGroup>,
```

The path compiles the same pure data source directly in pc-doc (as in 15's existing
providers), without a doc→engine crate dependency. Other vector metadata/defaults stay
unchanged. Package 00 may relocate the file once parallel ownership resolves. Run the
existing `repeat19_engine_native_roundtrip_retains_sources_parameters_and_old_documents`
regression after registration. It remains unignored and correctly failing until the
shared hook is applied; the two codec tests are separate evidence, not a substitute for
the native gate. The standalone `LiveGroup` serde derive is not used by the native
field after this hook; automation serializes `RepeatSpec` alone and is unchanged.

The owned UI module is already compiled as `crate::repeat`. `app_hooks::Bridge` stores
transient capture, detached preview and display cache in egui memory. No persisted
UiState field is necessary. `Preferences` is serde-default compatible with `{}`; wire it

## Tests and final coordinated gates

The evaluator's nine analytic/projection/exchange tests, six engine transaction/native
tests, two native compatibility-codec tests, one independent existing-v1 reader test,
six UI kittest/cache/settings tests and two strict GPU tests are compiled.
All new names use `repeat19_`. GPU tests are ignored per the owner speed override:

- `repeat19_gpu_projection_source_edit_and_expand_parity_rtx5090` (engine): actual
  Vulkan device, real source edit, preview and premultiplied CPU/GPU parity.
- `repeat19_full_app_gpu_live_preview_cancel_release_expand_undo_source_edit_rtx5090`
  (UI): offscreen **PhotocraftApp**, clicks the production panel, actual canvas drags,
  repeated live preview/release/cancel frames, expansion/undo, source edit and raw actual
  app canvas texture parity <=1/255. Absence of the hooks above fails this gate; no
  substituted parser/widget or manually replaced app document passes it.

The app GPU module is already compiled under repeat's cfg(test), so central registration
is not required to compile it. If moving it to the single GPU binary, make its fixture
and crate imports external and replace its local lock with that binary's `gpu_lock()`.
Run the ignored gates after the hooks and final providers integrate, under the existing
GPU serialization. No desktop windows, software fallback, skipped-adapter success,
release build or performance claim was used in this job. Final integrated app/scaled/
export acceptance remains a coordinator gate, as required by the ownership contract.
