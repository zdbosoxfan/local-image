## What merged

New crate `crates/li-i18n` is the only translation engine. Both old engines are deleted:
`crates/lc-ui-egui/src/i18n.rs`, `crates/lc-ui-egui/locales/`, the `tr_format!` half of
`crates/lc-ui-egui/build.rs`, and `crates/pc-ui-egui/src/i18n/`. Every caller (lc-ui-egui,
pc-ui-egui incl. its tests/examples, apps/local-image) now calls `li_i18n` directly; no
re-exports, adapters or aliases were left behind.

| | Library engine (lc, deleted) | Editor engine (pc, deleted) | `li-i18n` |
|---|---|---|---|
| Language type | `Locale` enum (`ALL`, `code`, `name`, `script`, `parse`, `parse_tag`) | `Lang(&LangInfo)` handle (`from_code`, `from_pref`, `all`, `complete_menus`) | one `Lang` enum with all of them (`ALL`, `code`, `name`, `script`, `complete_menus`, `plural_form`, `from_code`, `from_tag`, `from_pref`); serde stores the code as before |
| Current language | its own thread-local `Cell<Locale>` | its own thread-local `Cell<Lang>` | one thread-local (`current`, `set_current`, `with_language`, `language_scope`) |
| Catalog format | JSON (`locales/xx.json`) + `xx-formats.json` | TSV (contexts, `@id`, `@plural`) | TSV only; one parser (`catalog.rs`), also used by `build.rs` |
| Catalog loading | all 12 languages parsed on the first lookup; per-thread copy of every key | lazily per language | lazily per language and catalog; no per-thread copies |
| Lookups | `tr(&str)`, `Locale::tr`, `builtin_label` | `t`, `tr`, `tr_ctx`, `tr_id`, `trn`, `fmt`, `has`, `tl!` | the editor set unchanged + `library::t`, `library::tr`, `library::builtin_label`; `tl!` exported from `li-i18n` (`#[macro_use] extern crate li_i18n` in pc-ui-egui) |
| Compile-checked formats | `tr_format!` generated by lc `build.rs` | — | `tr_format!` generated by `li-i18n/build.rs` from `catalogs/library/*-formats.tsv` |
| Plurals | — | per-language rules | per-language rules (in the registry) |
| System language | — | `system_lang()` (sys-locale), test-only override | `system_lang()` + public `with_system_tags` scoped override |
| Env override | `LIGHTCRAFT_LANGUAGE` | `PHOTOCRAFT_LOCALE` (system tags) | `LOCAL_IMAGE_LANGUAGE` (`env_language()`, no fallback to the old name) + `PHOTOCRAFT_LOCALE` unchanged |

Library helpers that wrap user/catalog data (Activity steps, source headings, date headings,
capture times) moved from the deleted `i18n.rs` to `crates/lc-ui-egui/src/library_labels.rs`
(same code, `li_i18n` lookups). `sync_context` (font reinstall on a language change) is editor
UI, so it moved to `photocraft_ui_egui::theme::sync_language` next to `install_fonts`.

### Why two catalogs per language (one engine)

Measured on the bundled catalogs: each language's editor catalog (≈3,850 entries) and Library
catalog (1,588) share **307 English keys, and 41–95 of them per language (775 in all) are
translated differently** (e.g. Japanese "Exposure": Develop 露出, Compositing 露光量; German
"Flag", "Darks"…). Folding them into one catalog would change those strings in one half, and a
string only one half translates would suddenly be translated in the other — both are translation
work the owner deferred. So the engine keeps two catalog *domains* (`Domain::Editor`,
`Domain::Library`) with identical lookup rules; merging them is a data job for the next
translation pass (the conflict list above is where it starts).

## Parity evidence (same strings, same fallbacks)

- **Editor catalogs**: the 12 TSVs moved with `git mv`; every entry line is byte-identical to
  HEAD (46,416 entry lines checked; only the header comment that pointed at the old
  `i18n/mod.rs` changed, in 10 files). Parser, lookup and plural code moved unchanged.
- **Library catalogs**: `xx.json` / `xx-formats.json` converted to `catalogs/library/xx.tsv` /
  `xx-formats.tsv` by a one-off script (escapes `\\`, tab, newline; asserted no CR, empty or
  whitespace-only keys/values). Golden test `j29_library_catalogs_match_the_json_they_replaced`
  checks count + FNV-1a of the sorted pairs of all 24 files against values computed from the JSON
  before deletion (12 × 1,588 messages, 12 × 141 format strings): **pass**.
- **Fallbacks**: `j29_each_half_keeps_its_own_catalog` — a Library lookup never borrows an
  editor-only translation (falls back to English as before) and vice versa; English returns the
  source in both; ja "Exposure" stays 露出 / 露光量.
- **Registry**: `j29_one_registry_resolves_both_engines_codes` — every code round-trips through
  `from_code`, `from_pref` and serde; lenient tags in saved settings still load.
- All engine tests of both old engines moved into `li-i18n` with their assertions unchanged
  (tags, plurals for ru/cs/fr/pt/es/ko, contexts, ids, catalog consistency, placeholders,
  `tr_format!` in every language incl. precision/sign/reordering).
- `tr_format!` arms are generated with the same literal spelling as before (only `\\`, `"`,
  control characters escaped), so every existing call site matches its arm; all 137 call sites
  compile (a placeholder mismatch in any language is still a build error).

## User-visible changes (small, all from "one registry / one language state")

1. Traditional Chinese's own name is now one string everywhere: **繁體中文** (the editor's, used
   by Preferences and the macOS menu). The Library's Edit › Language menu and Library Settings
   showed 繁體中文（台灣）.
2. Library Settings' language dropdown follows the shared order (English, 日本語, 简体中文,
   繁體中文, Español, Русский, Čeština, Français, Bahasa Indonesia, 한국어, Deutsch, Português
   (Brasil), Italiano) — the order Preferences and the macOS Language menu already use. The
   Library's Edit › Language menu keeps its own order (it is a fixed table in `menus.rs`).
3. One drawing language: the Library and the editor can no longer disagree for a frame, and a
   Preferences language preview (`with_language`) also previews Library strings drawn inside it.
4. An unknown `interface.language` code now makes the Library follow the system language like
   the editor (it fell back to English); `C`/`POSIX` and script-qualified tags (`de-Hans`) are
   accepted where the Library's lenient parser rejected them.
5. `LIGHTCRAFT_LANGUAGE` is gone; use `LOCAL_IMAGE_LANGUAGE` (owner decision, no fallback).

## Measurements (speed / memory)

Release micro-benchmark (scratch crate outside the repo; the deleted Library lookup copied
verbatim from `lc-ui-egui/src/i18n.rs` at `bbd35791` against `li_i18n::library::tr`, Japanese
catalog, 1,588 keys × 400 rounds, best of 5, two runs agree within 5 %):

| | old Library engine | `li-i18n` |
|---|---|---|
| first lookup (cold start) | 2.7 ms (parses all 12 JSON catalogs, ≈1.0 MB, even in English) | 0.4 ms (one TSV, only when a non-English language is used) |
| ja hit | 40.6 ns | 14.5 ns |
| ja miss (user text, file names) | 42.1 ns | 13.2 ns |
| English (default) | 0.8 ns | 0.3 ns |

Memory: the old Library engine kept all 12 parsed catalogs plus a per-thread copy of every key of
the active language; `li-i18n` keeps only the catalogs of languages actually used, once per
process (English sessions parse nothing). Editor lookups use the unchanged editor code path
(HashMap; plus an English early-out and `#[inline]` on the hot lookups). No new dependencies:
`sys-locale` moved from photocraft-ui-egui to li-i18n (it stays a target-specific dev-dependency
of photocraft-ui-egui for `tests/it/system_locale.rs`); Cargo.lock only gains the `li-i18n`
package.
