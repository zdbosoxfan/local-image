# Background removal tiers — implementation and validation

Continued the existing owner's specification and bake-off work in this branch. No commits, GUI windows, owner-file changes, or changes outside the assigned source areas.

## Delivered

- Fast is BRIA RMBG-1.4 at 1024². Better Quality is InSPyReNet SwinB Plus-Ultra at 1024². Both catalogue rows use the supplied immutable URLs, exact byte counts and SHA-256 digests. BRIA's non-commercial terms and the MIT/community conversion attribution are explicit. IS-Net is removed from the offered catalogue and listed as a removable legacy installation.
- `li-seg` enables tract-linalg 0.23.8's `multithread-mm`. The executor initializes once at startup and before standalone model loads, capped at eight threads and leaving at least two logical CPUs where possible. `LOCAL_IMAGE_SEG_THREADS=1` allows the same production path to be measured with a one-thread executor; values are capped at eight. No new package is added to the lockfile: its two necessary dependency edges are li-seg → tract-linalg and tract-linalg → the already-locked rayon. The latter edge is generated by the requested feature, so the task's literal “single line only” cannot describe a valid lockfile for that feature.
- Subject models ignore declared output shapes; sky retains its existing shape handling and depth retains both ignore flags. Legacy/custom subject models retain peak normalization and min–max post-processing. Both new tiers use x/255 and clamp their already-normalized outputs, with the max < 0.5 no-subject rule.
- Properties and batch call the same `background_ui::settings` widget against the same persistent `AiOptions`. Engine order is Fast, Better Quality, Qwen AI · Compact, Qwen AI · Full. Edge matting, colour decontamination, output choices and conditional hint/colour/blur controls are shared. Old `quick` settings deserialize to Fast; Qwen keys are unchanged.
- Both tools use the same profile-aware cutout, matting and document output implementation. Single-image work runs through an undoable cancellable editor job; batch uses the same implementation on imported documents. Qwen still calls its existing ComfyUI/inventory/download service. Its tooltips explicitly require a capable NVIDIA GPU and say it does not run on a Mac.
- CPU tooltips display the latest measured service time when available, with initial estimates of 3 s and 15 s and a separate refinement-time explanation. First use offers the existing verified model download with size, progress, cancellation and errors. Local AI includes management for both models.
- All Subject-group consumers were checked (`pc-engine::seg` Select Subject, Object Selection and Quick Selection prior; Library masks; single/batch cutout). The group defaults to Fast, and the shared UI restores/publishes a Better choice for that model directory. Custom Subject overrides remain supported for selection; explicit cutout tiers use their named verified models.
- Batch adds the photo list, output-folder picker, `{name}` / `{counter}` basename template with prefix/suffix and live preview, overwrite/skip/rename choices, PNG/TIFF/PSD export, progress and Cancel. It stages files beside their destination and checks cancellation before publication. It refuses to overwrite an input photo. PSD preserves mask layers; PNG/TIFF render alpha through the established exporters.

## Real editor-path CPU timings

AMD Ryzen 7 9800X3D (8 physical cores, 16 logical CPUs), the prescribed dev/test profile (workspace opt-level 1, third-party opt-level 2), CC0 portrait at 1920 × 1199. Each measurement calls the same `apply_cutout` used by Properties and batch, including profile-aware image sampling, checksum verification/model load on the first call, inference, default edge matting and mask application. Each executor setting runs in a fresh process; OS file caches were warm. These are CPU measurements, not GPU claims. Machine one-minute load was 6.93 for the one-thread run and 5.97 for the eight-thread run.

| Tier | Tract threads | First call, load included | Median of 3 calls | All calls |
|---|---:|---:|---:|---|
| fast | 1 | 3.27 s | 3.09 s | 3.27, 3.08, 3.09 s |
| better | 1 | 15.73 s | 15.73 s | 15.73, 14.29, 15.90 s |
| fast | 8 | 3.03 s | 2.87 s | 3.03, 2.74, 2.87 s |
| better | 8 | 16.01 s | 12.48 s | 16.01, 12.48, 12.40 s |

The eight-thread Better Quality first call took 16.01 s, below the 45 s requirement. Its subsequent calls took 12.48 s and 12.40 s. The full editor-path speedup is smaller than inference-only bake-off gains: Fast's median improved 3.09 → 2.87 s, Better's 15.73 → 12.48 s. Default matting and document work are included. No model-load or refinement time was excluded to make the numbers look faster.

## External service status

The real GPU is an NVIDIA GeForce RTX 5090 (driver 615.71.09). At validation start, `http://127.0.0.1:8188/queue` and `/system_stats` refused connections. The new live Qwen test requires a real CUDA/NVIDIA device and an idle queue; no mock result or software renderer is counted as GPU validation. This feature's two new tiers are intentionally CPU-only.

I subsequently started a private ComfyUI 0.38.0 at `127.0.0.1:8199`, with base/input/output/user/cache directories under this worktree, bytecode writes disabled and the installed model weights read-only. It reported CUDA on the real RTX 5090. Two sequential INT8 probes exercised the unchanged production Qwen cutout graph (25 steps, seed 1) against the CC0 portrait. The 128 × 96 probe returned alpha 0..3 and failed the client's existing usable-cutout check; the second, grid-aligned 512 × 320 probe returned alpha 0..4 and also failed that same check. The strict opt-in GPU test remains intact; this is a recorded failure, not a skipped or passing GPU result. Logs: `target/bgremove-test-qwen-gpu*.log`, `target/bgremove-comfy-isolated.log`; outputs: `target/bgremove-comfy/output/`.

The Qwen prompt/graph/sampling/post-processing behavior was explicitly required to remain as today, and those production paths were not changed. I did not stretch the failed alpha, substitute another segmentation model, or relax the assertion to hide this failure. Qwen's actual GPU matte quality on this fixture remains an existing backend/model issue for its owner to investigate. The private queue was drained and only the private service was stopped; the owner's desktop/app/service were not stopped.
