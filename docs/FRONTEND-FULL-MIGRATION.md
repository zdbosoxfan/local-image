## Current implementation

| Surface | Current owner and behavior |
| --- | --- |
| Shell, menus, tool/workspace controls, document/filmstrip/status chrome | `application.ts` mounts `FullApp.tsx`; shell components and the single keyboard controller call the same explicit commands. |
| Document metadata, navigation, mutations, save/export/close | `documentController.ts` and `documentApi.ts`; immutable accepted backend metadata, revision checks, per-document mutation queues, shared operation reservations and no automatic write retries. |
| Persistent canvas and gestures | `canvasController.ts`/`canvasMath.ts`; mounted canvas subtree, camera, mask/path buffers, selection history and pointer capture stay outside React component state. |
| Native desktop boundary | `nativeBridge.ts`; one correlated listener, capability handshake, fixed action-specific operations and owned picker cancellation. Native dialogs remain native. |
| Layers, cutout properties and editor dialogs | React shell features; explicit selected-layer operations and save/overwrite/close/credit decisions. |
| Assets | React Stock/Folders/Generated views with typed APIs, attribution, backend-owned keys, lazy thumbnails and separate collection/library-copy identities. |
| Generation/refinement | React Create/Edit/Draft/Final drafts, extracted exact size math, capabilities/reference limits, reported progress, uncertain-outcome handling, selected-result routing and named generated-background handoff. |
| Settings/setup/help and Models/LoRA | React dialogs with typed feature/native ports, actual capability/status data, preferences and live generation draft ports. |
| Batch | React prepare/review/export/cancel/resume queue with immutable reviewed choices; existing durable Python batch authority and the disclosed treatment-save scope. |
| Delivery | React mode renders `backend/frontend/react.html` plus hashed manifest assets. It executes no legacy editor/adapter scripts, loads no legacy stylesheet, and retains no hidden legacy form copies. |

`main.tsx` uses one dark FluentProvider and a nonced Griffel renderer. `generationAdapters.ts` and `featureAdapters.ts` are typed domain adapters; they do not click hidden controls or install extra native/keyboard listeners. `App.tsx`, the first-stage `editorController.ts`/`editorApi.ts`, and the six old JS bridges are disconnected from the React entry graph. They remain on disk until the acceptance/approval gate, as does the functional legacy renderer. See [ownership and retirement](FRONTEND-OWNERSHIP.md).

## Performance and remaining limitations

The [performance observation](../qa-artifacts/migration/full-performance/results.json) used a real isolated source backend, installed headless Edge, a 4096 x 2732 image and the `Cgd1OQZH` bundle. One run measured startup about 4173 ms, import-ready about 1436 ms, p95 sampled frame interval 16.8 ms, and one coarse document publication during the pan. These include automation/system load. JS heap excludes decoded images, GPU and total-process memory. No performance budget or comparable before/after speed claim is established; the older mocked fixture workload differs.

No live provider, GPU/model job or model download was run for this migration's feature acceptance. Controlled fixtures prove request/state/error routing, not image quality or model execution. Native/source export precision is not a claim that the entire AI/preview pipeline is 16-bit. Batch treatment saving still preserves the existing subject mirror contract rather than inferring arbitrary background/group relationships; its scope is disclosed before saving.

## Historical chronology and regression repairs

- The first milestone retained the canvas and most legacy presentation behind a narrow shell/Layers boundary, with visual/function approval before broad work. Its `before`, `after`, `rollback`, `real-backend` and `packaged-backend` artifacts remain historical stage evidence.
- The next feature stage mounted Settings, Models, Batch, Assets and Generation through explicit temporary ports. The `react-*` reports cover that mixed composition, including five Generation groups, five Assets groups, three Models groups and the earlier Batch runs. They are not current full-shell acceptance reports.
- Early Batch execution exposed missing modern-stack assets in detached snapshots. The scoped `batch_tools.py` compatibility fix preserves stack assets, subject treatment parameters, provenance and native pixels. [Red/green evidence](../qa-artifacts/migration/batch-stack-regression.txt) and the backend regression tests remain. It did not introduce a new project format or inferred layer grouping.
- Initial full-shell runs found an empty-state mount obscuring pixels, a test drag during layout resizing, stale same-revision stack metadata, hidden Create wheel handling and saved workspace restoration overriding an explicit result handoff. Each was corrected and exercised again. The generated-result background command now uses the existing endpoint and the named target directly, even when a generated library copy was not saved.
- Earlier project-download diagnostics failed because the harness did not own the event/action promises together and omitted Fluent shortcut text from accessible names. Those failed reports remain failures; corrected drivers use the actual accessible controls and `Promise.all` event/action ownership.
- Source-fingerprint failures caused by concurrent edits remain separate from passing frozen-source reruns. Report histories and failure screenshots are retained rather than overwritten as successes.
- Cleanup preparation preserved immutable [e42 math fixtures](../tests/fixtures/legacy-frontend-e42/README.md) with commit/path/SHA provenance. All seven meaningful old API queue/failure guarantees were ported to the current owners while keeping the original tests. Wrong-document protocol errors intentionally reject `502`; stale revisions reject `409`, with exact no-retry/no-adoption/queue-invalidation assertions.
